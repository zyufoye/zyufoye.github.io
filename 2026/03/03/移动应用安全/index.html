移动应用安全

文档记录了移动应用（App）安全的威胁形势、Android/iOS 两大主流系统的安全机制、安全防护技术方案以及金融、运营商、移动办公三大典型场景的实战案例。

移动应用面临的五大安全威胁

移动应用系统由三部分组成：App客户端 + 通信网络 + 应用服务端。这个架构的每个环节都面临安全威胁：

  1. 操作系统漏洞：无论 Android 还是 iOS，都存在大量 CVE 公开漏洞，成为攻击的突破口。
  2. 无线网络攻击：WiFi 钓鱼（伪造热点）、假冒基站、DNS 劫持等。黑客搭建恶意路由器，监听并篡改用户与服务器之间的数据。
  3. 恶意代码泛滥：流氓行为、资费消耗、隐私窃取、远程控制、诱骗欺诈等，尤以 Android 平台最为严重。
  4. 代码逆向工程：黑客对 App 的二进制文件进行反编译，获取源代码中的加密算法、密钥、业务逻辑。
  5. App 非法篡改：黑客修改 App（如去广告、破解 VIP），甚至植入木马后重新打包发布（APK 二次打包）。

Android 系统的四层安全防护机制（重点）

Android 是一个开源的移动终端操作系统，系统结构分为：Linux内核层、系统运行库层、应用程序框架层和应用程序层。每层都面临着不同程度的安全威胁，基础层威胁来自Linux内核攻击。

Android 是开源系统，安全威胁尤为突出（APK 重打包、提权攻击、远程控制、恶意付费等）。针对性地，Android 在每一层都部署了防护措施，Android 系统安全机制如下：

1. 应用程序层：权限声明机制

  • 把权限和对象绑定，才有权操作对象；
  • 将权限分为四级：normal（无害）、dangerous（潜在威胁，如读取位置）、signature（同签名应用才能访问）、signatureOrSystem（设备厂商专用）。

2. 应用框架层：应用签名机制

  • 所有 APK 必须进行数字签名，标识开发者身份及应用之间的信任关系。

3. 系统运行层：沙箱隔离 + SSL/TLS

  • 每个 App 运行在独立的 Dalvik 虚拟机和 Linux 进程空间中，彼此完全隔离。
  • 支持 SSL/TLS 对通信加密。

4. 内核层：文件系统权限 + ASLR + SELinux

  • 采用 Linux ACL 权限控制：每个 App 拥有独立的用户 ID 和私有文件目录，互相不可访问。
  • 系统分区只读（system.img），用户数据分区可读写（data.img）。
  • Android 2.3 后引入基于硬件的NX（No Execute）支持，不允许在堆栈中执行代码。
  • Android 4.0 后引入 ASLR（地址空间布局随机化），防止内存攻击。

iOS 系统的六大核心安全机制（封闭生态）

iOS 采用封闭式生态，从硬件、固件到软件层层设防，安全性相对更高。IOS 系统架构包含4个层次：核心操作系统层、核心服务层、媒体层、可触摸层；IOS 系统安全机制如下：

1. 安全启动链（Trust Chain）

  • 开机时，只读内存（Boot ROM）验证底层引导程序（LLB）的苹果签名，确保启动链的每一步都是可信的。分叉为普通引导和DFU 固件更新模式。

2. 数据保护 API

  • 针对设备丢失风险，提供加密 API，让开发者轻松对敏感文件和 Keychain 项进行保护。

3. 强制全盘加密 + File Data Protection

  • 所有用户数据强制加密，且每个文件使用不同的密钥（Profile Key），存于元文件中。加解密由硬件 AES 引擎完成（位于 DMA 内），性能极高。

4. 地址空间布局随机化（ASLR）

  • 二进制文件、库、栈、堆的内存地址随机分布，增强抗攻击能力。

5. 代码签名（强制）

  • 所有可执行程序必须使用苹果公司颁发的证书签名，杜绝非法程序运行。

6. 沙箱机制

  • 限制进程的恶意行为，每个 App 只能访问自己的资源。

移动 App 的四大加固技术与安全检测要点

一、App 安全加固（四防）

  1. 防反编译：对 APK 文件进行加密（DEX 加密、SO 文件加密），代码混淆（名字混淆、控制流混淆）。
  2. 防调试：设置调试检测，一旦发现被调试，立即清理数据或退出。
  3. 防篡改：数字签名 + 多重校验，防止二次打包和盗版。
  4. 防窃取：加密本地数据文件和网络通信。

二、App 安全检测（11 项核心内容）

  • 身份认证、会话安全、敏感信息保护、日志策略、交易流程、鉴权机制、访问控制、防篡改、防 SQL 注入、防钓鱼、漏洞检测。

三、个人信息收集最小必要权限（依据国家规范）
文档列举了各类服务的最小权限要求（重要考点）：

  • 地图导航、网络约车：位置 + 存储（+ 拨打电话）。
  • 即时通信、博客论坛、短视频、网络支付：存储权限。
  • 新闻资讯、网购、交通票务、快递、网页浏览器、输入法：无需任何权限。
  • 安全管理类 App：需要存储、读取电话状态、短信等。

三大典型应用场景的安全方案（实战案例）

1. 金融移动安全（高危行业）

  • 威胁：木马控制、钓鱼 App、资金窃取。
  • 防护方案：
    • 安全开发：安全编程培训、代码安全审计、提供安全 SDK（安全软键盘、防界面劫持、短信保护）。
    • 通信加密：对 App 通信协议加密。
    • 加固：DEX 加密、smali 混淆、SO 加密、反调试。
    • 持续监测：钓鱼监测（下架仿冒）、漏洞监测、盗版监测、威胁态势感知。

2. 运营商移动安全

  • 威胁：账号窃取、漏洞利用、恶意刷量、计费 SDK 破解、钓鱼、社工库诈骗。
  • 防护方案：
    • 对运营商自有 App 和应用市场的第三方 App 全面加固。
    • 提供恶意代码查杀服务。
    • 对计费 SDK 进行防破解加固。
    • 通信协议和证书加密。
    • 威胁态势感知：监控异常流量、入侵攻击、风险 App。

3. 移动办公安全

  • 威胁：设备丢失、信息泄露、恶意攻击、账号共享、WiFi 监听。
  • 防护方案（以 360 天机为例）：
    • 安全管理平台 + 移动客户端架构。
    • 提供设备管控（外设管理、配置推送、远程锁定/擦除）。
    • 恶意代码防范、App 安全加固、安全接入控制。

💡 核心总结

移动安全的本质是攻防对抗的升级：Android 开源但更灵活（风险高），iOS 封闭但更安全。无论哪个平台，防护的核心都是加固 App + 加密通信 + 持续监测。对于考试，重点掌握 Android/iOS 的分层防护机制和 App 四防技术。
