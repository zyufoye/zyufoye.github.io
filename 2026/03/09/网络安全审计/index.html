网络安全审计

发表于 2026-03-09 分类于 软考 阅读次数：

一、网络安全审计概述

核心概念

网络安全审计：对网络信息系统的安全相关活动信息进行获取、记录、存储、分析和利用的工作。

核心作用

  • 建立”事后“安全保障措施
  • 保存网络安全事件及行为信息
  • 为安全事件分析提供线索及证据
  • 发现潜在威胁，支撑风险分析与管理

相关标准

标准 关键内容
TCSEC（美国，1985） 从 C2级 开始提出安全审计要求，B3级及以上不再变化
GB 17859（中国） 从第二级开始要求审计机制；第二级称为”系统审计保护级“

计算机系统安全保护能力的五个等级审计要求

级别类型 安全审计要求（核心内容）
用户自主保护级 无
系统审计保护级 ① 创建并维护受保护客体的访问审计跟踪记录，阻止非授权用户访问或破坏 ② 记录事件包括：用户身份鉴别、客体引入用户地址空间、删除客体、操作员/系统管理员操作、安全相关事件 ③ 每条记录包含：日期时间、用户、事件类型、成功与否 ④ 提供审计记录接口，可由授权主体调用
安全标记保护级 在系统审计保护级基础上，增强： ① 审计记录包含客体名及客体安全级别 ② 系统具有审计更改可读输出记号的能力
结构化保护级 在安全标记保护级基础上，增强： ① 系统能够利用隐蔽存储信道时可能被使用的事件进行审计
访问验证保护级 在结构化保护级基础上，增强： ① 对安全事件进行实时监控 ② 超过阈值时，立即向安全管理员发出报警 ③ 安全相关事件继续发生或积累时，系统以最小代价中止这些事件

📌 规律总结： 审计要求随级别提升逐步增强

  • 第1级：无要求
  • 第2级：基础审计（记录 + 跟踪）
  • 第3级：增加安全标记（客体名/级别）
  • 第4级：增加隐蔽信道审计
  • 第5级：增加实时告警与主动阻断

二、网络安全审计系统组成与类型

系统组成

审计类型（按审计对象）

操作系统 / 数据库 / 网络通信 / 应用系统 / 网络安全设备 / 工控 / 移动 / 互联网 / 代码

各系统审计内容（重点）

Windows 审计信息：

  • 注册登录事件、目录服务访问、账户管理、对象访问、策略变更、特权使用、进程跟踪、系统事件

Linux 审计信息：

  • boot.log（开机自检）、acct/pacct（用户命令）、lastlog（最近登录）、sulog（su命令）、utmp（当前用户）、wtmp（登录退出）、maillog（邮件）、messages（系统消息）

网络通信审计常见内容：

IP源地址、IP目的地址、源端口号、目的端口号、协议类型、传输内容

三、网络安全审计机制与实现技术

1. 网络流量数据获取技术

技术方法 说明
共享网络监听 利用 Hub 集线器构建共享式网络，采集设备接入Hub
交换机端口镜像（Port Mirroring） 将交换机流量复制到审计端口
网络分流器（Network TAP） 用于不支持端口镜像的交换机

2. 常见网络数据采集软件

工具 说明
Libpcap 开源网络数据采集库，Linux平台
Winpcap Windows平台网络数据捕获
Windump 基于Winpcap的协议分析工具
Tcpdump 基于Libpcap，Linux常用
Wireshark 图形化采集与分析工具

Libpcap 工作流程：
① 设置嗅探网络接口（Linux默认eth0）→ ② 初始化并设定过滤规则 → ③ 循环接收符合规则的数据包

3. 审计数据安全分析技术

技术 说明
字符串匹配 使用 grep 工具，基于正则表达式模式匹配
全文搜索 利用搜索引擎技术分析审计数据
数据关联 综合多源数据（日志、流量、安全设备）发现异常，识别未知攻击
统计报表 对事件、阈值、安全基线统计，生成日/周/月报及告警
可视化分析 饼图、柱状图、折线图、地图、仪表盘；关键KPI高亮显示

4. 审计数据保护技术

措施 说明
系统用户分权管理 操作员（操作维护）、安全员（安全策略）、审计员（审计查看），三权分立，互相制约
强制访问控制 设置安全标记，防止非授权查询/修改
审计数据加密 加密敏感审计数据，防泄露
隐私保护 防止审计数据泄露隐私信息
完整性保护 使用 Hash算法和数字签名，防止非授权修改

四、网络安全审计主要产品与技术指标

各类产品对比

产品类型 基本原理 主要功能
日志安全审计 利用Syslog、NetFlow、SSH等采集异构日志 日志采集/存储/分析/查询/告警/报表
主机监控与审计 代理程序采集主机行为 用户监控、配置管理、补丁管理、U盘管理、非法外联管理
数据库审计 流量监听/自带审计/Agent 记录读写查询增删改操作，可回放
网络安全审计 网络流量采集+深度内容分析 邮件/网页/文件/FTP/Telnet/DNS审计
工控审计 流量采集+工控协议识别还原 记录工控操作信息
运维安全审计 流量采集/服务代理 字符会话/图形操作/数据库运维/文件传输/合规审计

数据库审计三种方式

方式 优点 缺点
网络监听审计 不影响数据库服务器性能 无法审计加密流量；无法审计本地操作
自带审计 能审计网络和本地操作 影响性能；日志本地存储易被删除
数据库Agent 能审计网络和本地操作 需安装在服务器，影响性能/稳定性

运维安全审计五大功能

  1. 字符会话审计：SSH、Telnet操作（时间、IP、命令等）
  2. 图形操作审计：RDP、VNC、HTTP/HTTPS图形操作
  3. 数据库运维审计：Oracle、MS SQL Server、DB2、PostgreSQL等
  4. 文件传输审计：FTP、SFTP操作（含文件名、危险等级）
  5. 合规审计：对运维操作进行合规符合性检查

五、网络安全审计应用（重点场景）

应用场景 关键说明
安全运维保障 防范运维人员绕行堡垒机等违规操作，追溯安全威胁
数据访问监测 发现绕过前台业务系统直接操作数据库的违规行为
网络入侵检测 检测黑客入侵、扫描渗透、暴力破解、蠕虫、DDoS等；通过连续认证失败告警
网络电子取证 通过日志文件确定嫌疑IP，提供犯罪证据

📌 高频考点速记

  1. TCSEC → C2级起有审计；GB 17859 → 第二级起有审计
  2. 三大流量获取技术：Hub监听、端口镜像、TAP分流器
  3. 数据采集工具：Libpcap（Linux）、Winpcap（Windows）、Wireshark（图形化）
  4. 审计数据完整性保护：Hash + 数字签名
  5. 三权分立：操作员、安全员、审计员互相制约
  6. 数据库审计三方式：网络监听、自带审计、Agent
  7. 运维审计记录：”在什么终端、什么时间、登录什么设备、做了什么操作、什么时间登出“
