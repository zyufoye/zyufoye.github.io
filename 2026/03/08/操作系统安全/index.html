操作系统安全

文档记录了操作系统安全保护，涵盖了操作系统安全的基础理论，并分别针对 Windows、UNIX/Linux 以及国产操作系统的安全架构、面临的威胁及安全加固方案进行了深入剖析。

一、 操作系统安全概述

  • 安全概念：是指满足安全策略要求，具有相应的安全机制及安全功能，符合特定的安全标准，在一定约束条件下，能够抵御常见的网络安全威胁，保障自身的安全运行及资源安全。
    • 操作系统分为五个安全等级：用户自主保护级、系统审计保护级、安全标记保护级、结构化保护级、访问验证保护级。
  • 安全可控目标：用户可以按照预期的安全要求，实现对操作系统的操作和控制。
    • 技术层面：给定一个操作系统，用户能够实现对操作系统的可理解、可修改、可检测、可修复、可保护。
    • 商业层面：用户能主导产品化，不能被利用危及国家安全。
  • 核心安全机制：
    • 硬件安全、标识与鉴别（防止伪造验证身份）、访问控制、最小特权管理、可信路径（防木马窃听的通信路径）、安全审计、系统安全增强。

二、 Windows 操作系统安全分析与防护

  • 系统架构与安全子系统：Windows 架构是层次结构和客户机/服务器结构的混合体（分硬件抽象层、内核层、基本系统服务模块）。安全子系统主要由 LSA（本地安全授权）、SAM（安全账户管理） 和 SRM（安全参考监视器）组成。
    • SAM 提供用户登录认证，并为用户赋予安全标识符 (SID)。
    • SRM 负责访问控制和审查策略，通过 ACL（访问控制列表） 描述客体权限。
  • 安全机制：
    • 认证机制分为本地认证和网络认证（集成 Kerberos V5、公钥证书和 NTLM）。
    • 访问控制达到了C2级，实现用户级自主访问控制（基于安全性描述符）。
    • 日志分为：系统日志、应用程序日志和安全日志。分别对应SysEvent.evt / AppEvent.evt / SecEvent.evt；
  • 抗攻击机制（Win7/Win10新增）：
    • 增加抗攻击安全机制，集成了内存保护机制（SafeSEH、DEP、ASLR 等）。
    • Win10 提供减少攻击面规则配置（如：阻止所有 Office 应用程序创建子进程、阻止 JavaScript/VBScript 启动下载、防御勒索软件等）。
  • 安全加固最佳实践：
    • 确认系统安全增强的安全目标和系统的业务用途。
    • 安装最小化的操作系统（减少安全隐患数目，难以顾及）。
    • 配置安装的系统服务（不要安装与系统业务运行无关的网络/系统服务和应用程序）。
    • 配置安全策略、禁用 NetBIOS（封堵 135-139, 445端口）、账户/文件系统安全配置（删除不必要的帮助文件/应用程序，启用加密文件系统）。
    • 配置 TCP/IP 筛选、禁用光盘或软盘启动、使用屏幕保护口令。

三、 UNIX/Linux 操作系统安全分析与防护

  • 系统架构与核心理念：分硬件层、系统内核、应用层。作为多用户、多任务系统，核心需求是不同用户之间避免相互干扰，禁止非授权访问系统资源。
  • 安全机制：
    • 认证：基于口令、终端认证、主机信任机制、第三方认证（S/Key、Kerberos、PAM）。
    • 访问控制：通过文件 ACL 实现，即常说的通过“9 bit”位来实现（属主、同组、其他用户的 r/w/x 权限）。
  • 安全威胁来源：
    • 口令信息保存在 passwd 和 shadow 文件中；可信主机文件（.rhost / hosts.equiv）；SUID 文件（带有文件拥有者身份和权限执行）。
  • 安全加固最佳实践：
    • 给安全漏洞打补丁（用 MD5Sum 验证完整性）。
    • 最小化系统网络服务：尽量关闭不需要的服务和网络端口（将 inetd.conf 权限设为 600，属主为 root）。servlces文件权限设置为644，文件属主为root。
    • 设置系统开机保护口令（防止通过特殊的组合键而无须提供用户名和口令进入系统）。
    • 限制远程访问：通过 /etc/hosts.allow 和 /etc/hosts.deny 控制。
    • 弱口令检查，默认账户禁用，tcp_wrapper增强访问控制，使用Tripwire和MD5Sum等完整性检查工具，检测LKM后门（Kstat、Chkrootkit、Rootkit Hunter）
    • 用户超时注销：在 /etc/profile 设置 TMOUT=600。
    • 注销时删除命令记录：在 .bash_logout 中增加 rm -f $HOME/.bash_history。
  • 高级安全模块框架 (LSM)：
    • Linux 安全模块 (LSM)：在内核源代码中放置钩子的方法。首先查找索引节点，进行错误检查和自主访问控制 (DAC)。
    • 代表实现：PAM（以“插件”增加新的身份验证服务）和 SELinux（基于策略和实施，包含类型实施、基于角色的访问控制和可选的多级别安全性）。

四、 国产操作系统安全分析与防护

  • 概况与威胁：由国家自主研发力量研制，具有较强可控性。多基于开源 Linux 定制，面临 Linux 内核的安全风险、自主研发系统组件的安全、依赖第三方系统组件的安全、系统安全配置的安全以及硬件的安全。
  • 安全增强核心特性：
    • 在自主可控、安全可信方面提供全方位保护，核心机制包括管理员分权、最小特权、结合角色的基于类型的访问控制、细粒度的自主访问控制、多级安全（即禁止上读下写）。
  • 典型产品实例：
    • 方舟安全操作系统：基于三权分立的管理机制（系统、安全、审计管理员相互制约）；强化的身份标识与认证机制（唯一标识，生命周期管理）；综合应用多种安全策略；基于内核层的安全审计（必须通过操作系统内核才能作用，不可绕过）。
    • 中标麒麟安全/可信操作系统：基于 LSM 机制的 SELinux 安全子系统框架，提供三权分立机制权限集管理功能和统一的安全管理中心 SMC。
    • 结合可信计算，通过信任链的建立及传递实现度量。支持国内可信计算规范 (TCM/TPCM、TPM2.0) 及国家密码管理部门发布的 SM2、SM3、SM4 等国密算法，提供可持续性的安全保障。
