认证技术原理与应用

发表于 2026-03-01 更新于 2026-03-08 分类于 软考 阅读次数：

认证概念

一、 认证的基本概念与角色

  • 概念： 一个实体向另一个实体证明其所声称身份的过程。
  • 核心角色：
    • 声称者： 需要被证实身份的实体。
    • 验证者： 负责检查确认声称者身份的实体。

二、 认证的组成

认证一般由两部分组成：

  1. 标识（Identification）： 用来代表实体身份的标志（如名称、标识符ID），确保实体的唯一性和可辨识性。
  2. 鉴别（Authentication）： 利用凭证（如口令、电子签名、数字证书、令牌、生物特征等）对实体所声称的属性进行识别和验证的过程。

三、 认证依据（四大类）

认证依据（即鉴别信息）是用于确认实体身份真实性的凭证。目前主要分为四类：

  1. 所知道的秘密信息 （如：密码、PIN码）
  2. 所拥有的实物/数字凭证 （如：数字证书、令牌、门禁卡）
  3. 所具有的生物特征 （如：指纹、人脸、虹膜）
  4. 所表现的行为特征 （如：签名习惯、步态）

四、 认证的机制原理

认证机制由三个核心要素构成：

  • 验证对象： 需要鉴别的实体（声称者）。
  • 鉴别实体： 给出真实性判断的实体（验证者）。
  • 认证协议： 双方进行认证信息交换所遵从的规则。

五、 认证的分类

  • 按凭据的类型数量分：
    • 单因素认证
    • 双因素认证
    • 多因素认证
  • 按利用的时间长度分：
    • 一次性口令（OTP）： 用于防止口令重用攻击（如短信验证码）。
    • 持续认证： （见下方详述）

六、 重点概念：持续认证

  • 定义： 对用户整个会话过程中的特征行为进行连续检测，不间断地验证用户特性。
  • 核心思想： 将对事件的身份验证转变为对过程的身份验证。
  • 三大鉴定因素：
    1. 认知因素： 眼手协调、应用行为模式、使用偏好、设备交互模式等。
    2. 物理因素： 左/右手习惯、按压大小、手震、手臂大小、肌肉使用等。
    3. 上下文因素： 事务模式、导航模式、设备和网络模式。

根据认证主体双方的交互关系，认证主要分为三种类型：单向认证、双向认证和第三方认证。

单向认证

1. 概念：
验证者对声称者进行单方面的鉴别，声称者不需要识别验证者的身份。声称者发送凭据，验证者检查确认即可。

2. 实现技术（两种）：

  • 基于共享秘密：
    • 前提： 双方（声称者A，验证者B）共享一个秘密密钥 。
    • 过程： A 将包含自身标识（IDA）和共享秘密（）的消息发给 B；B 检查无误后即可确认 A 的身份，并回复结果。
  • 基于挑战响应：
    • 过程：
      1. 验证者 B 生成一个随机数 RB（挑战），连同自己的标识 IDB 发给 A。
      2. A 收到后，生成包含 RB 的秘密 （响应），连同自身标识 IDA 发给 B。
      3. B 收到后解密检查 RB 是否正确，正确则确认 A 的身份，并回复结果。

双向认证

1. 概念：
验证者对声称者进行鉴别，同时声称者也对验证者的身份进行确认。双方互为验证者。
2. 核心作用：
在网络服务中（如客户端与服务端通信），通过互相认证，可以有效解决“假冒服务器”的安全问题。

第三方认证

1. 概念：
两个实体（A 和 B）在鉴别过程中，通过一个可信的第三方（TTP，Trusted Third Party）来协助实现认证和密钥交换。A 和 B 分别与 TTP 存在共享密钥 Kpa 和 Kpb

2. 核心技术方案：基于第三方挑战响应（7步过程解析）
该过程通过 TTP 安全地为 A 和 B 分发会话密钥Kab，随后 A 和 B 利用该密钥进行挑战响应。具体过程如下：

  • 阶段一：向 TTP 申请密钥 (步骤 1-2)
    • 实体 A 向 TTP (P) 发送加密请求，包含 B 的标识和 A 的随机数 RA。
    • TTP 解密后，生成供 A 和 B 通信的共享密钥 Kab 。TTP 将带有 Kab 的消息分别用 A 和 B 的专属密钥加密，打包发给 A。
  • 阶段二：A 将票据传递给 B (步骤 3)
    • A 将 TTP 生成的、属于 B 的那部分加密消息（即票据，包含 IDA 和 Kab ）转发给实体 B。
  • 阶段三：A 与 B 利用新密钥进行挑战响应 (步骤 4-7)
    • B 解密票据获得 Kab B 生成随机数 RB，用 Kab 加密发送给 A（B 向 A 发起挑战）。
    • A 用 Kab 解密得到 RB，然后将包含 RB 的消息重新用 Kab 加密发给 B（A 响应挑战）。
    • B 检查 RB 正确无误，则 A 认证通过，B 回复最终验证结果。

常见的认证技术方法及其工作原理

一、 基础认证技术

1. 口令认证技术 (最常见)

  • 原理： 基于用户“所知道的秘密”（账号+密码）。
  • 安全要求： 密码绝不能明文传输和存储，必须经过加密/哈希变换。
  • 优缺点： 简单易实现；但极易受到窃听、重放、中间人攻击和口令猜测攻击。必须配合强口令策略和安全协议使用。

2. 智能卡技术

  • 原理： 利用带有集成电路、具备安全存储和一定计算能力的卡片。
  • 认证方式：基于“挑战/应答”。目标系统发送一个随机数（挑战），用户在智能卡输入，智能卡通过内置算法计算出一个结果（应答）返回给系统验证。

二、 生物与行为特征认证

1. 生物特征认证

  • 原理： 利用人类与生俱来、独特且稳定的生物特征进行验证。
  • 常见类型：
    • 指纹识别： 包括采集、处理、登记、比对等模块。
    • 人脸识别： 一般由客户端、服务器端、安全传输通道组成。
    • 视网膜/虹膜识别： 根据眼底血管分布或虹膜纹理鉴别。核心功能分为“登记”和“识别”两部分。

2. 基于行为的身份鉴别

  • 根据用户操作行为习惯和风险大小进行的动态鉴别。

三、 经典网络认证协议与基础设施

1. Kerberos 认证协议 (强身份认证)

  • 原理： 基于对称密码体系和可信第三方，为客户端和应用服务器建立安全信道。
  • 核心实体 (KDC = AS + TGS)：Key Distribution Center
    • 客户端 (Client)： 访问服务的用户。
    • AS (认证服务器)： 验证用户身份，发放 TGS 会话密钥（发放 TGT 票据）。
    • TGS (票据发放服务器)： 为用户授予访问特定应用服务器的最终票据。
    • 应用服务器 (App Server)： 提供实际服务的设备。
    • 票据Ticket是用于安全传递用户信息的集合。
  • 优点： 减少了用户密钥密文的暴露次数；实现了单点登录 (SSO)，只要用户拿到了TGT并且该TGT没有过期，用户就可以使用TGT通过TGS完成到任一服务器的认证而不必重新输入密码。
  • 致命缺点： 极度依赖时间同步（防重放）；存在单点故障风险，抗拒绝服务(DoS)攻击能力弱。

票据（Ticket） 主要包含以下 6 项核心内容：

  1. 客户方 Principal（客户端的身份标识）
  2. 目的服务方 Principal（目标服务器的身份标识）
  3. 客户方 IP 地址
  4. 时间戳（分发该 Ticket 的具体时间，主要用于防重放攻击）
  5. Ticket 的生存期（票据的有效时间期限）
  6. 会话密钥（用于后续客户端与目标服务器之间安全通信的临时密钥）

2. PKI 公钥基础设施

  • 原理： 利用非对称加密技术，通过公钥证书（类似数字身份证）将实体与公钥绑定，解决公钥的真实性和所有权问题。PKI 涉及多个实体之间的协商和操作，主要包括以下核心实体：
  • 核心实体：
    • CA (认证机构)： 核心，负责证书的颁发、废止和更新。
    • RA (登记机构)： 辅助 CA，负责审核用户身份信息、注册和担保。
    • 目录服务器： 提供证书的管理、存储和分发服务。
    • 终端实体/客户端： 需要被认证的对象及安全服务的使用者。

四、 现代应用安全认证机制

1. 单点登录 (SSO)

  • 用户访问多个互信系统时，只需进行一次身份认证，即可访问所有授权资源，极大简化了口令管理。

2. 人机识别认证 (CAPTCHA/验证码)

  • 目的： 利用计算机难以求解的难题，区分人类和机器程序，防止恶意自动化攻击（如撞库、刷单）。常见有文本、图像（如12306）、语音验证码。

3. 多因素认证 (MFA)

  • 组合使用多种鉴别信息（如：密码+短信+指纹），大幅提升安全性。

4. 快速在线认证协议 (FIDO)

  • 核心理念：保护隐私，生物特征数据绝对不出本地设备。
  • 工作原理：
    • 注册： 设备本地生成公私钥对。私钥留在本地安全芯片，公钥发给服务器绑定账号。
    • 登录： 服务器发送挑战 -> 用户在本地用生物特征（指纹/面容）解锁私钥 -> 设备用私钥对挑战进行签名发送给服务器 -> 服务器用公钥验证签名通过。
  • 优势： 提供了标准化的浏览器 API，兼容各种本地安全认证方式，彻底告别密码泄露风险。

认证的主要产品、技术指标以及在实际场景中的应用

一、 认证主要产品分类

认证技术产品是普遍的网络安全产品，通常以物理硬件实体（集成安全软件）为主。主要分为以下五大类：

  1. 系统安全增强产品：
    • 特点： 利用多因素认证（MFA）技术增强系统、数据库或网站的登录安全。
    • 常见组合： U盘+口令、智能卡+口令、生物信息+口令。
    • 应用： 网银U盾、指纹登录系统等。
  2. 生物认证产品：
    • 特点： 利用指纹、人脸、语音等生物特征进行身份鉴别。
    • 产品： 人脸识别门禁、指纹采集仪、人脸自动识别平台等。
  3. 电子认证服务产品：
    • 特点： 基于 PKI 技术和密码算法，提供数字证书的全生命周期管理（申请、颁发、废止等），提供可信身份、可信时间等服务。
    • 产品： CA数字证书认证系统、SSL证书、时间戳服务平台等。
  4. 网络准入控制产品：
    • 特点： 基于 802.1X、Radius、VPN 等协议，与网络设备（交换机、路由器）联动。
    • 作用： 在设备（主机、手机等）接入内部网络前，进行身份和安全合规性验证，防范非法设备接入。
  5. 身份认证网关：
    • 特点： 提供集中、统一的认证服务（形成认证中心）。
    • 功能： 支持单点登录（SSO）、安全审计等。

二、 认证技术产品的核心评价指标

评价一个认证产品的好坏，主要从安全功能、性能和安全保障三个维度，具体看以下四个指标：

  1. 密码算法支持： 是否支持主流算法，如对称（DES/AES/SM4）、非对称（RSA/SM2）、哈希（SHA-1/SM3）。
  2. 认证准确性（极重要）： 考量生物识别等技术的 认假率 (FAR，把坏人认成好人) 和 拒真率 (FRR，把好人认成坏人)。
  3. 用户支持数量： 系统的最大并发/承载用户量（性能指标）。
  4. 安全保障级别： 系统的抗攻击能力和可靠程度。

三、 认证技术的典型应用场景

认证技术是网络安全的基础，主要用于：用户身份验证、信息来源证实（防假冒）、信息安全保护（防篡改/重放）。具体典型应用如下：

  1. 校园信任体系建设 (PKI应用)：
    • 在校园内建立统一的数字证书发放体系，实现“物理身份”与“数字身份”的一一对应。从而实现统一认证、基于角色的授权管理和责任认定。
  2. 网络路由认证：
    • 目的： 保证路由器设备访问安全和路由信息交换的安全，防止恶意路由更新。
    • 对象： 用户访问认证、路由器邻居认证（如 OSPF、RIP、EIGRP 协议的认证）。
    • 注意： 明文认证极不安全，推荐使用信息摘要认证（哈希加密）。
  3. 基于人脸识别的机房门禁：
    • 彻底杜绝伪造证件、冒名顶替进入核心区域，并实时上传记录便于管理。
  4. eID (网络电子身份标识) 验证：
    • 特点： 由国家主管部门颁发，与公民真实身份一一对应的网络数字身份（基于非对称密码和数字证书）。
    • 验证流程（挑战/响应模式）： 服务商请求 -> eID平台发随机数(挑战) -> 服务商用eID运算 -> 平台验证结果并返回。
  5. HTTP 认证应用 (Web服务)：
    • 支持基本访问认证 (BAA)、数字摘要认证、NTLM 等。
    • 标准交互流程：
      1. 客户端请求资源。
      2. 服务器返回 401 Unauthorized 拒绝访问，并要求认证。
      3. 客户端获取用户凭证并处理。
      4. 客户端再次请求，并在报文中携带凭证（Authorization 头部）。
      5. 服务器验证凭证，成功则返回 200 OK 及资源，失败或无权限则返回 403 Forbidden。
