网络安全体系相关安全模型

发表于 2026-02-02 分类于 软考 阅读次数：

网络安全体系特征：整体、协同、过程、全面、适应性；

网络安全体系相关安全模型包含了BLP机密性模型、Biba完整性模型、信息流模型等。

BLP完整性模型在文章中 BLP机密性模型 ，BLP 关注“保密”（不让人看），而 Biba 关注“完整”（不让人改）。

一、 Biba 完整性模型 (Biba Integrity Model)

如果说 BLP 模型是为了防止“泄密”，那么 Biba 模型就是为了防止“篡改”。它的核心目的是保护系统信息的完整性。

核心逻辑：你可以把“完整性级别”想象成“纯净度”或“可信度”。

  • 级别高 = 非常纯净、可信（如：操作系统核心文件）。
  • 级别低 = 脏、不可信（如：从互联网下载的未知文件）。

三个安全特性解读：

  1. 简单安全特性 (Simple Integrity Axiom) —— 核心是“防污染”

    • 规则：主体（用户）的完整性级别必须 ≤ 客体（数据）的完整性级别，才能读取。
    • 口诀：“不可向下读” (No Read Down)
    • 通俗解释：一个“干净”的高级别用户，不应该去读取“脏”的低级别数据。因为一旦读了不可信的数据，用户自己也被污染了，完整性就降低了。
    • (注：图片中第一点文字描述稍显混乱，提到“修改”却结论为“不可向下读”。但在标准 Biba 理论中，简单安全性主要约束“读取”行为，防止主体被低级信息污染)。

  2. 特性 (\-Property) —— 核心是“防破坏”

    • 规则：主体（用户）的完整性级别必须 ≥ 客体（数据）的完整性级别，才能修改（写入）。
    • 口诀：“不可向上写” (No Write Up)
    • 通俗解释：一个“不可信”的低级别用户，不能去修改“可信”的高级别文件。比如，普通用户不能修改系统内核文件，否则会破坏系统的完整性。

  3. 调用特性 (Invocation Property)

    • 规则：完整性级别低的主体，不能调用（激活）完整性级别高的主体。
    • 解释：这是为了防止低权限的恶意程序去操控高权限的程序来执行破坏操作。

⚡️ Biba 与 BLP 的对比记忆（考试常考点）：

  • BLP (保密)：不可向上读，不可向下写。（目的是把秘密锁在上面）
  • Biba (完整)：不可向下读，不可向上写。（目的是防止下面的脏数据污染上面）
  • 两者方向完全相反。

二、 信息流模型 (Information Flow Model / FM)

这是一个更抽象的模型，它不仅仅关注“谁访问了谁”，而是关注数据流动的方向。

  1. 核心概念：

    • 它不仅检查简单的读写权限，而是检查信息是否通过各种操作从一个客体流向了另一个客体。
    • 基本原则：基于安全属性（安全级），控制信息从客体 A 到客体 B 的传输。如果这种流动违反了安全策略（例如秘密信息流向了公开区域），就被禁止。

  2. 数学表示（图中公式部分）：

    • 模型通过集合论来描述：包括客体集、进程集、安全类型集以及流关系（Flow Relation）。
    • 一个安全的系统，要求所有的操作序列执行后，都不会产生与规定的“流关系”相冲突的结果。

  3. 关键应用：隐蔽通道 (Covert Channels) 分析

    • 这是信息流模型最著名的应用场景。
    • 什么是隐蔽通道？
      图片中解释得很清楚：“低安全等级主体对高安全等级主体所产生信息的间接读取”。
    • 通俗例子：
      假设 BLP 模型禁止 User A（低级）读取 File B（高级）。
      但如果 File B 的持有者通过“占用 CPU 100%”表示“1”，“占用 CPU 0%”表示“0”来发送摩斯密码，User A 虽然读不到文件，但可以通过观察 CPU 占用率来推测出信息。
      这就是隐蔽通道。信息流模型就是用来分析和阻断这种非正常的泄密路径的。

总结

  • Biba 模型：保护数据不被篡改（不可向下读，不可向上写）。
  • 信息流模型：关注数据的整体流动方向，专门用于发现那些绕过常规访问控制的“隐蔽通道”。
