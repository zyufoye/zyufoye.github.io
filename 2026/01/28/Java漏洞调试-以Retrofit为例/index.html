Java漏洞调试-以Retrofit为例

发表于 2026-01-28 分类于 Java Security 阅读次数：

Java漏洞分析时，如果能够对程序进行动态调试，那就可以完整的追踪数据流的控制流，这样就可以知道漏洞的触发过程，对于漏洞原理的理解也会更加清晰。

以 Retrofit 项目为例，简单记录一下漏洞的调试过程。

打断点

一般在程序的三个位置打断点：入口点、核心漏洞点、编码决策点，在该项目中：

入口点 PathTraversalTest.java:23

测试用例发起的请求，这里是数据流的起点，参数 ../attacker 传入系统。

核心漏洞点 RequestBuilder.java:94

观察 relativeUrl 在替换前后的变化。这里会调用 canonicalizeForPath ，可以单步跟进这个函数，查看为什么 encoded=true 时 ../ 没有被编码。

编码决策逻辑 RequestBuilder.java:103

这是判断是否需要编码的核心逻辑。如果 alreadyEncoded 为 true （来自 @Path(encoded=true) ），这里的判断会直接跳过 / 的编码，导致路径遍历字符被保留。

等待终端显示 Listening for transport dt_socket at address: 5005

在 IDE 中使用 Attach to Remote JVM (端口 5005) 连接调试器，一般位置都在IDE的右上角，选择调试那个虫子按钮
