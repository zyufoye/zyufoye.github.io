Zip Slip目录遍历漏洞

发表于 2026-01-28 分类于 Java Security 阅读次数：

Zip Slip 是一个广泛存在且危害极大的目录遍历（Directory Traversal）漏洞。它主要发生在应用程序解压压缩文件（如 ZIP, TAR, JAR, WAR, APK 等）的过程中。

如果应用程序没有对压缩包内文件的名称进行严格的合法性校验，攻击者就可以通过构造恶意的压缩包，让解压程序将文件写入到意料之外的位置（例如覆盖系统关键文件或代码文件），从而导致远程代码执行（RCE）。

下面记录一下这个漏洞的原理、攻击方式、代码示例以及修复方案。

1. 核心原理：目录遍历

Zip Slip 的核心在于利用文件路径中的特殊字符 ../（点点斜杠）。

在操作系统中，../ 代表“上一级目录”。

  • 正常的文件名：photo.jpg
  • 恶意的文件名：../../../../var/www/html/evil.php

攻击流程如下：

  1. 构造恶意包：攻击者创建一个压缩包，在其中包含一个文件名被修改为包含大量 ../ 的文件（例如 ../../evil.sh）。
  2. 上传/传输：攻击者将这个压缩包上传到受害者的服务器（例如头像上传、文档导入功能）。
  3. 解压过程（漏洞触发点）：
    • 服务器接收到文件，准备解压到指定目录（例如 /app/uploads/）。
    • 程序读取压缩包内的文件名 ../../evil.sh。
    • 程序将“目标目录”与“文件名”拼接：/app/uploads/ + ../../evil.sh。
    • 结果：操作系统解析这个路径后，实际指向的是 /app/evil.sh（跳出了 uploads 目录）。
  4. 文件覆盖：如果程序没有检查路径，它就会将恶意文件写入 /app/evil.sh，可能会覆盖掉该位置原有的关键文件，或者写入一个恶意的 Web Shell。

很多开发者在使用编程语言（Java, Python, JavaScript, Go 等）的标准库进行解压操作时，往往只关注“拼接路径”和“写入文件”，而忽略了验证文件名的安全性。

3. 漏洞危害

Zip Slip 的危害取决于受害者服务器的权限和被覆盖文件的位置：

  1. 远程代码执行 (RCE)：
    • 这是最严重的后果。攻击者可以覆盖网站的可执行脚本（如 .php, .jsp, .asp），或者覆盖系统二进制文件。当服务器下次运行这些文件时，就会执行攻击者的恶意代码。
  2. 配置文件覆盖：
    • 攻击者可以覆盖数据库配置文件、系统设置文件，导致服务瘫痪或接管系统权限。
  3. 拒绝服务 (DoS)：
    • 通过覆盖关键的系统库文件导致系统崩溃或无法启动。

4. 影响范围

Zip Slip 并不是某一个特定软件的漏洞，而是一种由于编码习惯不良导致的设计模式漏洞。

它由安全公司 Snyk 在 2018 年大规模披露，当时发现影响了数千个开源项目，包括：

  • Java 生态：Spring, Hadoop, Spark, ElasticSearch 等。
  • JavaScript 生态：npm 上的多个解压库。
  • Python, .NET, Go 等语言的解压库或应用。

凡是允许用户上传压缩包并在服务端解压的应用，如果使用了未加固的解压代码，都可能受到影响。

  2. 最小权限原则：运行解压服务的用户不应拥有覆盖系统敏感文件（如 /etc/, /bin/）或 Web 根目录代码的权限。
  3. 使用安全的库：现在许多现代的解压库（如 Java 的 commons-compress 更新版）可能已经内置了防护，或者提供了更安全的 API。使用经过审计的第三方库通常比自己手写解压循环要安全。
  4. 文件类型限制：如果业务不需要，禁止用户上传压缩包文件。

简单总结

Zip Slip 就是攻击者把带有“穿越路径”文件名的文件藏在压缩包里，当你解压时，这个文件会“滑（Slip）”出你设定的文件夹，跑去覆盖系统的关键文件，从而让攻击者控制你的服务器。
