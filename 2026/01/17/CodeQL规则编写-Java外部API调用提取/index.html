发表于 2026-01-17 分类于 SAST 阅读次数：

在 IRIS 项目中，第一步就是提取全部外部 API ，CodeQL 规则编写如下，因为不太理解 CodeQL 规则如何编写，所以学习记录如下，内容由 GPT 5.2 生成。

一、先用一句话说：这条 CodeQL 规则在干什么？

👉 它在做一件事：

找出 Java 代码中所有“非测试框架”的外部方法调用，并尽可能完整地导出这些被调用方法的信息（类、包、签名、参数、返回值、是否 static、Javadoc、调用位置等）

换句话说：
📌 这是一个“API 调用收集 / API 使用分析”的规则

二、必须先看懂的 4 个 CodeQL 核心概念

在看规则之前，我们先建立脑模型。

1️⃣ CodeQL 是什么？

CodeQL = 用“数据库查询”的方式分析代码

  • 代码 → 被解析成数据库（AST + 语义信息）
  • 你写的 CodeQL → 查询这个数据库
  • select → 查出来你要的代码元素

2️⃣ Java 里最重要的几个 CodeQL 类型

CodeQL 类型 含义
Call 一次方法调用（foo.bar()）
Callable 可被调用的东西（方法 / 构造函数）
Constructor 构造函数
Type 类
Package 包
Javadoc JavaDoc

3️⃣ predicate 是什么？

👉 predicate = 布尔函数（true / false）

用来判断一个条件是否成立。

4️⃣ bindingset 是什么？

👉 这是一个和 m 绑定的函数

你可以理解为：

“给某个 Callable m，算出一个字符串结果”

三、逐段精讲这条规则

① import java

📌 告诉 CodeQL：

我要分析 Java 语言模型

没有这个，你就不能用 Call、Callable 等 Java 相关类型。

② 判断：什么是“外部调用”？

🔍 逐行翻译成人话

  • Call c：一个方法调用
  • getCallee()：被调用的方法
  • getDeclaringType()：这个方法属于哪个类
  • getPackage().getName()：类所在的包名
  • matches("org.junit%")：是否是 JUnit 包

📌 整体逻辑：

如果这个调用 不是 来自：

  • JUnit
  • Hamcrest
  • Mockito
  • junit.framework

👉 那么它就是 External Call（业务 / 第三方 API 调用）

💡 为什么要排除这些？

因为这些都是：

  • 测试框架
  • 不属于“真实业务 API”
