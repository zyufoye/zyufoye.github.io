解决HEXO无法渲染LaTeX数学公式的问题

发表于 2026-01-17 分类于 Config 阅读次数：

Hexo 默认的 Markdown 渲染引擎不支持 LaTeX 数学公式语法（即 和 $$$ … $$$），或者在渲染时将公式中的特殊字符（如 _、\）错误地转义了。

VS Code 能够正常显示是因为它内置了强大的 Markdown 预览功能（通常带有 MathJax 或 KaTeX 插件支持），但 Hexo 是一个静态生成器，需要手动配置数学公式渲染插件。

要解决这个问题，可以按照以下步骤操作：

第一步：更换更强大的渲染引擎（推荐）

Hexo 默认使用的 hexo-renderer-marked 对数学公式支持很差，经常会导致公式乱码。建议更换为 hexo-renderer-kramed（它是 marked 的改进版，专门优化了数学公式）。

为什么会显示不正常？（技术原因分析）

  1. 符号冲突：Markdown 中 _ 表示斜体，而在 LaTeX 中表示下标。Hexo 默认引擎会先处理 _，导致 LaTeX 还没来得及解析，公式就已经被破坏了。
  2. 转义问题：LaTeX 中经常使用反斜杠 \（如 \phi），默认引擎可能会把它当成 Markdown 的转义字符给删掉。
  3. 缺少前端渲染库：即便 Markdown 引擎不破坏公式，浏览器本身也看不懂 $$$ … $$$，需要像 MathJax.js 这样的 JavaScript 脚本在页面加载时把这些代码转换成美观的数学符号。

建议： 完成上述配置后，运行 hexo clean 然后 hexo g 重新生成预览。如果公式依然有部分乱码，通常是由于 _ 导致的冲突，此时使用 hexo-renderer-kramed 效果通常最好。

可能会遇到的问题

我遇到的终端输出结果会提示环境安装已经成功，但存在一些版本兼容性带来的“副作用”。

以下是详细的分析和后续操作建议：

1. 结果分析：安装成功了吗？

结论：安装已经成功，可以开始配置了。

  • 卸载成功：hexo-renderer-marked 已移除。
  • 安装成功：hexo-renderer-kramed 和 hexo-filter-mathjax 都已经正确进入了你的 node_modules 文件夹。
  • 警告（Warn）：你看到的 deprecated（弃用）警告是因为这两个插件都是社区维护的，引用的某些底层库（如 highlight.js 和 mathjax-full）版本较旧。对于 Hexo 静态博客来说，这些警告通常可以忽略，不影响使用。

2. 安全漏洞（Vulnerabilities）分析

执行 npm audit 发现了 5 个漏洞（2 个中等，3 个高危）。

  • 原因：hexo-renderer-kramed 是一个为了解决数学公式而停止在旧版本的渲染器，它依赖的一些组件（如 cross-spawn, striptags）确实存在已知的安全漏洞。
  • 风险评估：低风险。 因为 Hexo 是在本地电脑上运行生成静态 HTML 文件的工具。这些漏洞大多数是“拒绝服务攻击 (ReDoS)”，除非从网上下载来历不明的恶意 Markdown 插件并运行，否则它们不会影响生成的博客网页，也不会威胁到访问网站的读者。
  • 特别提醒：千万不要运行 npm audit fix --force。这可能会导致 npm 强制把你刚装好的 kramed 降级或替换回 marked，让你之前的操作白费。
