软考密码学考点概述

发表于 2026-01-18 分类于 密码学 阅读次数：

软考常考的密码学基础知识、攻击类型以及主要的密码体制。以下是重要知识点：

一、 密码学基础概念 (Overview)

  • 定义与目标：密码学是研究信息安全保护的科学。主要目标是实现信息的保密性、完整性、可用性及抗抵赖性。
  • 组成：包含 密码编码学（研究加密/保护）和 密码分析学（研究破译/获取明文）。
  • 相关法律：提及了《电子签名法》（2005年）、商用密码算法公布（2006年）及《密码法》草案（2019年）。
  • 核心术语：
    • 明文：未加密的消息。
    • 密文：加密后的消息。
    • 加/解密算法：进行变换的运算规则。
    • 密钥：控制算法操作的关键参数。

二、 密码分析与攻击类型 (Attack Types)

根据攻击者拥有的信息量（前提条件），攻击类型分为五种（按攻击者能力从低到高）：

  1. 唯密文攻击：最困难，攻击者只有密文。
  2. 已知明文攻击：攻击者拥有一些“明文-密文”对。（注：一个安全的密码必须能经得起这种攻击）。
  3. 选择明文攻击：攻击者能制造明文并获取对应的密文（对攻击者有利）。
  4. 密文验证攻击：攻击者能判断某个密文解密后的结果是否合法。
  5. 选择密文攻击：最容易破译，攻击者能选定密文并获取对应明文（常见于攻击公钥体制和数字签名）。

三、 密码体制分类 (Cryptosystems)

1. 私钥密码体制 (Symmetric Key / 对称加密)

  • 特点：加密和解密使用相同的密钥。
  • 流程：双方必须事先通过安全渠道交换密钥。
  • 优缺点：
    • 优点：速度快
    • 缺点：密钥分配困难、密钥管理量大、无法认证源（难以实现抗抵赖）。
  • 常见算法：
    • DES：替换+移位、56位密钥、64位数据块、速度快、但56位密钥易被破解
    • 3DES：三重DES，两个56位密钥，K1和K2，较DES更安全
    • AES：美国标准，替代DES，安全性高
    • IDEA：128位密钥、64位数据块、较DES加密性更好
    • RC-5：RSA 数据公司很多产品使用RC5

2. 公钥密码体制 (Asymmetric Key / 非对称加密)

  • 特点：加密和解密使用不同的密钥（公钥和私钥）。
  • 原理：
    • 公钥：公开，用于加密。
    • 私钥：保密，用于解密。
    • 例子：甲给乙发消息，用乙的公钥加密，只有乙的私钥能解密。
  • 优缺点：
    • 优点：密钥分发方便、管理量少、支持数字签名。在公钥密码体制中，仅根据密码算法和加密密钥来确定解密密钥在计算上是不可行的。
    • 缺点：速度慢，计算量大，不适合加密大数据。
  • 常见算法：
    • RSA：基于大数分解，应用最广。公钥 (e,n) 私钥 (d,n) 。
    • ECC（椭圆曲线）、Elgamal、D-H（Diffie-Hellman）、背包算法。

3. 混合密码体制 (Hybrid System)

  • 目的：结合对称加密的“快”和非对称加密的“密钥分发方便”。
  • 工作流程：
    1. 发送方随机生成一个对称密钥。
    2. 用对称密钥加密明文消息（数据传输快）。
    3. 用接收方的公钥加密这个对称密钥（数字信封）。
    4. 将加密后的消息和加密后的密钥一起发送。
    5. 接收方先用私钥解出对称密钥，再用对称密钥解密消息。

这张PPT主要详细介绍了四种常见的对称加密算法（DES、3DES、IDEA、AES）的具体参数和工作原理。以下是为您总结的核心知识点：

四、常见密码算法

1. DES 算法 (Data Encryption Standard)

  • 类型：分组加密算法。
  • 分组长度：支持 64比特 的明文块加密。
  • 密钥长度：56比特。
  • 特点：由于密钥较短（56位），在现代算力下安全性较低，已逐渐被淘汰。

2. 三重DES (3DES / TDEA)

  • 原理：为了提高安全性，使用DES算法对明文进行 “加密 - 解密 - 加密” 的三次操作。
  • 操作流程：
    • 加密：明文 -> (用K1加密) -> (用K2解密) -> (用K3加密) -> 密文。
    • 解密：密文 -> (用K3解密) -> (用K2加密) -> (用K1解密) -> 明文。
  • 密钥规则：通常情况下，K1 和 K3 是相同的密钥（即使用两个不同的密钥K1和K2进行三次运算）。

3. IDEA 算法 (International Data Encryption Algorithm)

  • 类型：分组加密算法。
  • 分组长度：明文和密文分组均为 64比特。
  • 密钥长度：128比特（比DES更安全）。
  • 设计思想：混合使用来自不同代数群中的运算。

4. AES 算法 (Advanced Encryption Standard)

AES是用来替代DES的新一代标准，PPT中列出了该算法必须满足的标准要求：

  • 公开性：算法无密级，描述必须完全公开披露。
  • 免费性：必须可以在世界范围内免费使用。
  • 分组长度：支持至少 128比特 的分组。
  • 密钥长度：支持 128、192 和 256比特 的密钥长度。

总结对比表：

算法 分组长度 密钥长度 关键特征
DES 64 bit 56 bit 早期标准，现已被认为不够安全。
3DES 64 bit 112 bit* (通常) “加密-解密-加密”模式，过渡方案。
IDEA 64 bit 128 bit 混合代数运算设计。
AES ≥128 bit 128/192/256 bit 现行标准，公开、免费、强度高。

(注：3DES如果K1=K3，有效密钥长度通常认为是112位)

5.国产密码算法

  • 国产密码算法：指由国家密码研究相关机构自主研发、具有相关知识产权的商用密码算法。
算法名称 算法类型 关键参数/技术细节 主要用途/备注
SM1 对称加密 分组长度：128比特
密钥长度：128比特		 硬件实现为主，通常作为SM4的非公开版本背景知识
SM2 非对称加密 基于椭圆曲线（ECC）
推荐使用素数域 256位 椭圆曲线		 功能全面：包括公钥加密、密钥交换协议、数字签名算法。
SM3 杂凑算法 (Hash) 杂凑值（摘要）长度：256比特 类似于国际上的SHA-256。
SM4 对称加密 分组长度：128比特
密钥长度：128比特		 无线局域网标准算法，参数与SM1一致，但已公开。
SM9 标识密码 标识密码算法 (IBC) 基于身份的密码技术（例如将邮箱或手机号直接作为公钥）。

为了方便理解和记忆，可以将国产算法与国际通用算法进行对标：

  • SM1 / SM4 (对称) AES-128 (两者都是128位分组和密钥)
  • SM2 (非对称) ECC / RSA (但在相同安全强度下，SM2比RSA密钥更短，速度更快)
  • SM3 (哈希) SHA-256 (输出长度相同)

6.习题

利用公开密钥算法进行数据加密时，采用方式是：发送方用公开密钥加密，接收方用私有密钥解密。

五、数字信封技术

核心概念：什么是“数字信封”？

在之前的混合密码体制中我们提到过：

  • 数字信封（Digital Envelope） 是一种结合了对称加密和非对称加密（公钥加密）优点的技术。
  • 工作原理：
    1. 发送方生成一个随机的对称密钥（比如DES或AES密钥），用它来加密明文数据（因为对称加密速度快）。
    2. 发送方再用接收方的公钥，对刚才那个对称密钥进行加密（这就形成了“数字信封”）。
    3. 接收方收到后，先用自己的私钥解开信封（得到对称密钥），再用对称密钥解密数据。

选项深度解析

  • A. 对发送者和接收者的身份进行认证 —— 错误

    • 原因：数字信封使用的是接收方的公钥进行加密。因为公钥是公开的，任何人都可以获取接收方的公钥并发送数字信封。因此，接收方收到信封后，无法确定是谁发的（无法认证发送者身份）。
    • 补充：要实现身份认证，通常需要使用数字签名技术（使用发送方的私钥加密）。

  • B. 保证数据在传输过程中的安全性 —— 正确

    • 原因：这里的“安全性”具体指的是机密性（Confidentiality）。
    • 数据本身被高强度的对称算法加密了，而解密数据的钥匙（对称密钥）又被非对称算法加密保护在“信封”里。只有拥有对应私钥的接收者才能解开信封拿到钥匙，进而看到数据。这就保证了数据在传输过程中即使被截获，黑客也无法看到明文。

  • C. 防止交易中的抵赖发生 —— 错误

    • 原因：“抵赖”是指发送方事后否认自己发过该消息。防止抵赖（抗抵赖性）同样需要数字签名。因为数字信封不包含发送方的特征信息（私钥签名），所以发送方完全可以不承认这东西是他发的。

  • D. 隐藏发送者的身份 —— 错误

    • 原因：虽然数字信封不验证身份，但它的设计目的并不是为了“匿名”或隐藏身份，而是为了保护内容（密钥和数据）不被泄露。

知识点总结（考试必记）

为了防止混淆，请记住这组对比：

技术名称 使用的密钥 主要功能 对应安全目标
数字信封 接收方的公钥 加密传输密钥 机密性 (Confidentiality)
数字签名 发送方的私钥 签名摘要 完整性、认证、抗抵赖

结论：
题目问的是数字信封的功能，它是用来“装秘密”的，所以选 B（保证传输安全性/机密性）。

六、数字签名技术

数字签名比作现实生活中的“手写签名+防伪印章”，相关技术和原理总结如下：

什么是数字签名？

简单来说，数字签名就是电子世界里的“亲笔签名”。

  • 定义：签名者使用自己的私钥，对数据的杂凑值（Hash值/摘要）进行加密处理，得到的这一串数据就是数字签名。
  • 核心规则：
    • 私钥签名：只有签名者自己有私钥，所以只有他能生成这个签名（代表身份真实性）。
    • 公钥验证：签名者的公钥是公开的，任何人都可以用它来解密签名，验证是不是他签的。

数字签名有什么用？（三大核心功能）

  1. 完整性 (Integrity)：证明文件在传输过程中没有被篡改。如果文件被改了一个标点符号，签名验证就会失败。
  2. 真实性/身份认证 (Authentication)：证明文件确实是发送方发的，而不是别人冒充的（因为只有发送方有私钥）。
  3. 不可抵赖性/非否认 (Non-repudiation)：发送方事后不能不承认自己发过这份文件。如果有争议，可以通过公正的仲裁者利用公钥来验证。

数字签名是怎么工作的？

“数字签名 + 信息摘要（Hash）” 联合使用的标准过程。为什么不直接对原文件签名？因为原文件可能很大，计算太慢，所以通常只对文件的“指纹”（摘要）进行签名。

发送方（签名过程）：

  1. 生成摘要：先把原文（如电子合同）通过 Hash函数（杂凑算法），生成一个短小且唯一的消息摘要（相当于文件的指纹）。
  2. 生成签名：用发送方的私钥，对这个消息摘要进行加密。生成的这段乱码就是“数字签名”。
  3. 发送：将原文和数字签名一起打包发给接收方。

接收方（验证过程）：

  1. 还原摘要：收到签名后，用发送方的公钥对签名进行解密。如果能解开，说明确实是用发送方私钥签的。解密后得到摘要A。
  2. 计算摘要：收到原文后，用同样的Hash函数对原文重新计算一遍，得到摘要B。
  3. 比对：将摘要A和摘要B进行比较。
    • 如果 A = B：说明文件没被改过，且确实是这个人发的（验证成功）。
    • 如果 A ≠ B：说明文件被篡改了，或者签名是伪造的（验证失败）。

关键辨析：签名 vs 加密

维度 加密 (Encryption) 数字签名 (Digital Signature)
使用的密钥 公钥加密，私钥解密 私钥加密（签名），公钥解密（验证）
核心目的 保证机密性（不让人看） 保证完整性、真实性、不可抵赖性（不怕人看，只怕人改）
操作对象 针对整个明文数据 通常针对数据的杂凑值（摘要）

常见算法

  • RSA
  • Rabin
  • ElGamal
  • DSS (Digital Signature Standard，数字签名标准)
  • (国产算法 SM2 也常用于数字签名)

七、数字证书

数字证书（Digital Certificate）包含定义、结构、分类以及管理体系。它是公钥密码体制（PKI）中至关重要的一环，解决了“公钥归属性”的问题，数字证书可以比作网络世界的“身份证”来进行解读。

什么是数字证书？（定义）

  • 核心概念：数字证书（也叫公钥证书）是一种数据结构。
  • 作用：它相当于网络世界的“身份证”。它的核心作用是证明某个公钥确实属于某个人、机构或设备。
  • 信任关系：这张“身份证”不是自己画的，而是由权威的证书认证机构（CA, Certificate Authority） 签发并签名的。

证书里都有什么？（基本信息域）

就像身份证上印有姓名、身份证号、有效期一样，数字证书包含以下关键信息：

  • 主体信息 (Subject)：证书持有者的身份（是谁的证书）。
  • 公开密钥 (Public Key)：这是最核心的部分。证书把这个公钥和上面的主体身份绑定在一起。
  • 颁发者 (Issuer)：是谁发的这张证书（通常是CA机构）。
  • 有效期：证书从什么时候到什么时候有效。
  • 序列号 & 版本号：证书的唯一编号和格式版本。
  • 签名算法：CA用来签署这张证书的算法。
  • 扩展项：其他补充信息。

证书怎么分类？

  • 按“谁在用”分（类别）：

    • 个人证书：发给自然人。
    • 机构证书：发给企业或组织（比如网站的SSL证书）。
    • 设备证书：发给路由器、服务器等硬件设备。

  • 按“干什么用”分（用途）：

    • 签名证书：包含签名公钥。主要用于身份认证和抗抵赖（验证签名）。
    • 加密证书：包含加密公钥。主要用于数据加密传输（发送密文）。
    • 注：在某些高安全标准（如中国SM2国密体系）中，签名和加密通常使用两对不同的密钥，所以会对应两张不同的证书（双证书机制）。

谁来管理证书？（CA与PKI）

数字证书不是凭空产生的，它依赖于PKI（公钥基础设施）技术，并由 CA（证书认证系统） 进行全生命周期管理。

  • CA的职能：贯穿证书的“一生”，包括：

    • 申请 & 审核：检查你是不是合法的申请人。
    • 签发：给你发证书。
    • 查询 & 发布：让别人能查到你的证书。
    • 吊销：如果你的私钥丢了，或者不想用了，CA会注销这张证书（相当于挂失）。

  • 系统的构成：

    • 注册服务器：负责登记信息。
    • 签发服务器：负责核心的加密签发。
    • 目录服务器：用于存储和发布证书。
    • OCSP服务器：在线证书状态协议，用于实时查询证书是不是被吊销了（查询证书是否有效）。

总结

数字证书就是权威机构（CA）用自己的私钥对你的公钥和身份信息进行打包签名后生成的一张电子凭证，用来防止有人冒充你的身份发公钥。

八、哈希函数(杂凑函数/散列函数)

定义与特性

  • 定义：一种能将任意长度的信息转换为固定长度哈希值（数字摘要/信息摘要）的函数。
  • 核心特性：
    • 唯一性对应：任意不同的消息或文件，其生成的哈希值是不一样的（抗碰撞）。
    • 输入：可以是任意长度的消息 。
    • 输出：长度是固定的。
    • 计算简便性：给定 ，计算 很容易。
    • 单向性/抗碰撞性：给定算法 ，想要找到两个不同的消息 和 使得它们哈希值相同（），在计算上是不可行的。

常见Hash算法对比

算法名称 处理分组长度 输出摘要长度 特点/备注
MD5 512比特 128比特 经典算法，但现在安全性相对较低。
SHA 512比特 160比特 比MD5具有更强的安全性。
SM3 512比特 256比特 国产密码算法 (2010年公布)。采用 Merkle-Damgard (M-D) 结构，安全性高。

九、 密钥管理体系

密码系统的安全性主要依赖于密钥管理。主要包含三个维度的内容：

1. 密钥管理 (全生命周期)

围绕密钥的整个“一生”进行管理，包括以下环节：

  • 生成 存储 分发 使用 更新 撤销 备份 恢复 销毁 审计。

2. 密钥管理政策 (法律法规)

依据《密码法》和《商用密码管理条例》，我国对密码实行分类管理：

  • 核心密码 & 普通密码：
    • 保护对象：国家秘密信息。
    • 属性：本身属于国家秘密。
    • 管理方式：由密码管理部门依法实行严格统一管理。
  • 商用密码：
    • 保护对象：不属于国家秘密的信息。
    • 适用范围：公民、法人和其他组织均可依法使用，用于保护网络与信息安全。
    • 管理内容：涉及科研生产、销售、使用、安全保密等环节。

3. 密码测评

  • 定义：对密码产品及系统进行安全性和合规性评估。
  • 机构：国家设立了商用密码检测中心来负责此项工作。

十一、 具体场景的技术实现细节

1. 路由器安全 (Router Security)

  • 口令管理：切忌明文存储。路由器使用 MD5 对管理员口令进行 Hash 计算后存储。
  • 远程管理：
    • 放弃 Telnet：因为它是明文传输，易泄露口令。
    • 使用 SSH：替代 Telnet 进行加密的远程管理。
  • 路由信息交换：
    • 防欺诈：使用 MD5-HMAC 机制。
    • 原理：发送方和接收方分别计算路由更新包的Hash值并对比。如果Hash值不同，说明数据包被篡改，直接拒绝更新。

2. Web 网站安全 (Web Security)

  • 核心威胁：信息泄露、非授权访问、假冒网站。
  • 核心方案：数字证书 + SSL 协议 (即 HTTPS)。
  • 作用：防止浏览器和服务器之间的通信被窃听（机密性）或篡改（完整性），并验证网站身份（真实性）。

3. 电子邮件安全 (Email Security)

  • 现状：普通 Email 是明文传递的，极不安全。
  • 解决方案：使用 PGP (Pretty Good Privacy) 软件。
  • PGP 的技术架构（考试常考点）：
    • 混合加密体系：有机集成了对称和非对称算法。
    • 密钥管理：使用 RSA 算法。
    • 数据加密：使用 IDEA 算法（对称加密，速度快）。
    • 完整性与签名：使用 MD5 + RSA + 随机数生成器。
  • 功能：实现邮件的防窃听（加密）、发信人身份确认（签名）及防篡改。
