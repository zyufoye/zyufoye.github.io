SSH安全协议

发表于 2026-01-18 分类于 Config 阅读次数：

基础理论：Diffie-Hellman (DH) 密钥交换协议

在介绍SSH之前，首先了解DH协议，因为它是SSH能够安全协商密钥的基石。

  • 核心难题：如何在不安全的网络上，让两个人协商出一个只有他们知道的“密码”（会话密钥），而不用担心被旁人窃听？
  • 数学原理：基于离散对数问题的困难性。
    • 公式：
    • 正向计算容易：已知 ，算出 很快。
    • 反向计算极难：已知 ，想要算出指数 （私钥），在 足够大时，计算量是指数级的，现代计算机无法在有效时间内破解。
  • 作用：SSH利用DH算法，在客户端和服务器之间安全地生成一个对称密钥，用于后续的数据加密传输。

核心重点：SSH协议详解 (Secure Shell)

1. 什么是SSH？

SSH（Secure Shell）即“安全外壳”。它是基于公钥密码体系的安全应用协议，专为远程登录会话和其他网络服务提供安全性。

  • 主要目的：替代Telnet、rsh等不安全的明文传输协议。
  • 核心功能：加密（防窃听）、认证（防伪装）、完整性检查（防篡改）。

2. SSH的内部架构（三大子协议）

SSH不是一个单一的协议，而是由三个分工明确的协议组成的“协议栈”：

  1. SSH传输层协议 (Transport Layer Protocol)
    • 职责：负责最底层的脏活累活。包括算法协商（商量用什么加密）、密钥交换（DH算法）、服务器认证（确认服务器是真的）。
    • 结果：建立一个加密的、压缩的、保证完整性的安全通道。
  2. SSH用户认证协议 (User Authentication Protocol)
    • 职责：运行在传输层之上，负责鉴别客户端（用户）是谁。
    • 方式：支持口令认证（输入密码）、公钥认证（免密登录）等。
  3. SSH连接协议 (Connection Protocol)
    • 职责：在加密和认证都完成后，负责把加密隧道多路复用。
    • 功能：将一个物理连接逻辑上分为多个逻辑通道（Channel），分别处理终端会话、文件传输、端口转发等。

3. SSH的工作流程（7个步骤）

  1. 获取证书：客户端获取服务器的公钥证书（或已经存有服务器公钥）。
  2. 连接请求：客户端发起TCP连接（握手）。
  3. 服务器身份通告：服务器把自己的公钥发给客户端。
  4. 验证服务器：客户端验证这个公钥是不是真的服务器（防止中间人冒充）。
  5. 建立密钥 (DH)：双方通过Diffie-Hellman算法，协商出一个会话密钥（对称密钥）。
  6. 认证用户：建立加密隧道后，服务器验证客户端的身份（如输入密码）。
  7. 会话开始：使用SSH Tunnel进行加密通信。

4. 关键环节：如何验证服务器公钥的真实性？

客户端如何确认“发给我公钥的服务器真的是由于我要连接的那台服务器？”（防止中间人攻击）。主要有三种方法：

  • 方法一：物理拷贝 (最原始)
    • 用户直接带个U盘把服务器的公钥拷到客户端电脑里。安全但麻烦，不适合大规模使用。
  • 方法二：指纹核对 (最常用)
    • 流程：
      1. 首次连接时，客户端下载服务器公钥。
      2. 屏幕显示公钥的指纹 (Hash值)。
      3. 用户通过电话或其他渠道联系管理员核对指纹。
      4. 若指纹一致，用户输入“yes”信任该主机，公钥被保存到 known_hosts 文件中。
  • 方法三：PKI 认证 (最规范)
    • 通过权威的 CA 机构（PKI体系）来验证服务器证书的合法性。

5. SSH 的实际应用与风险

  • 默认端口：Linux系统中默认是 TCP 22 端口。
  • 功能扩展：不仅是远程黑窗口（Shell），还支持 scp/sftp（文件传输）、端口转发（跳板机/代理）。
  • 安全隐患：
    • 中间人攻击 (MITM)：如果在首次连接（TOFU, Trust On First Use）时没有仔细核对指纹，攻击者可能拦截连接并伪造公钥。
    • 拒绝服务攻击 (DoS)：因为SSH握手涉及复杂的加密计算（DH交换），消耗CPU资源大，攻击者可利用这一点耗尽服务器资源。

总结

SSH 是一个分层的协议，利用 DH算法 协商密钥，通过 三种方式 验证服务器身份，最终建立加密隧道替代 Telnet，保障 22端口 的远程管理安全。
