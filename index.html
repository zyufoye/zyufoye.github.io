威胁类别 (STRIDE) 核心含义 简单举例
S - 欺骗 (Spoofing) 攻击者伪装成其他用户或系统 伪造身份验证令牌来模拟合法用户
T - 篡改 (Tampering) 对数据或代码进行未经授权的修改 修改网络传输中的API请求数据
R - 否认 (Repudiation) 用户否认执行了某操作，而系统无法证明其行为 用户否认下过订单，但审计日志并未记录该操作
I - 信息泄露 (Information Disclosure) 将敏感信息暴露给未授权的实体 API返回了比用户所需更多的数据字段
D - 拒绝服务 (Denial of Service) 耗尽系统资源，导致合法用户无法使用 用大量请求轰炸公共API，耗尽后端连接池
E - 权限提升 (Elevation of Privilege) 攻击者获得了超越其应有级别的访问权限 利用错误配置的角色分配来获取管理权限

网络安全风险评估

1. 网络安全风险评估概述

  • 核心定义：依据信息安全技术和管理标准，对网络系统的保密性、完整性、可控性和可用性进行科学评价；评估脆弱性、网络安全威胁以及脆弱性被威胁者利用后所造成的实际影响，并根据安全事件发生的可能性影响大小确认风险等级。
  • 本质：评估威胁者利用网络资产的脆弱性，造成网络资产损失的严重程度。
  • 计算模型：网络安全风险值等价为安全事件发生的概率（可能性）与安全事件的损失的乘积，即 R = f (Ep, Ev)。
  • 六大评估要素：涉及资产、威胁、脆弱性、安全措施、风险等各个要素。其中，资产因其价值受威胁，威胁者利用资产脆弱性构成威胁，安全措施修补脆弱性从而降低风险。
  • 三种评估模式：
    1. 自评估：依靠自身力量进行。
    2. 检查评估：由网络安全主管机关或业务主管机关发起。
    3. 委托评估：委托具有风险评估能力的专业评估机构实施的评估活动。

2. 网络安全风险评估核心过程

风险评估包括：准备、资产识别、威胁识别、脆弱性识别、已有的网络安全措施分析、网络安全风险分析、网络安全风险处置与管理等多个环节。

  • 准备阶段：首要工作是确定评估对象和范围（首先进行网络系统范围的界定），最终生成《网络风险评估范围界定报告》。
  • 资产识别：包括网络资产鉴定和网络资产价值估算。资产主要分为网络设备、主机、服务器、应用、数据和文档资产。价值估算是确认其重要程度，它不是资产的物理实际经济价值，而是相对价值，以保密性、完整性和可用性为基础衡量。
  • 威胁识别：分析资产有可能受到的安全危害，从威胁来源、威胁途径、威胁能力、威胁效果、威胁意图、威胁频率等方面分析。
    • 需标记出潜在的威胁源，形成威胁列表（分自然威胁和人为威胁），并根据其表现形式分类。
    • 分析威胁者为了实现其意图，会使用各种攻击方法和工具（途径）；成功后给网络系统造成的影响如非法访问、欺骗、拒绝服务（效果）；目的如挑战、情报信息获取、恐怖主义、经济利益和报复（意图）。
    • 对出现频率进行等级化处理。
  • 脆弱性识别：通过各种测试方法，获得网络资产中所存在的缺陷清单。以资产为核心，识别可能被威胁利用的弱点，并对脆弱性的严重程度进行评估。依据主要是网络安全法律法规政策、标准及行业要求。
    • 包括技术脆弱性评估（现有安全技术措施的合理性和有效性）和管理脆弱性评估（从管理上分析弱点并标识严重程度）。
  • 安全措施确认：确认已采取的各种预防性和保护性安全措施的有效性。

3. 网络安全风险分析与计算

  • 风险分析步骤：在各项评估基础上，综合利用定性和定量的分析方法，确定风险的大小与风险等级（形成风险测量列表）。步骤依次为：对资产识别、对威胁识别、对脆弱性识别 -> 判断安全事件发生的可能性 -> 计算安全事件的损失 -> 计算一旦发生对组织的影响，即网络安全风险值。
  • 风险计算方法：
    1. 定性计算：对各要素属性进行主观评估，结果分为：无关紧要、可接受、待观察、不可接受。
    2. 定量计算：将要素量化为数据，输出结果是一个风险数值。
    3. 综合计算：结合定性和定量方法进行量化赋值，输出风险数值，同时给出相应的定性结论。
    4. 具体算法包含相乘法（可能性与损失相乘）和矩阵法（构造二维矩阵）。

4. 评估技术方法与工具

  • 资产信息收集：通过调查表形式，查询资产登记数据库，掌握重要资产分布。
  • 网络拓扑发现：获取被评估网络信息系统的资产关联结构信息，进而获取资产信息（生成网络拓扑结构图，掌握关联情况）。
  • 漏洞扫描：自动搜集待评估对象的漏洞信息，以评估其脆弱性。
  • 人工检查：通过人直接操作评估对象以获取信息，需事先设计好“检查表 (CheckList)”。
  • 渗透测试：获得法律授权后，模拟黑客攻击网络系统，进行安全漏洞发现、网络攻击路径构造、安全漏洞利用验证。
  • 问卷调查：采用书面的形式获得相关信息，根据调查对象进行分别设计（分管理类和技术类）。
  • 安全访谈：通过专家与使用人员、管理人员等相关人员进行直接交谈。
  • 审计数据分析：通常用于威胁识别，作用包括侵害行为检测、异常事件监测、潜在攻击征兆发觉等（采用特征模式匹配等技术）。
  • 入侵监测：将设备接入网络，采集评估对象的威胁信息和安全状态。

5. 评估项目流程与规范

  • 五大流程：评估工程前期准备、评估方案设计与论证、评估方案实施、评估报告撰写、评估结果评审与认可。
  • 前期准备：是后续工作开展的前提，需确定对象、界定范围、粒度和时间等。开始前一定要签订合同和保密协议。需要多方面的协调，必要的、充分的准备是风险评估成功的关键。
  • 方案设计与论证：依据被评估方的安全需求来制定，需经过双方讨论并论证通过后方可进行下一步工作。涵盖评估方法、评估人员组织、评估工具选择、预期风险分析、评估实施计划等。
  • 方案实施：在论证通过后，才能组织相关人员进行实施。包含基本情况调查、安全需求挖掘以及确定具体操作步骤。
    • 红线要求：应避免改变系统的任何设置或必须备份系统原有的配置，并书面记录操作过程和相关数据；必须有工作备忘录；敏感系统测试要求至少两人，且必须领导签字批准。
  • 报告撰写：完成评估报告撰写，它是风险评估结果的记录文件，是组织实施风险管理的主要依据。内容包括评估范围、计算方法、问题归纳及描述、风险级数、安全建议等。
  • 评审与认可：最高管理层或其委托的机构应组织召开评估工作结束会议，总结评估工作，对风险评估活动进行评审。对结果的验收是本次风险评估活动结束的标志，最后将经验形成书面文字材料备案。

6. 技术应用场景与前沿

  • 四大应用场景：网络安全规划和设计；网络安全等级保护；网络安全运维与应急响应；数据安全管理与运营。
  • OWASP Web应用风险评估6步法：
    1. 确定风险类别。
    2. 评估可能性的因素（从攻击者因素、漏洞因素分析）。
    3. 评估影响的因素（包括技术影响因素、业务影响因素）。
    4. 确定风险的严重程度。
    5. 决定修复内容（规则是首先修复最严重的风险）。
    6. 定制合适的风险评级模型。
  • ICT供应链安全：面临风险目标为完整性、保密性、可用性及可控性（ICT供应链概念）。
  • 人工智能 (AI) 安全风险分析：核心是防范对人工智能系统的攻击、侵入、干扰、破坏和非法利用以及意外事故，使系统处于稳定可靠的运行状态。主要面临5大风险：
    1. 人工智能训练数据安全风险。
    2. 人工智能算法安全风险。
    3. 人工智能系统代码实现安全风险。
    4. 人工智能技术滥用风险。
    5. 高度自治智能系统导致社会安全风险。

主动防御技术

1. 入侵阻断技术与应用 (IPS/SPS)

  • 核心理念：网络安全的主动防御方法，其基本原理是对目标对象的网络攻击行为进行阻断。
  • 技术实现：
    • 入侵防御系统 (IPS)：根据网络包的特性及上下文进行攻击行为判断。为解决性能瓶颈，商用多采用硬件方式或基于旁路阻断 (SPS)。
    • 旁路阻断 (SPS)：一般对网络延迟影响不大。
  • 主要作用：过滤掉有害的网络信息流，阻断入侵者对目标的攻击行为。

2. 软件白名单技术与应用

  • 核心原理：设置可信任的软件名单列表，以阻止恶意的软件在相关的网络信息系统运行。
  • 应用机制：
    • 应用审查设立初审、复审、终审三个环节，发布过程分为公示和发布两个阶段，以构建安全、可信的移动互联网安全生态环境。
    • 恶意代码防护：相比黑名单，白名单能更好防范零日漏洞。
    • 白环境保护：核心在于“三可信”——只有可信任的设备才能接入；只有可信任的消息才能传输；只有可信任的软件才允许执行。

3. 网络流量清洗技术与应用

  • 工作原理 (三步曲)：
    1. 流量检测：基于深度包检测 (DPI) 识别异常，快速识别隐藏在背景流量中的攻击包。
    2. 流量牵引与清洗：将目标系统的流量动态转发到流量清洗中心，拒绝对指向目标系统的恶意流量进行路由转发。
    3. 流量回注：将清洗后的干净流量回送给目标系统。
  • 典型应用：畸形数据报文过滤、抗拒绝服务攻击 (DDoS)、Web应用保护、DDoS高防IP服务（采用代理转发模式，流量牵引到高防IP）。

4. 可信计算技术与应用 (核心重点)

  • 概念发展：早期集中于操作系统的安全机制和容错计算。由TCPA演进为TCG，制定了TPM（可信平台模块）和TNC（可信网络连接）标准。
  • 信任体系：TPM是信任根。包含三个根：可信度量根RTM、可信存储根RTS、可信报告根RTR。目的是从硬件、BIOS、操作系统等各个层次上增强计算系统平台的可信性。
  • 中国标准：建立起以自主密码算法 TCM为核心 的标准，由可信密码模块(TCM)和TCM服务模块(TSM)组成。
  • TNC 三层架构：完整性度量层（搜集和验证）、完整性评估层（评估状况）、网络访问层（请求处理与授权）。

5. 数字水印技术与应用

  • 核心原理：通过数字信号处理方法，在数字化的媒体文件中嵌入特定的标记。分为水印的嵌入和水印的提取。
  • 两大核心算法：
    1. 空间域方法：直接叠加到数字载体的空间域上。典型如Schyndel算法（即最低有效位算法 LSB，按像素点逐一嵌入最低位上）和Patchwork算法（改变统计特性）。
    2. 变换域方法：利用扩展频谱通信技术和离散余弦变换(DCT)，将水印叠加到DCT域中幅值最大的前L个系数上（不包括直流分量）。
  • 应用场景：版权保护、信息隐藏（提升保护程度）、信息溯源、访问控制。

6. 网络攻击陷阱技术 (蜜罐/陷阱网络)

  • 核心理念：一种主动的防御方法，帮助防守方获得信息优势。能消耗攻击者资源、加重工作量、迷惑/跟踪攻击者、制止破坏行为，形成威慑。
  • 蜜罐主机技术：
    • 空系统：标准的机器，运行着真实完整的OS及程序，包含真实系统中的漏洞。
    • 镜像系统：建立提供敌手感兴趣的服务的服务器镜像，具有较强的欺骗性。
    • 虚拟系统：在真实物理机上运行仿真软件，运行多个不同OS（虚拟机）。
  • 陷阱网络发展：
    • 第一代：多个设备共同组成，不对外限制但对内加强控制，必须获取系统活动记录（远程日志、监控软件）。
    • 第二代：实现集成系统（监控非授权、隐蔽性更强、可积极响应限制非法活动）。
    • 第三代：虚拟陷阱网络 (Virtual Honeynets)，将功能集中到一个物理设备中运行。

7. 入侵容忍及系统生存技术

  • 核心理念：安全3.0理念是容忍入侵（区别于1.0挡在门外，2.0检测隔离），目标是实现网络安全弹性，具有容侵能力、可恢复能力。
  • 生存性3R方法：将系统划分为不可攻破的安全核和可恢复部分（假定基本服务不可攻破）。包含三策略：抵抗(Resistance)、识别(Recognition)、恢复(Recovery)。
  • 关键技术与应用：
    • 分布式共识（如区块链，众多对等节点组成，去中心化，避免单一缺陷）。
    • 门限密码（如弹性CA系统，容忍一台或多台设备被入侵，将私钥分解成若干个数的和）。
    • 主动恢复（周期性转变到可信状态）与多样性设计（避免通用模式失效）。

8. 隐私保护技术与应用

  • 四类隐私：身份隐私、属性隐私、社交关系隐私、位置轨迹隐私。
  • 保护目标：通过安全修改处理，使数据可公开发布而不会遭受隐私攻击，并最大可能保留原数据使用价值。
  • 核心算法：
    • k-匿名方法：对所有元组进行泛化处理（不再一一对应），但容易遭到一致性攻击。改进方案为 l-多样性方法（每个敏感属性至少有l个不同的值）。
    • 差分隐私方法：通过添加随机噪声保护数据。
  • 操作方法：抑制（置空）、泛化（降精度）、置换（改属主）、扰动（加噪声）、裁剪（分开发布）。
  • 脱敏处理：匿名化（处理后不能被复原）与 去标识化（采用假名、加密、Hash函数等置换）。系统敏感口令也常用Hash函数处理后再保存。

9. 网络安全前沿技术动向

  • 网络威胁情报：指有关网络信息系统遭受安全威胁的信息（如漏洞、攻击来源IP、恶意邮箱/域名、攻击工具等）。
  • 同态加密：允许在密文上直接进行计算，解密后的结果与明文计算结果一致（包括加同态、乘同态和全同态）。
  • DNS域名安全：DNS是逐级授权的分布式数据查询系统（完成域名到IP的翻译），分为递归和权威（根、顶级等各级组成）。主要风险包括：域名信息篡改、解析配置错误、域名劫持、软件安全漏洞。

一、网络安全审计概述

核心概念

网络安全审计：对网络信息系统的安全相关活动信息进行获取、记录、存储、分析和利用的工作。

核心作用

  • 建立”事后“安全保障措施
  • 保存网络安全事件及行为信息
  • 为安全事件分析提供线索及证据
  • 发现潜在威胁，支撑风险分析与管理

相关标准

标准 关键内容
TCSEC（美国，1985） 从 C2级 开始提出安全审计要求，B3级及以上不再变化
GB 17859（中国） 从第二级开始要求审计机制；第二级称为”系统审计保护级“

计算机系统安全保护能力的五个等级审计要求

级别类型 安全审计要求（核心内容）
用户自主保护级 无
系统审计保护级 ① 创建并维护受保护客体的访问审计跟踪记录，阻止非授权用户访问或破坏 ② 记录事件包括：用户身份鉴别、客体引入用户地址空间、删除客体、操作员/系统管理员操作、安全相关事件 ③ 每条记录包含：日期时间、用户、事件类型、成功与否 ④ 提供审计记录接口，可由授权主体调用
安全标记保护级 在系统审计保护级基础上，增强： ① 审计记录包含客体名及客体安全级别 ② 系统具有审计更改可读输出记号的能力
结构化保护级 在安全标记保护级基础上，增强： ① 系统能够利用隐蔽存储信道时可能被使用的事件进行审计
访问验证保护级 在结构化保护级基础上，增强： ① 对安全事件进行实时监控 ② 超过阈值时，立即向安全管理员发出报警 ③ 安全相关事件继续发生或积累时，系统以最小代价中止这些事件

📌 规律总结： 审计要求随级别提升逐步增强

  • 第1级：无要求
  • 第2级：基础审计（记录 + 跟踪）
  • 第3级：增加安全标记（客体名/级别）
  • 第4级：增加隐蔽信道审计
  • 第5级：增加实时告警与主动阻断

一、网络安全漏洞概述

核心概念

网络安全漏洞（脆弱性）：致使网络信息系统安全策略相冲突的缺陷，通常称为安全隐患。

漏洞影响范围

机密性受损 / 完整性破坏 / 可用性降低 / 抗抵赖性缺失 / 可控制性下降 / 真实性不保

漏洞分类（按补丁状况）⭐

类型 说明
普通漏洞 漏洞信息已广泛公开，安全厂商已有修补方案
零日漏洞（Zero-day） 新发现、尚未提供补丁的漏洞，通常用于定向攻击

漏洞威胁类型

网络信息系统漏洞的存在是攻击成功的必要条件之一。

敏感信息泄露 / 未授权访问 / 身份假冒 / 拒绝服务

我国漏洞相关平台与标准 ⭐

  • CNNVD：国家信息安全漏洞库（中国信息安全测评中心建设）
  • CNVD：国家信息安全漏洞共享平台（国家计算机网络应急技术处理协调中心）
  • 相关标准：GB/T 33561 / GB/T 30279 / GB/T 28458 / GB/T 30276
