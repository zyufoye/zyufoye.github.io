哈希 Hash 散列函数 消息摘要

常见哈希算法有MD5、SHA、SM3（国密）；

将任意长度的一段数据经过一道计算，转换为一段定长的数据（MD5 128位，SHA 160位，SM3 256位）：

  1. 不可逆性（单向）：几乎无法通过hash结果推导出原文，无法通过x的哈希值推导出x；
  2. 无碰撞性：几乎没可能找到一个y使y的hash值等于x的hash值；
  3. 雪崩效应：输入发生轻微变化，hash输出会产生巨大变化（可用于校验完整性）；

MD5：对任意长度报文进行运算，先把报文按照512位分组，最后得到128位报文摘要；

SHA：对512位数据块进行复杂运行，最终产生160位散列值，比MD5更安全更慢；

SM3：分组512位，输出杂凑256位；

Hash三大应用：文件完整性校验、账户密码加密存储、用户身份认证。

账户密码存储方式：

  1. 明文存储，无安全防护；
  2. 哈希存储，容易受到彩虹表攻击；
  3. 哈希+盐存储，彩虹表攻击无效，盐（账户注册时间或者加上其他随机数一起生成）；

CHAP认证（PPP中的认证方式：PAP和CHAP）：首先A向PPPoE服务器发起认证，服务端检测有张三，返回随机数R，A接收到R后用密码+R生成哈希，发回HMAC，服务端完成对比验证，可以实现源认证+完整性校验，不需要在网络上传输真实的密码。

MAC或者HMAC，消息认证码，HMAC是基于hash的消息认证码，HMAC=hash（密码+R）。

数字签名

签名方用自己的私钥进行签名，对方收到后，用签名方的公钥进行验证；

签名的主要目的是为了防止事后否认，跟手写签名的核心理念是一样的。

常见的数字签名算法（公钥加密算法）：RSA（使用较多）、SM2（国密）Rabin、ELGamel签名体制和DSS标准；

数字签名用于确认发送者身份和消息完整性的一个加密消息摘要，具体特点如下：可信、不可伪造、不重新使用，签名文件不可改变，不能抵赖，能够核实发送者身份；

实现基于：公钥密码体制和单向安全哈希算法，如MD5RSA；

SM2算法基于椭圆曲线，RSA基于大整数因子分解问题，Elgamal和ECC椭圆曲线密码基于离散对数问题；

数字证书

数字证书是由一个可信的权威机构签署的信息集合。PKI中的X.509数字证书的内容包括：版本号、序列号、签名算法、颁发者、有效起始日期、有效终止日期、主体名称、用户公钥、CA数字签名信息等，不含加密算法标识。

S/MIME采用MD5生成数字指纹，利用RSA进行数字签名，并采用3DES加密数字签名。

A获取B的数字证书，利用其中的B的公钥进行加密，B收到消息后用自己的私钥进行解密。

权威机构CA用自己的私钥进行签名，大家可以用CA发布的公钥去进行验证。

CA提供数字证书的申请、审核、签发、查询、发布及证书吊销等全生命周期的管理服务。

PKI（公钥基础设施）体系结构

PKI 是一套用于管理数字证书和公钥加密的框架，主要组件及其职责如下：

组件 角色与功能
终端实体（用户/终端实体） 申请数字证书的客户，可以是个人、组织或政府机构。
注册机构（RA） 负责受理证书申请，对申请人合法性进行资格审查，决定批准或拒绝申请。RA 不签发证书，仅做身份审核；小型机构可由 CA 兼任 RA。
证书颁发机构（CA） 核心机构，负责签发、管理和撤销证书（包括颁发、续期、吊销）。
证书发布系统 负责证书的发放与分发，可通过目录服务或用户自行下载等方式。
CRL（证书吊销列表）库 存放已吊销或过期证书的列表，供验证方查询证书有效性。
CRL 发布者 负责生成并发布 CRL。
CRL 用户 需要查询 CRL 以验证证书状态的实体。

关键点：CA 负责签发证书，RA 负责资格审查，CRL 用于证书状态查询，三者协同完成证书全生命周期管理。

Kerberos 认证协议

Kerberos 是一个基于对称加密的网络认证协议，使用可信第三方（KDC）为客户端/服务器应用提供强身份认证。

1. 体系结构组件

  • KDC（密钥分发中心）：由两个逻辑服务组成：
    • AS（认证服务器）：负责初始身份认证，发放许可凭证（Ticket Granting Ticket, TGT）。
    • TGS（票据发放服务器）：负责为已认证用户发放访问特定服务的服务凭证（Service Ticket）。

2. 认证流程（简略步骤）

  1. 客户端向 AS 请求许可凭证（TGT）。
  2. AS 返回 TGT（加密的）。
  3. 客户端用 TGT 向 TGS 请求访问某服务的凭证。
  4. TGS 返回服务凭证。
  5. 客户端将服务凭证提交给目标服务器，完成认证。

3. 重要概念

  • 票据（Ticket） 主要包含：客户与目的服务方的 Principal（主体名）、客户方 IP 地址、时间戳、生存期、会话密钥等。
  • 整个协议依赖对称密钥（如 DES、AES），KDC 作为可信第三方。

4. 常见误区辨析（结合题干）

  • 错误说法：认证服务器 AS 为申请服务的用户授予票据 —— 实际上，AS 授予的是 TGT（许可凭证），而访问具体服务的票据由 TGS 授予。因此该说法是错误的。

数字证书 vs 数字签名（类比与对比）

对比维度 数字证书 数字签名
类比 身份证 手写签名 / 按手印
核心作用 验证用户/网站身份（即“你是谁”） 防止抵赖（不可否认性） + 验证身份（“你是否认过此内容”）
技术原理 证书中包含用户公钥，并由 CA 的私钥进行数字签名（即 CA 担保公钥的归属）。 发送方使用自己的私钥对消息（或摘要）加密，接收方使用发送方的公钥进行验证。
典型应用场景 验证网站真伪（HTTPS）、加密通信、代码签名等。 合同签署、电子邮件、软件发布等需要确保完整性和来源真实性的场景。

核心差异：数字证书用于绑定身份与公钥（借助 CA 的可信背书）；数字签名用于保证数据完整性和来源可信（借助私钥签名、公钥验签）。两者常结合使用（例如证书中包含公钥，该公钥可用于验证签名）。

综合归纳

  • PKI 提供了证书的颁发、管理和撤销机制，是数字证书可信的基础。
  • Kerberos 是另一种基于对称密钥、无需公钥体系的认证协议，适合内网环境，强调单点登录和时效性。
  • 数字证书与数字签名虽都依赖非对称加密，但目的不同：证书侧重“身份绑定”，签名侧重“行为确认”。

RSA基础

目前公认的比较安全的公钥密码有两类：

  1. 基于大素数因子分解困难性：RSA；
  2. 基于离散对数问题困难性：DH、Elgamal、ECC（椭圆曲线密码）

RSA算法中，公钥和私钥都可以用来加密消息，加密与解密使用不同密钥即可。

RSA提供了一种保护网络通信和数据存储的机密性、完整性、真实性和不可否认性的方法。

SSH、OpenPGP、S/MIME、SSL/TLS都依赖RSA进行加密和数字签名功能。

RSA计算

gcd表示求解最大公约数

步骤 操作 是否保密
① 随机选择两个大素数 p 和 q p 和 q 保密
② 计算 n = p * q n 公开
③ 计算 phi(n) = (p-1) * (q-1) phi(n) 保密
④ 随机选取正整数 e，满足 1 < e < phi(n) 且 e 与 phi(n) 的最大公约数为 1 e 公开
⑤ 根据 e * d = 1 (mod phi(n))，求出 d d 保密
⑥ 加密运算 C = Me mod n，解密运算 M = Cd mod n （空）

RSA 公钥（公开密钥）：Ke = < n, e >
RSA 私钥（保密密钥）：Kd = < p, q, d, phi(n) >

是否可以直接使用RSA密码进行进行数字签名？

不可以，需要首先做Hash，首先是保证签名完整性，其次是确保密文长度小于n，不然会产生回转，无法解密；

RSA签名：真实性、完整性、不可否认性；

访问控制策略

两个网络安全模型：BLP模型和Biba模型。

BLP：Bell-LaPadula BLP机密性模型，防止非授权信息访问扩展。

  • 简单安全特性：不能向上读，只能向下读；
  • *特性：只能向上写，不能向下写；

机密性模型，不能保证完整性，因为可以向上写会破坏完整性。

Biba模型：防止非授权篡改，保证信息系统完整性。

  • 简单安全特性：不能向下读；
  • *特性：不能向上写；
  • 调用特性：不能向上调；

访问控制三要素：主体、客体、（访问控制数据库、参考监视器、审计库）；

iptables四表五链

默认的 4 个规则表

  • raw 表：确定是否对该数据包进行状态跟踪
  • mangle 表：为数据包设置标记
  • nat 表：修改数据包中的源、目的 IP 地址或端口
  • filter 表：确定是否放行该数据包（过滤）

默认的 5 种规则链

  • INPUT：处理入站数据包
  • OUTPUT：处理出站数据包
  • FORWARD：处理转发的数据包
  • PREROUTING：在进行路由选择前处理数据包
  • POSTROUTING：在进行路由选择后处理数据包

规则表与规则链的对应关系

规则表 定义 包含的规则链
raw 表 确定是否对该数据包进行状态跟踪。 OUTPUT、PREROUTING
mangle 表 修改数据包内容，用来做流量整形的，给数据包设置标记。 INPUT、OUTPUT、FORWARD、PREROUTING、POSTROUTING
nat 表 负责网络地址转换，用来修改数据包中的源/目标 IP 地址或端口。 OUTPUT、PREROUTING、POSTROUTING
filter 表 负责过滤数据包，确定是否放行该数据包（包过滤防火墙）。 INPUT、FORWARD、OUTPUT

iptables 命令的语法格式

  • iptables [-t 表名] 管理选项 [链名] 条件匹配 -j 执行动作
  • 示例：
    iptables -t filter -A INPUT -s 192.168.184.20 -p tcp --dport 22 -j DROP

通用参数

参数 说明 示例
-p 协议 指定协议（如 tcp, udp, icmp） iptables -A INPUT -p tcp
-s 源地址 指定源 IP 地址 iptables -A INPUT -s 192.168.1.1
-d 目的地址 指定目的 IP 地址 iptables -A INPUT -d 192.168.12.1
--sport 源端口 指定源端口（需配合 -p） iptables -A INPUT -p tcp --sport 22
--dport 目的端口 指定目的端口（需配合 -p） iptables -A INPUT -p tcp --dport 22
-j 处理动作 指定匹配后的处理动作 见下方动作列表
-t 指定表 一般都是指定filter表 默认不写就是指定filter表
-A 添加一条规则 Append
-D 删除一条规则 Delete
-I 插入一条规则 Insert默认插入在第一行
-P 默认策略 大写P是表示默认策略

常用处理动作（-j）

动作 说明
DROP 直接丢弃数据包，不回应
REJECT 丢弃数据包，并回显 ICMP 不可达消息
LOG 将数据包信息记录到 syslog（继续执行后续规则）
ACCEPT 允许数据包通过

实现允许IP为10.0.0.2的客户端访问本机的tcp 22端口：

iptables -I INPUT -s 10.0.0.2 -p tcp —dport 22 -j ACCEPT

出口防火墙设置iptables默认不允许任何数据包进入：

iptables -t filter -P FORWARD -j DROP

iptables -t filter -P FORWARD DROP

iptables -t filter -P FORWARD -j REJECT

DMZ区的网站一般开放端口是80和443；

iptables -t filter -A FORWARD -p tcp —dport 80,443 -j ACCEPT （入站流量）

iptables -t filter -A FORWARD -p tcp —dport 80,443 -j ACCEPT（出站放行流量）

iptables -A FORWARD -p tcp -s 192.168.70.0/24 —sport 22 -d 192.168.11.2 -j ACCEPT（外转内放行）

Snort入侵检测系统

  • 在 Snort 中有五种动作：alert、log、pass、activate 和 dynamic。
  • Alert：生成一个警报，然后记录（log）这个包。
  • Log：记录这个包。
    Log 动作与 Alert 动作的不同在于：Alert 动作是发送告警然后记录包，Log 动作仅仅记录包。
  • Pass：丢弃（忽略）这个包。
  • Activate：报警并且激活另一条 dynamic 规则，比如进一步检验。
  • Dynamic：保持空闲直到被一条 activate 规则激活，被激活后就作为一条 log 规则执行。
    Dynamic 规则动作由其它用 activate 动作的规则调用，在正常情况下，他们不会被用来检测包。一个动态规则仅能被一个“activate”动作激活。

动作写在第一个空

Alert tcp any any → any any (msg:”XXX”;content:”union select“;nocase;sid:110;)

防火墙

发表于 2026-08-07 分类于 软考

概述

为了应对网络威胁，将内部信任网络与外部公共不可信任网络进行隔离（逻辑隔离）。

物理隔离设备：网闸；

网闸：物理隔离，数据摆渡。不建立两个网络的直接链接，而是像一艘“数据摆渡船”，将数据以“文件”形式从一端“搬运”到另一端。在任一时刻，内外网仅有一侧与中间的隔离交换区相连。

防火墙是由一些软、硬件组合而成的网络访问控制器，它根据一定的安全规则来控制流过防火墙的网络包，如禁止和转发，能够屏蔽被保护网络的内部信息、拓扑结构和运行情况，起到网络安全屏障的作用。

华为防火墙对流量的操作：permit、deny

Linux防火墙对流量的操作：Accept接收、Reject拒绝数据包通过（通知信息源）、Drop拒绝数据包通过（不通知信息源）

防火墙安全策略

1.白名单策略：只允许符合安全规则的包通过防火墙，其他通信包进制；

2.黑名单策略：禁止与安全规则相冲突的包通过防火墙；

iptables防火墙

Chain INPUT （policy ACCEPT）默认是policy ACCEPT接受，在里面写了规则的是不接受，所以是黑名单策略。

包过滤防火墙

包过滤：在IP层实现（网络层），根据源、目的IP，源、目的端口及协议、包传递方向等包头信息判断包是否通过。

优点：低负载、高通过、对用户透明；

缺点：不能进行应用层的用户级别过滤；

五元组：源目IP、源目端口、协议号；

包过滤规则由“规则号、匹配条件、匹配操作”三部分构成，根据源目IP、源目端口、协议类型（UDP/TCP/ICMP）、通信方向、规则运算进行匹配，匹配操作有拒绝、转发、审计三种。

华为ACL案例

rule 10 permit tcp source any destination any source-port gt 1024 destination eq 25

允许任何源IP端口大于1024对任何目的IP端口等于25进行通信。

⭐防火墙防御体系结构类型

一、密码体制分类

密码体制分为私钥和公钥密码体制两种，介于私钥和公钥之间的密码称为混合密码体制。

  • 私钥密码：又称为对称密码，加密秘钥和解密密钥一致，双方事先需要通过安全渠道交换密钥；
  • 公钥密码：有两个密码，加密和解密用的密钥是不一样的；

对称加密算法特点：

  • 优点：加密速度快、密文紧凑、使用长密钥时难破解；
  • 缺点：密钥分配、管理问题，无法进行源认证；

一般使用对称密码加密大的内容（文件、消息），使用公钥密码加密小的内容（密钥、签名、哈希）

常见的对称密钥加密算法：DES、3DES、AES、RC4/5、IDEA；

DES密钥长度56，3DES密钥长度112。

公钥密码体制称为非对称加密体制：A→B发送数据，A在进行数据加密时使用B的私钥，B收到数据后再用B的私钥解密。

  • 优点：密钥分发方便、密钥保管量少、支持数字签名；
  • 缺点：加密速度慢（计算量大，不适合加密大数据）、数据膨胀率高；

每个实体都有两个密钥：公钥公开、私钥自己保存：

  • 公钥加密，私钥解密可实现保密通信
  • 私钥加密，公钥解密可实现数字签名（私钥签名，公钥验证）

常见的非对称加密算法：RSA（密钥512、1024或2048位）、Elgamal、ECC（椭圆曲线算法）、背包算法、Rabin、DH等；

PHP伪协议详解与CTF示例

前言

在 Web 安全以及 CTF 竞赛中，文件包含漏洞（File Inclusion, LFI/RFI） 是一种极其常见的漏洞类型。而在利用文件包含漏洞时，PHP 伪协议（PHP Pseudo-protocols / Stream Wrappers） 无疑是我们手中最强大的工具之一。本文将对 PHP 伪协议的分类、原理进行系统梳理，并通过一个典型的 CTF 题目加深理解。

一、什么是 PHP 伪协议？

PHP 带有许多内置的流包装器（Stream Wrappers），即我们常说的“伪协议”。它允许开发者像访问本地文件一样去操作各种不同的数据源（例如网络请求、标准输入输出流、Base64 字符流、压缩包等）。

在代码中，像 include(), require(), file_get_contents(), file_put_contents() 等文件操作函数，如果传入的参数可控且使用了伪协议，就会触发不一样的逻辑。

1.1 关键配置项 (php.ini)

伪协议能否生效，很大程度上取决于 PHP 的配置文件 php.ini 中的两个核心参数：

  • allow_url_fopen：是否允许将 URL 当作文件打开（默认开启 On）。
  • allow_url_include：是否允许将 URL 作为 include/require 的参数包含（非常关键，默认关闭 Off）。

1.2 常见伪协议一览表

伪协议 主要作用
file:// 访问本地文件系统
php://filter 对读取/写入的流进行过滤处理（常用于读源码）
php://input 读取 POST 原始数据（常用于命令执行）
data:// 直接传输数据流（常用于命令执行）
http:// / https:// 远程文件包含（RFI）
phar:// / zip:// 解压并读取压缩包内的文件

在实际渗透和解题中，使用频率最高的应该是 php://filter 和 php://input。

威胁类别 (STRIDE) 核心含义 简单举例
