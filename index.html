CodeQL规则编写_Java内部测试API提取

发表于 2026-01-17 分类于 SAST

在 IRIS 项目中，第二步是提取全部内部测试 API ，CodeQL 规则编写如下，因为不太理解 CodeQL 规则如何编写，所以学习记录如下，内容由 GPT 5.2 生成。

解读方式：“这条规则想解决什么问题 → 每个谓词/函数做什么 → where 条件组合后的真实含义 → 可能的坑与改进”的顺序，带你把它吃透。

1）一句话概括：这条规则在找什么？

它在找：

“在 src/test 里被调用过、但在非 test（业务代码）里从未被调用过”的 public 且有参数的源代码方法。

更口语一点：

  • ✅ 测试代码里在用它（isTested）
  • ❌ 业务代码里没人用它（isNotInvokedByInternalFunction）
  • 并且方法是 public、来自项目源码、且至少有一个参数

这类方法常见场景：

  • 只为了测试而写的“辅助 API”（不一定是好事）
  • public 暴露出去但实际上没人用（可能是 dead API / 过度暴露）
  • 测试通过“直接调用内部方法”来测（可能说明设计不佳或测试方式不对）

2）fullSignature(Callable m)：拼一个“人类可读签名”

你这段和上一条差不多，只是单独拿来复用。

关键点 A：Constructor vs 普通方法

  • 构造函数没有返回值，所以输出 ClassName(...)
  • 普通方法输出 ReturnType methodName(...)

关键点 B：concat 遍历参数

它的意图是按参数顺序拼成：
int a, java.lang.String b

⚠️ 潜在坑：索引范围

  • m.getNumberOfParameters() 返回参数个数，比如 2
  • 参数下标通常是 0 和 1
  • 但你用了 [0 .. m.getNumberOfParameters()]（包含上界的话会多取一次）

在很多 CodeQL 示例里会用：

  • [0 .. m.getNumberOfParameters()-1]
  • 或者用 Parameter p | p = m.getAParameter() 这种更安全的写法

如果你跑起来没报错，可能是 CodeQL 的区间语义/实现把最后一个排除了，但从阅读角度这段写法很容易“越界风险”，建议改成更明确的写法。

3）isTested(Callable m)：在测试目录出现过调用

它在做什么？

  • 遍历所有调用 Call c
  • 找到被调用目标是 m 的调用点
  • 并且调用点的位置字符串里包含 "src/test"

✅ 这就是：至少有一次调用发生在 src/test 目录中

⚠️ 这条判断“测试代码”的方式比较粗糙

  • Maven/Gradle 常见测试路径：src/test/java
  • 但也可能是：src/test/kotlin、src/integrationTest、test/、src/it 等
  • 甚至 Windows 路径分隔符等问题（不过 toString() 一般会统一）

更稳妥方式是用 CodeQL 自带的测试/文件夹抽象（如果有），或者用正则匹配更完整路径。

4）isNotInvokedByInternalFunction(Callable m)：业务代码里从未调用过

翻译成人话

不存在这样的调用 c：

  • 调用了 m
  • 并且调用位置 不在 src/test（因为 indexOf < 0 表示没找到）

等价于：

m 的所有调用点都在测试目录中（或者根本没人调用）

但注意：你在 where 里又加了 isTested(method)，所以确保至少在测试里被调用一次。
因此最终效果是：

只被测试调用过（至少一次），从不被业务代码调用。

⚠️ 命名有点误导

isNotInvokedByInternalFunction 其实检查的是“非 test 的任何调用”。
并不一定是“internal function”（内部函数）调用，也可能是 main、工具脚本、样例代码等。
更贴切的名字可能是 hasNoNonTestCallSites。

5）paramTypes(Callable m)：只拼参数类型

输出像：
int;java.lang.String;boolean

用途通常是：

  • 比 getStringSignature() 更可控
  • 用于后处理（CSV 分析）做“方法重载区分”

同样有上面提到的索引区间潜在坑。

6）getJavadocString(Callable m)：把 JavaDoc 扁平化成字符串

这个函数最终让你的输出列里有 doc 文本，方便：

  • 生成报告
  • 过滤“有没有说明文档”
  • 做 NLP/检索（比如把这些 API 建索引）

7）主查询：from / where 的组合含义

逐个解释：

✅ method.fromSource()

只选项目源码里的方法（排除库/依赖里解析出来的方法）

✅ method.isPublic()

只关心 public 方法
→ 这意味着你在找“对外暴露的 API”，但其实只被测试用。

✅ not method.hasNoParameters()

只关心有参数的方法
（可能你想排除 getter / toString 这种零参方法，让结果更有价值）

✅ isTested(method)

必须在 src/test 至少出现一次调用

✅ isNotInvokedByInternalFunction(method)

必须在非 test 路径中 没有任何调用

8）select 输出：你最终想拿到什么信息？

你输出的是一张“方法清单”表：

  • package
  • clazz
  • func（方法名）
  • full_signature（人类可读签名）
  • internal_signature（CodeQL 的签名字符串，更偏机器）
  • location（方法声明位置）
  • parameter_types（类型列表）
  • return_type
  • doc（Javadoc）

👉 这是典型的“导出 CSV / 报告”的结构。

9）这条规则的典型用途（为什么有意义？）

它可以用于发现：

A. 只为测试写的 public API（过度暴露）

如果一个 public 方法只被测试调用，那它可能本不该是 public。

B. “死 API”

对业务没有任何调用，但测试仍在测它——可能是旧功能遗留。

C. 测试策略问题

测试直接调用内部方法，而不是通过更高层接口测试行为。

10）重要的坑与改进建议（很实用）

改进 1：测试路径判断更稳

当前用 "src/test" 字符串包含判断，建议更精确：

  • 匹配 src/test/java、src/test/kotlin
  • 或额外覆盖 src/integrationTest 等

改进 2：区分“被测试调用” vs “测试类反射/框架调用”

如果测试是通过反射、参数化框架、Spring 容器间接触发，有时 Call 不会出现显式调用点。结果会漏。

改进 3：排除构造函数/重载/接口方法等

你现在是 Callable，包含：

  • 方法
  • 构造器
  • 可能还包括一些特殊 callable

如果你的目标是“public 方法”，更常用 Method 类型：

改进 4：把 “业务代码里没人调用” 限定为 fromSource

现在 isNotInvokedByInternalFunction 只看 location 字符串。
更稳的是限定调用点来源文件也是 source。

RSA原理解读

发表于 2026-01-17 分类于 密码学

内容由 Gemini 3 Flash Preview 生成，个人认为讲解的是最好的了，比较通俗易懂。

RSA 算法之所以能够实现“加密后再解密”并回到原文，其核心秘密在于数论中的一个神奇特性：通过巧妙构造的一对密钥（公钥和私钥），我们可以利用幂运算和取模运算，在一个闭环的数学世界里绕一圈后再回到起点。

为了理解透彻，分三个层面来剖析：直观逻辑、操作步骤和数学原理。

1. 直观逻辑：神奇的“数学回力棒”

可以把 RSA 想象成一个特殊的魔术盒。

  • 加密（投掷）： 你把数字 $M$（明文）放进去，按一下公钥按钮（求 $e$ 次方再取模），数字会变成一个面目全非的密文 $C$。
  • 解密（返回）： 对方收到 $C$ 后，按一下只有他持有的私钥按钮（求 $d$ 次方再取模），这个面目全非的数字竟然会像回力棒一样，**精准地变回原来的数字 $M$**。

这种“对称性”是由特殊的数学关系保证的。

2. 操作步骤：密钥是如何产生的？

要理解为什么能解密，先看公钥和私钥是怎么选出来的。

  1. 选种子： 选两个巨大的质数 $p$ 和 $q$。
  2. 算模数： $n = p \times q$。这个 $n$ 会公开，是加解密的公用容器。
  3. 算欧拉函数： $\phi(n) = (p-1) \times (q-1)$。这个值是生成密钥的关键，必须保密。
  4. 选公钥 $e$： 选一个与 $\phi(n)$ 互质的数 $e$。
  5. 算私钥 $d$： 这是最关键的一步，要找到一个 $d$，使得 $(e \times d)$ 除以 $\phi(n)$ 的余数等于 1。用数学公式表达就是：
    $$e \cdot d \equiv 1 \pmod{\phi(n)}$$

结论： 公钥是 $(n, e)$，私钥是 $(n, d)$。它们通过 $\phi(n)$ 像纽扣一样紧紧扣在一起。

3. 数学原理：为什么 $(M^e)^d$ 能回到 $M$？

这是你最关心的部分。加密和解密的过程如下：

  • 加密： $C = M^e \pmod n$
  • 解密： $M’ = C^d \pmod n$

我们要证明的是：$M’ = (M^e)^d \pmod n$ 是否等于 $M$？也就是证明：
$$M^{ed} \equiv M \pmod n$$

核心依据：欧拉定理（Euler’s Theorem）

数学家欧拉证明过：如果 $M$ 和 $n$ 互质，那么 $M^{\phi(n)} \equiv 1 \pmod n$。

根据我们产生私钥时的规定，$e \cdot d$ 除以 $\phi(n)$ 余 1，所以可以写成：
$$e \cdot d = k \cdot \phi(n) + 1 \quad (\text{其中 } k \text{ 是整数})$$

现在我们代入到解密公式里：
$$M^{ed} = M^{k \cdot \phi(n) + 1} = (M^{\phi(n)})^k \cdot M^1$$

根据欧拉定理，括号里的 $M^{\phi(n)}$ 在模 $n$ 的世界里等于 1。
所以：
$$(1)^k \cdot M = 1 \cdot M = M$$

这就是 RSA 能够还原原文的数学真相： 密钥 $e$ 和 $d$ 的乘积被设计成“欧拉函数的一个循环再多加 1”。在取模运算下，绕着 $\phi(n)$ 转圈最终都会回到 1，多出的那个“1”就把原始的 $M$ 给带回来了。

4. 为什么这样是安全的？

既然 $e$ 是公开的，为什么别人算不出 $d$？

  • 要算出 $d$，必须知道 $\phi(n)$。
  • 要算出 $\phi(n)$，必须知道 $p$ 和 $q$（即对 $n$ 进行质因数分解）。
  • 现实困难： 当 $n$ 非常大时（比如 2048 位二进制），人类目前的计算机在可接受的时间内（比如几千年）根本无法分解出 $p$ 和 $q$。

总结

RSA 能够加解密，是因为它利用了大质数乘积的不可逆性来保护秘密，并利用了欧拉定理的周期性（模运算下的幂循环）来确保加密后的数据可以通过特定的数学钥匙精准还原。

IRIS：基于LLM辅助的静态分析检测安全漏洞

发表于 2026-01-13 分类于 SAST

软件容易受到安全漏洞的影响。用于检测这些漏洞的程序分析工具由于依赖人工标注的规范，在实践中效果有限。大型语言模型（LLM）展现出令人印象深刻的代码生成能力，但它们无法对代码进行复杂推理以检测此类漏洞，特别是因为此任务需要全仓库分析。我们提出了IRIS，一种神经符号方法，系统地结合LLM与静态分析来执行全仓库推理以检测安全漏洞。具体来说，IRIS利用LLM推断污点规范并执行上下文分析，从而减轻对人工规范和检查的需求。为了评估，我们策划了一个新数据集CWE-Bench-Java，包含120个经过人工验证的真实Java项目中的安全漏洞。最先进的静态分析工具CodeQL仅检测到其中27个漏洞，而使用GPT-4的IRIS检测到55个（+28），并将CodeQL的平均误报发现率提高了5个百分点。此外，IRIS识别出4个以前未知的漏洞，这些漏洞无法被现有工具发现。IRIS已公开发布于 https://github.com/iris-sast/iris。

📌 关键解读1：研究动机与核心贡献

核心问题

  1. 静态污点分析的局限：传统工具如CodeQL严重依赖人工标注的API规范（源、汇点、净化器），这导致：

    • 规范缺失→漏报
    • 规范不精确→误报

  2. LLM的潜力与限制：

    • LLM能理解代码但无法进行复杂的全项目推理
    • 需要结合静态分析的精确性

核心创新

IRIS提出的神经符号方法实现了三个关键突破：

  1. 自动规范推断：使用LLM从API文档和代码中推断污点源和汇点
  2. 上下文感知过滤：利用LLM理解代码上下文，减少误报
  3. 全仓库分析：结合静态分析的数据流追踪能力

1. 引言

安全漏洞对软件应用程序及其用户的安全构成重大威胁。仅在2023年，就报告了超过29,000个CVE——比2022年高出近4000个（CVE趋势）。尽管在揭示漏洞的技术方面取得了进展，检测漏洞仍然极具挑战性。

一种名为静态污点分析的有前景技术被广泛应用于流行工具中，如GitHub CodeQL、Facebook Infer、Checker Framework和Snyk Code。然而，这些工具面临几个极大限制其在实践中有效性和可访问性的挑战。

1.1 主要挑战

由于缺少第三方库API的污点规范而导致的漏报

静态污点分析主要依赖第三方库API作为源、汇点或净化器的规范。在实践中，开发人员和分析工程师必须根据他们的领域知识和API文档手动制作这些规范。这是一个费力且容易出错的过程，经常导致规范缺失和漏洞分析不完整。此外，即使这些规范可能存在于许多库中，它们也需要定期更新以捕获这些库新版本中的变化，并覆盖开发的新库。

由于缺乏精确的上下文感知和直观推理而导致的误报

众所周知，静态分析经常受到低精度的困扰，即可能产生许多虚假警报。这种不精确源于多种来源。例如，源或汇点规范可能是虚假的，或者分析可能过度近似代码中的分支或可能的输入。此外，即使规范正确，检测到的源或汇点所使用的上下文可能无法被利用。因此，开发人员可能需要筛选几个潜在的虚假安全警报，浪费大量时间和精力。

1.2 先前数据驱动方法的局限性

已经提出了许多技术来解决静态污点分析的挑战。例如，MERLIN提出了一种概率方法来自动挖掘污点规范。最近的工作Seldon通过将污点规范推断问题表述为线性优化任务来提高这种方法的可扩展性。然而，这些方法依赖于分析第三方库的代码来提取规范，这既昂贵又难以扩展。研究人员还开发了统计和基于学习的技术来缓解虚假正警报。然而，这些方法在实践中仍然效果有限。

网络攻击概述

网络攻击是指损害网络系统安全属性的危害行为。危害行为导致网络系统的机密性、完整性、可用性、真实性、抗抵赖性等受到不同程度的破坏。

常见的危害行为有四个基本类型：信息泄露攻击；完整性破坏攻击；拒绝服务攻击；非法使用攻击。

网络攻击模型

掌握网络攻击模型有助于更好地理解分析网络攻击活动，以便对目标系统的抗攻击能力进行测评。常见的网络攻击模型如下：

以下为图片中的文字内容（按原结构整理）：

1. 攻击树模型：起源于故障树分析方法，经过扩展形成 AND-OR 形式的树结构 对目标对象进行网络安全威胁分析。可以被 Red Team 用来进行渗透测试，同时也可以被 Blue Team 用来研究防御机制。

◆ 优点：
能够采取专家头脑风暴法，并且将这些意见融合到攻击树中去；
能够进行费效分析或者概率分析；
能够建模非常复杂的攻击场景。

◆ 缺点：
由于树结构的内在限制，攻击树不能用来建模多重常识攻击、时间依赖及访问控制等场景；
不能用来建模循环事件；
对于现实中的大规模网络，攻击树方法处理起来将会特别复杂。

2. MITRE ATT&CK 模型：
根据真实观察到的网络攻击数据提炼形成的攻击矩阵模型；
该模型把攻击活动抽象为初始访问、执行、持久化、特权提升、躲避防御、凭据访问、发现、横向移动、收集、指挥和控制、外泄、影响，然后给出攻击活动的具体实现方式。
主要应用场景有：网络红蓝对抗模拟、网络安全渗透测试、网络防御差距评估、网络威胁情报收集等。

3. 网络杀伤链（Kill Chain）模型：
将网络攻击活动分成目标侦察、武器构造、载荷投送、漏洞利用、安装植入、指挥和控制、目标行动等七个阶段。

网络攻击一般过程

（1）隐藏攻击源。 利用被侵入的主机作为跳板；免费代理网关；伪造 IP 地址；假冒用户账号。

（2）收集攻击目标信息。 收集目标系统一般信息、配置信息、安全漏洞信息、安全措施信息、用户信息。

（3）挖掘漏洞信息。 系统或应用服务软件漏洞；主机信任关系漏洞；目标网络的使用者漏洞；通信协议漏洞；网络业务系统漏洞。

（4）获取目标访问权限。 获得系统管理员的口令；利用系统管理上的漏洞；让系统管理员运行一些特洛伊木马；窃听管理员口令。

（5）隐藏攻击行为。 连接隐藏；进程隐藏；文件隐藏。

（6）实施攻击。 攻击其他被信任的主机和网络；修改或删除重要数据；窃取敏感数据；停止网络服务；下载敏感数据；删除数据账号；修改数据记录。

（7）开启后门。 放宽文件许可权；重新开放不安全的服务；修改系统的配置；替换系统本身的共享库文件；修改系统的源代码；安装各种特洛伊木马；安装嗅探器；建立隐藏信道。

（8）清除攻击痕迹。 篡改日志文件中的审计信息；改变系统时间造成日志文件数据紊乱以迷惑系统管理员；删除或停止审计服务进程；干扰入侵检测系统的正常运行；修改完整性检测标签。

网络攻击常见技术方法

1.端口扫描

端口扫描目的是找出目标系统上提供的服务列表。
挨个尝试与 TCP/UDP 端口连接，然后根据端口与服务的对应关系，结合服务器端的反映推断目标系统上是否运行了某项服务，攻击者通过这些服务可能获得关于目标系统的进一步的知识或通往目标系统的途径。
扫描类型包括：

  • 完全连接扫描：利用 TCP/IP 协议的三次握手连接机制，使源主机和目的主机的某个端口建立一次完整的连接。如果建立成功，则表明该端口开放；否则，表明该端口关闭。

  • 半连接扫描：是指在源主机和目的主机的三次握手连接过程中，只完成前两次握手，不建立一次完整的连接。

  • SYN 扫描：首先向目标主机发送连接请求，当目标主机返回响应后，立即切断连接过程，并查看响应情况。如果目标主机返回 ACK 信息，表示目标主机的该端口开放；如果目标主机返回 RESET 信息，表示该端口没有开放。

  • ID 头扫描：ID 头扫描是一种非常隐蔽的端口扫描方法，攻击者不会直接扫描目标主机，而是利用一台几乎不与外界通信的“空闲主机”。通过伪造空闲主机的 IP 地址向目标主机发送连接请求，再观察空闲主机返回数据包中 IP ID 字段的变化情况，来判断目标主机端口是否开放。如果空闲主机的 IP ID 增长异常，说明目标端口是开放的；如果按正常规律递增，则说明端口未开放。

    • 具体操作：需要用一台第三方机器配置扫描，并且这台机器的网络通信量要非常少，即 dumb 主机。首先由源主机 A 向 dumb 主机 B 发出连续的 PING 数据包，并且查看主机 B 返回的数据包的 ID 头信息。一般而言，每个顺序数据包的 ID 头的值会加 1。然后由源主机 A 假冒主机 B 的地址向目的主机 C 的任意端口（1–65535）发送 SYN 数据包。这时，主机 C 向主机 B 发送的数据包有两种可能的结果：

    • ◆ SYN | ACK：表示该端口处于监听状态。

    • ◆ RST | ACK：表示该端口处于非监听状态。

    • 那么，由后续 PING 数据包的响应信息的 ID 头信息可以看出，如果主机 C 的某个端口是开放的，则主机 B 返回的数据包中，ID 头的值不是递增 1，而是大于 1。如果主机 C 的某个端口是非开放的，则主机 B 返回的数据包中，ID 头的值递增 1，非常规律。

  • 隐蔽扫描：是指能够成功地绕过 IDS、防火墙和监视系统等安全机制，取得目标主机端口信息的一种扫描方式。

  • SYN | ACK 扫描：由源主机向目标主机的某个端口直接发送 SYN/ACK 数据包，而不是发送 SYN 数据包。由于这种方法不发送 SYN 数据包，目标主机认为这是一次错误的连接，从而会报错。如果目标主机的该端口没有开放，会返回 RST 信息；如果该端口开放（LISTENING），则不会返回任何信息，而是直接将这个数据包丢弃。

  • FIN 扫描：源主机 A 向目标主机 B 发送 FIN 数据包，然后查看反馈消息。如果端口返回 RESET 信息，则说明该端口关闭；如果端口没有返回任何信息，则说明端口开放。

  • ACK 扫描：首先由主机 A 向目标主机 B 发送 FIN 数据包，然后查看反馈数据包的 TTL 值和 WIN 值。开放端口所返回的数据包的 TTL 值一般小于 64，而关闭端口的返回值一般大于 64；开放端口所返回的 WIN 值一般大于 0，而关闭端口的返回值一般等于 0。

  • NULL 扫描：将源主机发送的数据包中的 ACK、FIN、RST、SYN、URG、PSH 等标志位全部置空。如果目标主机没有返回任何信息，则表明该端口是开放的；如果返回 RST 信息，则表明该端口是关闭的。

  • XMAS 扫描：原理和 NULL 扫描相同，只是将要发送的数据包中的 ACK、FIN、RST、SYN、URG、PSH 等标志位全部置 1。如果目标主机没有返回任何信息，则表明该端口是开放的；如果返回 RST 信息，则表明该端口是关闭的。

    为什么扫描经常会用到 RST 呢？ 因为当主机收到无法识别或不合法的 TCP 请求，且对应端口没有监听时，必须返回 RST（复位）报文。RST（Reset，复位）是 TCP 的一种控制报文，作用是立即终止一个不存在、异常或错误的连接。

2.口令破解

口令机制是系统访问控制的第一道防线，攻击者通过不断尝试用户名和口令来获取系统访问权限。其基本过程是：先与目标服务器建立连接，然后准备用户名和密码字典，按照网络服务协议将用户名和口令组合发送给目标服务，分析服务器的返回结果判断是否登录成功，若失败则更换新的用户名和口令反复尝试，直到成功或字典用完为止。

3.缓冲区溢出

通过向程序的缓冲区写出超出其长度的内容，造成缓冲区溢出，从而破坏程序的堆栈，使程序转而执行其他预设指令，以达到攻击目的的攻击方法。

缓冲区溢出攻击的基本原理是向缓冲区中写入超长的、预设的内容，导致缓冲区溢出，覆盖其他正常的程序或数据，然后让计算机转去运行预设的程序，达到执行非法操作、实现攻击的目的。

4.恶意代码

为达到恶意目的而专门设计的程序或代码，是指破坏计算机或网络系统可靠性、可用性、安全性和数据完整性或者损耗系统资源的恶意程序。
常见的恶意代码类型有：计算机病毒、网络蠕虫、特洛伊木马、后门、逻辑炸弹、僵尸网络等。

5.拒绝服务攻击

拒绝服务攻击 DoS（Denial of Service）的主要目标是依靠网络系统或网络协议的缺陷和配置漏洞进行网络攻击，使网络拥塞、系统资源耗尽或者系统应用死锁，妨碍目标主机和网络系统对正常用户服务请求的及时响应，造成服务的性能受损甚至服务中断。

原理：消耗系统资源，导致目标主机宕机，从而阻止授权用户正常访问服务。

要对服务器实施拒绝服务攻击，实质上的方式就是有两个：

  1. 服务器的缓冲区满，不接收新的请求。
  2. 使用 IP 欺骗，迫使服务器把合法用户的连接复位，影响合法用户的连接。这也是 DoS 攻击实施的基本思路。

拒绝服务攻击类型有许多种，网络的内外部用户都可以发动这种攻击。内部用户可以通过长时间占用系统的内存、CPU 处理时间使其他用户不能及时得到这些资源，而引起拒绝服务攻击；外部攻击者可以通过占用网络连接使其他用户得不到网络服务。

外部用户针对网络连接发动拒绝服务攻击主要有几种模式：消耗资源、破坏或更改配置信息、物理破坏或改变网络部件、利用服务程序中的处理错误使服务失效。

  • SYN Flooding：利用 TCP 协议缺陷发送大量伪造的 TCP 连接请求，使得服务器资源耗尽。三次握手，进行了两次，不进行第三次握手，连接队列处于等待状态，大量这样的等待，会占满全部队列空间，使得系统挂起。

  • Smurf 攻击：攻击者伪装目标主机向局域网的广播地址发送大量欺骗性的 ICMP 请求，这些包被放大，并发送到被欺骗的地址，大量的计算机向一台计算机回应 ECHO 包，目标系统会崩溃。

  • Ping of Death 攻击：攻击者故意发送大于 65535 字节的 IP 数据包给对方，导致内存溢出，这时主机会出现内存分配错误而导致 TCP/IP 堆栈崩溃，导致死机。

  • Teardrop 攻击：分段攻击，伪造数据报文向目标主机发送含有重叠偏移的数据分段，通过将各个分段重叠来使目标系统崩溃或挂起。

  • Winnuke 攻击：针对 Windows 系统开放的 139 端口，只要向该端口发送 1 字节的 TCPOOB 数据（TCP 连接的一种特殊数据，设置了 URG 标志，优先级更高），就可以使 Windows 系统出现蓝屏错误，并且网络功能完全瘫痪。

  • Land 攻击：也是利用三次握手的缺陷进行攻击，将 SYN 数据包的源地址和目的地址都设置为目标主机的地址，目标主机向自己回应 SYN+ACK 包，导致自己又给自己回一个 ACK 并建立自己与自己的连接。当这种无效连接达到一定的数量，目标主机将会拒绝新的连接请求。

  • 电子邮件轰炸：针对服务端口（SMTP 端口，端口号 25）的攻击，攻击者通过连接邮件服务器的 25 端口，按照 SMTP 协议发送几行头信息加上一堆文字垃圾，反复发送形成邮件轰炸。

  • 低速率拒绝服务攻击（Low-rate DoS，LDoS）：与传统的洪泛式 DoS 攻击截然不同，其最大特点是不需要维持高速率攻击流，耗尽受害者端所有可用资源，而是利用网络协议或应用服务中常见的自适应机制（如 TCP 的拥塞控制机制）中所存在的安全漏洞，通过周期性地在一个特定的短暂时间间隔内突发性地发送大量攻击数据包，从而降低被攻击端服务性能。

  • 分布式拒绝服务攻击 DDoS（Distributed Denial of Service）：是对传统 DoS 攻击的发展，攻击者首先侵入并控制一些计算机，然后控制这些计算机同时向一个特定的目标发起拒绝服务攻击。
    分布式攻击 C/S 结构：

    • Client（客户端）：运行在攻击者的主机上，用来发起和控制 DDoS 攻击；

    • Handler（主控端）：运行在被攻击者侵入并获得控制的主机上，用来控制代理端；

    • Agent（代理端）：运行在已被攻击者侵入并获得控制的主机上，从主控端接收命令，负责对目标实施实际的攻击。

6.网络钓鱼（Phishing，与 fishing 发音相近名）

是一种通过假冒可信方（知名银行、在线零售商和信用卡公司等可信的品牌）提供网上服务，以欺骗手段获取敏感个人信息（如口令、信用卡详细信息等）的攻击方式。网络钓鱼者利用欺骗性的电子邮件和伪造的网站来进行诈骗活动，诱骗访问者提供一些个人信息，以谋求不正当的利益。

7.网络窃听

是指利用网络通信技术缺陷，使得攻击者能够获取到其他人的网络通信信息。常见的网络窃听技术手段主要有网络嗅探、中间人攻击。网络攻击者将主机网络接口的方式设成“混杂”模式，就可以接收整个网络上的信息包，从而可以获取敏感口令，甚至将其重组、还原为用户传递的文件。

8.SQL 注入攻击

在 Web 服务中，一般采用三层架构模式：浏览器 + Web 服务器 + 数据库。其中，WEB 应用程序负责处理来自浏览器的请求。但是由于 WEB 应用程序的编程漏洞，对来自浏览器的信息缺乏输入安全合法性检查，网络攻击者利用这个漏洞，把 SQL 命令插入 WEB 表单的输入域或页面的请求参数字符串，欺骗服务器执行恶意的 SQL 命令。

9. 社会工程学

网络攻击者通过一系列的社交活动，获取需要的信息。例如伪造系统管理员的身份，给特定的用户发电子邮件欺骗他的密码口令。有的攻击者给用户发送免费程序，不过该程序除了完成用户所需的功能外，还隐藏了一个将用户的计算机信息发送给攻击者的功能。

10.电子监听

网络攻击者采用电子设备远距离地监视电磁波的传送过程。灵敏的无线电接收装置能够在远处看到计算机操作者输入的字符或屏幕显示的内容。

11.会话劫持

是指攻击者在初始授权之后建立一个连接，在会话劫持以后，攻击者具有合法用户的特权权限，如 “TCP 会话劫持”。

12.漏洞扫描

是一种自动检测远程或本地主机安全漏洞的软件，通过漏洞扫描器可以自动发现系统的安全漏洞。常见的漏洞扫描技术有 CGI 漏洞扫描、弱口令扫描、操作系统漏洞扫描、数据库漏洞扫描等。

13.代理技术

网络攻击者通过免费代理服务器进行攻击，其目的是以代理服务器为“攻击跳板”，即使攻击目标的网络管理员发现了，也难以追踪到网络攻击者的真实身份或 IP 地址。为了增加追踪的难度，网络攻击者还会采用多级代理服务器或者“跳板机”来攻击目标。在黑客中，代理服务器被称为“肉鸡”，黑客常利用所控制的机器进行攻击活动，如 DDoS 攻击。

14.数据加密

网络攻击者常采用数据加密技术来逃避网络安全管理人员的追踪。加密使网络攻击者的数据得到有效保护，即使网络安全管理人员得到这些加密的数据，没有密钥也无法读懂，这就实现了攻击者的自我保护。攻击者的安全原则是，任何与攻击有关的内容都必须加密或者立刻销毁。

典型攻击案例

W32.Blaster.Worm（冲击波蠕虫） 的典型攻击案例：W32.Blaster.Worm 是一种利用 Windows 系统 DCOM RPC 漏洞进行传播的网络蠕虫。它通过扫描网络中存在漏洞的主机，主动连接目标主机的 TCP 135 端口发起 RPC 漏洞攻击，在目标主机上打开 TCP 4444 端口获取命令行控制权限，并通过 UDP 69（TFTP） 将蠕虫程序下载到受害主机并执行，实现自动传播。蠕虫会在系统中写入注册表项以实现开机自启动，导致系统频繁重启、运行不稳定。同时，该蠕虫还会在特定时间段对 windowsupdate.com 发动拒绝服务攻击，阻止用户下载系统补丁，从而进一步扩大感染范围。

网络信息安全概述

发表于 2026-01-06 分类于 软考

网络发展趋势——数字化、网络化、智能化

网络安全（狭义）指网络信息系统的各组成要素符合安全属性的要求，包含机密性、完整性、可用性、抗抵赖和可控性

网络安全（广义）包含国家安全、城市安全、经济安全、社会安全、生产安全、人身安全在内的大安全

网络安全新变化：

  • 单维向多维转变，保障维度包含网络空间域、物理空间域、社会空间域
  • 网络信息安全保障措施从单一性转向综合性（法律、政策、技术、管理、产业、教育）
  • 保障时间维度要求涵盖网络系统的整个生命周期，保障相应速度不断缩短，网络安全无战时、平时之分，而是时时刻刻

网络信息安全涉及方面

  1. 网络强依赖及关联风险
  2. 产品供应链和安全质量风险
  3. 技术同质性和技术滥用风险
  4. 安全建设和管理发展不平衡
  5. 数据安全
  6. 高级持续威胁
  7. 恶意代码
  8. 软件安全漏洞
  9. 网络安全意识
  10. 技术复杂性和运营安全
  11. 灰黑产
  12. 间谍

网络信息安全基本属性

基本属性

  • 机密性 Confidentiality 信息不泄露给非授权用户
  • 完整性 integrity 未经授权不能进行更改
  • 可用性 availability 合法许可用户能够及时获取网络信息或服务
  • 抗抵赖性 防止用户否认其活动行为
  • 可控性 主体对其具有管理和支配能力

其他属性

  • 真实性 客观事实保持一致
  • 时效性 满足时间约束要求
  • 合规性 符合法律法规政策、标准规范要求
  • 公平性 同等地位处理相关任务
  • 可靠性 有效完成预定系统功能特性
  • 可生存性 提供最小化必要服务
  • 隐私性 敏感信息不对外公开

网络安全基本要求

宏观：网络信息系统满足国家安全需求特性

微观：具体安全要求

基本功能：具备防御、监测、应急和恢复功能

其他方面：物理环境安全、安全认证、访问控制、保密、漏洞扫描、恶意代码防护、内容安全、监测预警、应急响应。

网络信息安全管理

管理对象：网络设备、网络通信协议、操作系统、网络服务、安全网络管理在内的软硬件和。企业、机构直接赋予了价值而需要保护的资产。

涉及内容：物理安全、通信安全、操作系统安全、网络服务安全、操作安全和人员安全。

网络安全管理方法：风险管理、等级保护、纵深防御、层次化防护、应急响应以及PDCA方法。

网络信息安全管理要素：网络管理对象、网络威胁、网络脆弱性、网络风险、网络保护措施。

安全威胁：自然威胁和人为威胁。

风险控制包括：避免风险、转移风险、减少威胁、消除脆弱点、减少威胁影响、风险监测。

管理工作流程如下：确定对象、评估价值、识别威胁、识别脆弱性、确定风险级别、指定防护体系和措施、实施和落实、运行和维护。

生命周期：

  • 系统规划：风险评估，标识安全目标和安全需求；
  • 系统设计：风险控制方法，安全解决方案，安全体系结构涉及；
  • 系统集成：购买部署安全产品，系统安全配置，效果评估，需求、环境验证；
  • 运行维护：建立管理组织，制定规章制度，定期评估对象，挑战安全配置，漏洞修复，安全监测和应急处理；
  • 系统废弃：对要废弃的系统组件进行评估、处理和更新。

网络信息安全法规

网络信息安全管理评估：网络信息安全等级保护测评、信息安全管理体系认证（ISMS）、系统安全工程能力成熟度模型（SSE-CMM）

《中华人民共和国网络安全法》由第十二届全国人大第二十四次会议2016年11月7日通过，2017年6月1日执行。

《中华人民共和国密码法》于2020年1月1日起实施。

采取监测、记录网络运行状态、网络安全事件的技术措施，按照规定留存的网络日志不少于6个月。

网络安全等级保护

等保工作可以概括为：定级、备案、建设整改、等级测评、运营维护。

  • 定级：确定定级对象
  • 备案：准备备案材料
  • 建设整改：根据差距分析，针对不符合项结合行业要求对保护对象进行整改
  • 等级测评：对定级的保护对象进行测评
  • 运行维护：对保护对象的安全相关事宜进行监督管理

网络信息安全领域顶刊：S&P、CCS、NDSS、USENIX Security

网络信息安全术语包含：基础技术类、风险评估类、防护技术类、检测技术类、响应恢复类、测评技术类。

  • 密码：加密、解密、非对称加密、公钥、私钥
  • 风险评估：分布式拒绝服务、网页篡改、网页仿冒、挂马、域名劫持、垃圾邮件、恶意代码、特洛伊木马、网络蠕虫、僵尸网络
  • 防护技术：访问控制、防火墙、入侵检测
  • 检测技术：入侵检测、漏洞扫描
  • 响应恢复：应急响应、灾难恢复、备份
  • 测评技术：黑盒测试、白盒测试、灰盒测试、渗透测试、模糊测试

漏洞代码分析

这段代码定义了一个Spring MVC 控制器方法（Controller Method），它是后端处理前端请求的入口点。

代码逐行详细解读

  • 功能：这是一个路由映射注解。
  • 含义：它告诉 Spring 框架，当服务器收到一个 HTTP POST 请求，且请求的路径（URL）是 /SqlInjection/attack2 时，请把这个请求交给下面定义的 completed 方法来处理。
  • 对应前端行为：用户在浏览器点击“提交”按钮时，浏览器会向这个地址发送数据。
  • 功能：这是一个响应处理注解。
  • 含义：它告诉 Spring，这个方法的返回值（AttackResult 对象）应该直接被序列化（通常转为 JSON 格式）并写入 HTTP 响应体（Body）中返回给浏览器，而不是被解析为 JSP 或 HTML 页面模板。
  • 对应前端行为：浏览器收到的不是一个新网页，而是一段 JSON 数据（如 {"lessonCompleted": true, "feedback": "..."}），前端 JS 脚本会读取这个 JSON 并弹窗提示结果。
  • 方法签名：定义了一个名为 completed 的公共方法。
  • **@RequestParam String query**：
    • 这是参数绑定。它告诉 Spring 从 HTTP 请求的参数中提取名为 “query” 的值，并将其赋值给方法参数 query。
    • 如果请求是 POST /SqlInjection/attack2?query=SELECT... 或者表单数据中包含 query=SELECT...，那么这里的 String query 就会得到那个 SQL 字符串。
  • **返回值类型 AttackResult**：这是 WebGoat 自定义的一个类，用来封装“练习结果”，包含是否通关、反馈信息等。
  • 逻辑：它没有自己处理业务逻辑，而是直接调用了同一个类中的辅助方法 injectableQuery(query)，并将结果直接返回。
  • 作用：这是一个简单的入口转发。真正执行 SQL 查询和判定是否通关的逻辑都在 injectableQuery 方法里（也就是下面那段有漏洞的代码）。

总结功能

这段代码的作用是在服务器上开放了一个名为 /SqlInjection/attack2 的接口，专门接收用户 POST 过来的 query 参数，然后把这个参数扔给内部逻辑去执行，最后把执行结果（成功或失败的消息）以 JSON 格式扔回给用户。

CodeQL 分析

如果使用 CodeQL 进行静态分析，它识别到的Source（污染源/用户输入点） 就是：

@RequestParam String query

具体来说，CodeQL 的污点跟踪（Taint Tracking）分析会标记以下位置为 Source：

  1. 位置：第 42 行的参数声明 String query。
  2. 原因：
    • 该方法被注解 @PostMapping 标记，表明这是一个处理 HTTP 请求的 Handler 方法。
    • 参数被注解 @RequestParam 标记（即使没有显式标记，Spring Boot 中默认非简单类型或特定配置下也会被视为输入）。
    • CodeQL 的 RemoteFlowSource 库（尤其是针对 Spring MVC 的建模）明确定义了被 @RequestParam、@RequestBody、@PathVariable 等注解修饰的控制器方法参数均视为不可信的外部输入（Untrusted User Input）。

CodeQL 视角的污点路径（Data Flow Path）

CodeQL 会追踪数据流，构建如下的路径：

  1. Source (源头): 第 42 行 completed(@RequestParam String query) 中的 query 变量。
    • 标记：Remote user input source
  2. Flow (传递): 第 43 行 return injectableQuery(query);，query 被传递给 injectableQuery 方法。
  3. Flow (传递): 第 46 行 protected AttackResult injectableQuery(String query)，参数 query 接收了污点。
  4. Sink (汇聚点/漏洞点): 第 49 行 statement.executeQuery(query);。
    • 标记：SQL Injection Sink (java.sql.Statement.executeQuery)

小结

CodeQL 会准确地将 第 42 行的 query 参数 识别为用户输入的源头。
