物理环境安全分析与防护

发表于 2026-02-04 分类于 软考

一、 物理安全的基本概念

  1. 定义：
    • 传统上称为“实体安全”。
    • 它是网络信息系统安全、可靠、不间断运行的基本保证。
    • 核心目标：保护支持系统运行的硬件（环境、设备、记录介质），防止因自然或人为因素导致信息丢失、泄露、破坏或服务中断。
  2. 广义定义：
    • 指由硬件、软件、操作人员、环境组成的“人、机、物”融合的网络信息物理系统的安全。

二、 物理安全威胁分析

威胁主要分为两大类：传统威胁与新型硬件威胁。

1. 常见（传统）威胁

  • 自然威胁：地震、洪水、火灾、鼠害、雷电等。
  • 人为威胁：盗窃、爆炸、毁坏、硬件攻击等。

2. 新型硬件威胁

具有隐蔽性、危害性、攻击主动性和非临近性。

  • 硬件木马：
    • 指在集成电路（IC）全生命周期（研发、制造、封装、应用）中植入的恶意电路。
    • 激活后会导致信息泄露或功能失控。
  • 硬件协同的恶意代码：利用硬件特性，使非授权软件访问特权内存区域。
  • 硬件安全漏洞利用：
    • 具有持久性和破坏性。
    • 典型案例：2018年的“熔断”（Meltdown）和“幽灵”（Spectre）CPU漏洞，通过侧信道攻击获取缓存数据。
  • 基于软件漏洞攻击硬件实体：
    • 利用控制系统软件漏洞修改物理配置，破坏硬件。
    • 典型案例：“震网”（Stuxnet）病毒。
  • 基于环境攻击：利用电磁波、温度、湿度等外部环境缺陷破坏系统运行。

三、 物理安全保护体系

1. 保护维度

  • 设备物理安全：标志标记、防电磁泄露/干扰、电源保护、抗震动、供应链安全（防木马）。
  • 环境物理安全：机房选址、屏蔽、防火/水/雷/鼠/盗、供电及空调系统。
  • 系统物理安全：介质安全、灾难备份、访问控制、资源利用。

2. 保护方法

  • 安全合规、访问控制、安全屏蔽、故障容错、安全监测与预警、供应链管理、容灾备份。

3. 分级标准

依据《信息系统物理安全技术要求（GB/T 21052-2007）》，分为四个等级：

  • 第一级：用户自主保护级（基本保护）。
  • 第二级：系统审计保护级（适当保护）。
  • 第三级：安全标记保护级（较高程度保护）。
  • 第四级：结构化保护级（更高程度保护）。

四、 物理环境安全分析与防护（具体措施）

针对具体的环境风险，采取了以下针对性措施：

  1. 防火：消除隐患、安装报警系统、配置灭火设备、加强管理规范。
  2. 防水：
    • 机房内禁铺水管（或做防漏措施）。
    • 墙壁/天花板/地面需防水防潮。
    • 选址避免底层或地下室，防止雨水倒灌。
  3. 防震：建筑物抗震、机柜设备固定、禁止移动在线设备。
  4. 防盗：报警器、锁定装置、视频监控、严格的物理访问控制。
  5. 防鼠虫害：
    • 封堵洞口。
    • 使用超声波驱鼠、捕鼠器、投放毒饵（需谨慎）。
    • 电缆使用防鼠涂层或毒饵。
  6. 防雷：
    • 安装避雷针。
    • 设备安全接地并连通地线网。
    • 重要设备加装专用防雷设施。
  7. 防电磁：
    • 目的：防止干扰和信息泄露。
    • 措施：接地、屏蔽、合理选址。
  8. 防静电：
    • 人员穿着防静电衣鞋、戴静电手套。
    • 控制机房温湿度。
    • 地板和工作台使用防静电材料/阻值达标。
  9. 安全供电：
    • 专用供电线路。
    • 配备不间断电源（UPS）。
    • 配备备用发电机。

网络安全体系建设

发表于 2026-02-02 分类于 软考

一、 国内核心标准：网络安全等级保护 2.0 (MLPS 2.0)

这是中国网络安全工作的“基本法”和最核心的合规要求。

1. 核心流程与分级

  • 工作流程：定级、备案、建设整改、等级测评、监督检查。
  • 定级方法：通过评估“业务信息安全”和“系统服务安全”受破坏后的侵害程度，综合判定。
  • 五个安全等级（级别越高，保护越严）：
    • 一级：用户自主保护级
    • 二级：系统审计保护级
    • 三级：安全标记保护级（注：通常企业核心系统是三级）
    • 四级：结构化保护级
    • 五级：访问验证保护级

2. 等保 2.0 的三大变化（重点）

相比于旧版（1.0），2.0 标准做了重大升级：

  1. 对象范围扩大：不再只管传统电脑网络，把云计算、移动互联、物联网、工业控制系统全都管起来了（通用要求+扩展要求）。
  2. 防护架构升级：提出了“一个中心，三重防护”的架构：
    • 一个中心：安全管理中心。
    • 三重防护：安全通信网络、安全区域边界、安全计算环境。
  3. 强化“可信计算”：这是2.0的一大特色，要求从一级到四级都要逐步增加“可信验证”。
    • 意思是从系统启动（引导程序）开始，到应用程序运行，每一步都要验证“你是你，你没被篡改”，一旦发现被篡改立刻报警。

二、 行业应用案例：智慧城市安全体系

这是一个典型的复杂巨系统安全建设案例，强调“全方位、立体化”。

  • 顶层设计：最上面是战略保障（法律、政策、标准）。
  • 左右护法：
    • 左边是管理体系（决策、组织、协调、评价）。
    • 右边是运营体系（实施、监测、应急、恢复）。
  • 核心技术柱（中间部分）：
    采用了分层防护思想，从下到上依次为：
    1. 物联感知层（摄像头、传感器安全）
    2. 网络通信层（传输安全）
    3. 计算存储层（云平台、服务器安全）
    4. 数据与服务融合层（数据隐私、融合安全）
    5. 智慧应用层（App、Web安全）
  • 基础支撑：最底下是密钥管理、身份认证（PKI/CA）等基础设施。

三、 国际管理标准：ISO 27000 (ISMS)

这是全球公认的信息安全管理体系标准，核心思想是动态循环。

  • 核心逻辑：PDCA 循环
    • P (Plan) 计划：建立 ISMS。识别资产，评估风险，制定策略（比如决定要不要装防火墙）。
    • D (Do) 执行：实施和运行。把计划落到实处，进行日常管理。
    • C (Check) 检查：监视和评审。检查做得怎么样，有没有漏洞，效果好不好。
    • A (Act) 处理：维护和提升。根据检查结果进行纠正，预防再次发生，确保持续改进。
  • 总结：安全不是一次性的工作，而是一个螺旋上升的管理过程。

四、 国际技术框架：NIST 网络安全框架

这是美国国家标准与技术研究院（NIST）提出的框架，主要用于关键基础设施保护，非常强调实战能力。

它定义了网络安全的五个核心功能（IPDRR）：

  1. 识别 (Identify)：“知己知彼”。搞清楚自己有哪些资产、有什么风险、商业环境是怎样的。
  2. 保护 (Protect)：“扎好篱笆”。制定安全措施（访问控制、加密、培训），确保关键服务不挂。
  3. 检测 (Detect)：“即时发现”。通过持续监测，第一时间发现有没有网络安全事件发生。
  4. 响应 (Respond)：“快速行动”。发现出事了，立刻分析、缓解、沟通，把影响压到最小。
  5. 恢复 (Recover)：“亡羊补牢”。制定恢复计划，修好被破坏的功能，并从中吸取教训。

综合总结

建设网络安全体系的四种维度：

  1. 要合规：必须遵守等保 2.0（中国法律底线）。
  2. 懂场景：像智慧城市那样，根据业务层次（感知、网络、应用）进行分层设计。
  3. 重管理：利用 ISO 27000 (PDCA) 确保流程不断优化。
  4. 强实战：利用 NIST (IPDRR) 提升从识别到恢复的闭环作战能力。

其他网络安全体系模型

发表于 2026-02-02 分类于 软考

一、 纵深防御模型 (Defense-in-Depth)

这是现代安全防御最核心的理念，其精髓在于“多重保险，互相补位”。

  • 基本思路：
    绝对安全的单一防线是不存在的。所以不能只靠一道墙，要设立多道防线。一道破了，后面还有，互相支援。
  • 核心：四道防线（按时间轴排列）
    1. 安全保护 (Protection) —— 第一道：
      • 任务：拒敌于门外。
      • 作用：比如防火墙、门禁，尽量不让攻击发生。
    2. 安全监测 (Detection) —— 第二道：
      • 任务：发现漏网之鱼。
      • 作用：比如入侵检测系统（IDS），如果有人翻过了第一道墙，必须立马看见。
    3. 实时响应 (Response) —— 第三道：
      • 任务：带伤战斗（打不垮）。
      • 作用：攻击正在发生时，要能顶住，维持网络不瘫痪。
    4. 恢复 (Recovery) —— 第四道：
      • 任务：起死回生。
      • 作用：如果真的被打瘫了，要能最快速度用备份数据复原，把损失降到最低。

二、 分层防护模型 (Layered Protection)

纵深防御是横向的“多道墙”，分层防护则是纵向的“剥洋葱”。

  • 参考标准：OSI 7层模型（网络通信的基础标准）。
  • 核心逻辑：
    针对每一个单独的节点，从物理硬件到最上层的管理，每一层都有独特的漏洞，所以每一层都要有对应的锁。
  • 典型层次与举例：
    • 物理层：防止有人偷走服务器、拔网线。
    • 网络层：防止数据包监听、IP欺骗。
    • 系统层：防止操作系统漏洞（Windows/Linux漏洞）。
    • 应用层：防止 SQL 注入、网页篡改。
    • 管理层：防止员工贴便利贴泄露密码。
    • 结论：每一层都得配专门的药，不能用防火墙去防小偷砸门。

三、 等级保护模型 (Graded Protection)

这就是我们常听到的“等保”，是中国网络安全工作的基本国策。

  • 核心逻辑：“看人下菜碟”（资源是有限的，好钢要用在刀刃上）。
  • 划分依据：
    根据系统的重要性（涉及国家安全、经济命脉，还是普通娱乐网站）以及被破坏后的危害程度。
  • 执行方式：
    • 重要的系统（如银行、电网、政务网）：定级高，防护措施极其严格，花大价钱保护。
    • 不重要的系统（如公司内部食堂点餐网）：定级低，基本的防护即可。
  • 目的：平衡安全需求与成本开销。

四、 网络生存模型 (Network Survivability)

这个模型非常硬核，它不再幻想“完全防住”，而是假设“攻击一定会成功”，这时候该怎么办？

  • 核心定义：
    带病生存能力。指系统在遭受入侵、甚至部分被破坏的情况下，仍然能够持续提供必要服务的能力。
  • 关键方法：“3R”策略
    1. 抵抗 (Resistance)：尽量防住攻击（加固盾牌）。
    2. 识别 (Recognition)：识别出哪里被攻击了，是哪种模式。
    3. 恢复 (Recovery)：快速修复受损部分。
  • 战术思想：
    • 划分“安全核”：把系统分为两部分，一部分是“绝对不能死的核心”（安全核），另一部分是“可以牺牲的可恢复部分”。
    • 丢车保帅：在遭到猛烈攻击时，为了保证核心业务（如银行的存取款）不停，可以暂时牺牲非关键业务（如银行的积分兑换网页）。

总结

  • 纵深防御：设多道关卡（防、测、应、恢）。
  • 分层防护：从硬件到软件，层层设防。
  • 等级保护：重要的重点保，次要的简单保。
  • 网络生存：被打残了也要能动，核心心脏不能停（3R）。

能力成熟度模型CMM

发表于 2026-02-02 分类于 软考

简单来说，CMM 就是一把“尺子”，用来衡量一个公司或组织做事情（特别是做软件或安全工程）的靠谱程度和规范程度。

第一部分：通用的 CMM 五级模型（核心基础）

这是所有成熟度模型的“祖师爷”，用来评价一个组织做事有没有章法。图片中将其分为从低到高的五个等级：

  • 1级 - 非正式执行 (Initial)：
    • 关键词：混乱、救火。
    • 解读：没有规矩，全靠“英雄主义”。项目能不能成全看程序员心情和个人能力。一旦核心人员离职，项目就崩了。
  • 2级 - 计划跟踪 (Managed)：
    • 关键词：有计划、但未成体系。
    • 解读：开始有项目经理了，知道制定计划和跟踪进度。以前做成功的项目，现在能照葫芦画瓢再做一次（可重复），但还没形成全公司的统一标准。
  • 3级 - 充分定义 (Defined)：
    • 关键词：标准化、文档化。
    • 解读：全公司有了统一的“标准作业程序”（SOP）。不管张三还是李四做项目，都得按这一套流程走。
  • 4级 - 量化控制 (Quantitatively Managed)：
    • 关键词：数据说话。
    • 解读：不仅有流程，还开始用数据来管理。比如“代码缺陷率控制在0.1%以内”，“服务器响应时间不超过20ms”。一切用量化指标考核。
  • 5级 - 持续优化 (Optimizing)：
    • 关键词：自我进化。
    • 解读：不满足于现状，利用数据分析不断寻找流程中的短板，主动改进，追求完美。

第二部分：安全领域的 CMM 变体

CMM 的思想被引入到安全界，衍生出了几个特定的模型：

  1. SSE-CMM (系统安全工程能力成熟度模型)：

    • 用途：专门衡量做“安全工程”的能力。
    • 三大过程类：它不只看技术，还看工程过程（怎么做的）、组织过程（公司怎么管的）和项目过程（项目怎么推的）。

  2. 数据安全能力成熟度模型：

    • 评估维度：它从四个方面来综合打分：
      1. 组织建设（有没有专门的部门？）
      2. 制度流程（有没有规章？）
      3. 技术工具（有没有买防火墙、DLP等设备？）
      4. 人员能力（员工懂不懂安全？）

第三部分：软件安全能力成熟度模型（实战举例）

这部分非常有意思，它把通用的 CMM 级别对应到了具体的软件开发安全（DevSecOps）动作上。这实际上展示了一个公司是如何从“不管安全”进化到“顶级安全”的：

  • CMM 1级 - 补丁修补：
    • 状态：亡羊补牢。
    • 软件做出来发布了，用户发现有漏洞，赶紧打个补丁。这是最被动的。
  • CMM 2级 - 渗透测试、安全代码评审：
    • 状态：找茬纠错。
    • 在上线前，专门请黑客（渗透测试员）来攻击一下，或者找人检查代码。比1级强，因为是在内部发现问题。
  • CMM 3级 - 漏洞评估、安全编码标准：
    • 状态：立规矩。
    • 不再只靠最后测试，而是在写代码之前就规定好：“大家必须按安全标准写代码（如禁止使用 strcpy 函数）”。把安全融入到了开发规范中。
  • CMM 4级 - 软件安全风险识别、SDLC 检查点：
    • 状态：全程管控。
    • 在软件开发生命周期（SDLC）的每一个阶段（需求、设计、开发、测试）都设置“关卡”。比如设计阶段如果不符合安全要求，就不准进入开发阶段。
  • CMM 5级 - 改进风险覆盖率、评估安全差距：
    • 状态：精益求精。
    • 系统性地分析：“为什么我们上次漏掉了那个漏洞？”、“我们和行业顶尖水平差在哪里？”。通过复盘来提升整个体系的防御能力。

总结

核心逻辑是：安全不是一个“状态”，而是一个“过程”。

通过 CMM 模型，企业可以知道自己现在的安全水平处于哪个阶段（是还在忙着打补丁的菜鸟，还是已经建立标准化流程的高手），并明确下一阶段的努力方向。

信息保障模型

发表于 2026-02-02 分类于 软考

信息保障模型讲的是“实战战术”，它描述了在实际的网络安全建设中，应该如何构建一套动态的、完整的防御体系。

重点介绍三种由简入繁的模型：PDRR、P2DR 和 WPDRRC。

1. PDRR 模型 (最基础的闭环)

这是现代网络安全防御的基础模型。它改变了过去“只管防御（造墙）”的旧思想，强调安全是一个循环的过程。

  • 含义：
    • P (Protection) 保护：这是第一道防线。
      • 措施：加密、数据签名、访问控制、防火墙。
      • 通俗理解：像给家里装防盗门、防盗窗，不让坏人进来。
    • D (Detection) 检测：光有门不够，还得知道有没有人撬门。
      • 措施：入侵检测、漏洞扫描、完整性检测。
      • 通俗理解：像装了摄像头和报警器，一旦有人非法闯入立马发现。
    • R (Recovery) 恢复：如果防线被突破了，必须能把数据救回来。
      • 措施：数据备份、数据修复、系统恢复。
      • 通俗理解：家里被偷了没关系，重要的东西在保险柜还有备份，或者买了保险能赔付。
    • R (Response) 响应：发现攻击后，要立刻采取行动。
      • 措施：应急策略、应急机制、入侵过程分析。
      • 通俗理解：保安抓小偷，或者修补被撬坏的门锁。

2. P2DR 模型 (强调“策略”的核心地位)

P2DR 模型（有时也写作 PPDR）在 PDRR 的基础上，引入了一个核心指挥官——策略 (Policy)。

  • 含义：Policy (策略) + Protection (防护) + Detection (检测) + Response (响应)
  • 核心逻辑：
    • 策略 (Policy) 是大脑：所有的防护工具、检测工具和响应动作，都必须在统一的“安全策略”指导下进行。没有策略，买再多防火墙也是乱摆。
    • 动态调整：这是一个动态循环的模型。通过不断的检测来评估系统状态，如果发现风险，通过响应将系统调整回“最安全”的状态。
  • 比喻：
    • 如果 PDRR 是保安队，那么 P2DR 就是给保安队配了一个队长（策略）。队长规定：“咱们小区晚上10点后必须锁大门（策略）”，然后保安去锁门（防护），巡逻（检测），发现没锁好赶紧锁上（响应）。

3. WPDRRC 模型 (最全面的“攻防一体”模型)

这是目前最全面、也是最激进的模型，它在 PDRR 的基础上增加了事前预警和事后反击，构成了 6 个环节。

  • 含义：
    • W (Warning) 预警：在攻击发生之前，通过情报分析发出警告。（这是 PDRR 没有的“超前意识”）
    • P (Protection) 保护：传统的防御。
    • D (Detection) 检测：实时的监控。
    • R (Reaction) 反应：对攻击做出即时处理。
    • R (Recovery) 恢复：灾难后的重建。
    • C (Counterattack) 反击：这是该模型最特殊的地方。它引入了“以攻代守”的概念，对攻击者进行反制或取证。（注：在实际法律层面，反击通常受严格限制，多指技术上的阻断或诱捕）。

总结与记忆技巧

这三者其实是网络安全体系发展的三个阶段：

  1. PDRR：“防、测、修、应” —— 基础的运维循环，东西坏了知道修。
  2. P2DR：“策略为王” —— 强调管理，所有的技术手段都要听指挥。
  3. WPDRRC：“攻防兼备” —— 增加了预警（W）和反击（C），把安全防御的时间轴向前（预防）和向后（反制）极大地延伸了。

网络安全体系相关安全模型

发表于 2026-02-02 分类于 软考

网络安全体系特征：整体、协同、过程、全面、适应性；

网络安全体系相关安全模型包含了BLP机密性模型、Biba完整性模型、信息流模型等。

BLP完整性模型在文章中 BLP机密性模型 ，BLP 关注“保密”（不让人看），而 Biba 关注“完整”（不让人改）。

一、 Biba 完整性模型 (Biba Integrity Model)

如果说 BLP 模型是为了防止“泄密”，那么 Biba 模型就是为了防止“篡改”。它的核心目的是保护系统信息的完整性。

核心逻辑：你可以把“完整性级别”想象成“纯净度”或“可信度”。

  • 级别高 = 非常纯净、可信（如：操作系统核心文件）。
  • 级别低 = 脏、不可信（如：从互联网下载的未知文件）。

三个安全特性解读：

  1. 简单安全特性 (Simple Integrity Axiom) —— 核心是“防污染”

    • 规则：主体（用户）的完整性级别必须 ≤ 客体（数据）的完整性级别，才能读取。
    • 口诀：“不可向下读” (No Read Down)
    • 通俗解释：一个“干净”的高级别用户，不应该去读取“脏”的低级别数据。因为一旦读了不可信的数据，用户自己也被污染了，完整性就降低了。
    • (注：图片中第一点文字描述稍显混乱，提到“修改”却结论为“不可向下读”。但在标准 Biba 理论中，简单安全性主要约束“读取”行为，防止主体被低级信息污染)。

  2. 特性 (\-Property) —— 核心是“防破坏”

    • 规则：主体（用户）的完整性级别必须 ≥ 客体（数据）的完整性级别，才能修改（写入）。
    • 口诀：“不可向上写” (No Write Up)
    • 通俗解释：一个“不可信”的低级别用户，不能去修改“可信”的高级别文件。比如，普通用户不能修改系统内核文件，否则会破坏系统的完整性。

  3. 调用特性 (Invocation Property)

    • 规则：完整性级别低的主体，不能调用（激活）完整性级别高的主体。
    • 解释：这是为了防止低权限的恶意程序去操控高权限的程序来执行破坏操作。

⚡️ Biba 与 BLP 的对比记忆（考试常考点）：

  • BLP (保密)：不可向上读，不可向下写。（目的是把秘密锁在上面）
  • Biba (完整)：不可向下读，不可向上写。（目的是防止下面的脏数据污染上面）
  • 两者方向完全相反。

二、 信息流模型 (Information Flow Model / FM)

这是一个更抽象的模型，它不仅仅关注“谁访问了谁”，而是关注数据流动的方向。

  1. 核心概念：

    • 它不仅检查简单的读写权限，而是检查信息是否通过各种操作从一个客体流向了另一个客体。
    • 基本原则：基于安全属性（安全级），控制信息从客体 A 到客体 B 的传输。如果这种流动违反了安全策略（例如秘密信息流向了公开区域），就被禁止。

  2. 数学表示（图中公式部分）：

    • 模型通过集合论来描述：包括客体集、进程集、安全类型集以及流关系（Flow Relation）。
    • 一个安全的系统，要求所有的操作序列执行后，都不会产生与规定的“流关系”相冲突的结果。

  3. 关键应用：隐蔽通道 (Covert Channels) 分析

    • 这是信息流模型最著名的应用场景。
    • 什么是隐蔽通道？
      图片中解释得很清楚：“低安全等级主体对高安全等级主体所产生信息的间接读取”。
    • 通俗例子：
      假设 BLP 模型禁止 User A（低级）读取 File B（高级）。
      但如果 File B 的持有者通过“占用 CPU 100%”表示“1”，“占用 CPU 0%”表示“0”来发送摩斯密码，User A 虽然读不到文件，但可以通过观察 CPU 占用率来推测出信息。
      这就是隐蔽通道。信息流模型就是用来分析和阻断这种非正常的泄密路径的。

总结

  • Biba 模型：保护数据不被篡改（不可向下读，不可向上写）。
  • 信息流模型：关注数据的整体流动方向，专门用于发现那些绕过常规访问控制的“隐蔽通道”。

BLP机密性模型

发表于 2026-02-02 分类于 软考

Bell-LaPadula (BLP) 模型，这是一种专注于机密性（Confidentiality）的安全模型。

1. 什么是 BLP 模型？

  • 定义：BLP 模型是基于军事安全策略提出的计算机安全模型。
  • 核心目标：它的主要目的是保护机密性，防止非授权信息的扩散（即防止泄密）。它并不关注信息的完整性或可用性，只关注“谁能看什么”和“谁能写什么”。

2. 两大核心安全规则（这是考试或理解的重点）

BLP 模型通过强制控制主体（用户/程序）对客体（文件/数据）的访问，来确保信息安全。它定义了两条“铁律”：

① 简单安全性 (Simple Security Property) —— 关于“读”

  • 规则口诀：“向下读，不可向上读” (No Read Up)
  • 含义：
    • 级别高的用户可以读取级别低（或相同）的文件。
    • 级别低的用户不能读取级别高的文件。
  • 具体条件：
    1. 安全级：主体的安全级 ≥ 客体的安全级。
    2. 范畴：主体的访问范畴必须包含客体的全部范畴（即如果你想读某文件，你必须拥有该文件所属的所有部门权限）。

② 特性 (-Property / Star Property) —— 关于“写”

  • 规则口诀：“向上写，不可向下写” (No Write Down)
  • 含义：
    • 级别低的用户可以向级别高（或相同）的文件写入数据。
    • 级别高的用户不能向级别低的文件写入数据。
    • （注：这条规则看似反直觉，其实是为了防止高权限用户无意中将“绝密”信息写入到“公开”文件中，从而导致泄密。）
  • 具体条件：
    1. 安全级：客体的安全级 ≥ 主体的安全级（即你只能往比你等级高或相等的地方写）。
    2. 范畴：客体的范畴必须包含主体的全部范畴。

3. 访问类的组成

为了实现上述策略，系统给每个用户（主体）和信息（客体）都分配了一个“访问类”，由两部分组成：

  1. 安全级 (Security Level)：
    • 等级顺序为：公开 < 秘密 < 机密 < 绝密。
  2. 范畴级 (Category)：
    • 指信息的归属领域，例如“人事处”、“财务处”等。这是一种基于“需知原则”（Need-to-know）的水平隔离。

4. 实例解析

给出一个具体的判定例子，帮助理解：

  • 文件 F (客体)：

    • 级别：机密
    • 范畴：{人事处, 财务处}
    • (意思是：要读这个文件，你至少得是机密级，且必须同时拥有人事和财务的权限)

  • 用户 A (主体)：

    • 级别：绝密 （级别够了，绝密 > 机密）
    • 范畴：{人事处} （范畴不够，缺“财务处”）
    • 结果：用户 A 不能 读文件 F。

  • 用户 B (主体)：

    • 级别：绝密 （级别够了）
    • 范畴：{人事处, 财务处, 科技处} （范畴够了，包含了文件F要求的所有范畴）
    • 结果：用户 B 可以 读文件 F。

总结

BLP 模型就是一套严格的等级制度，确保低级别的人看不见高级别的秘密（不能向上读），高级别的人不会把秘密泄露到低级别区域（不能向下写）。
