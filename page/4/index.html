入侵检测系统IDS

模块一：入侵检测的基础概念与定位

1. 什么是入侵检测（IDS）？

  • 概念：入侵是指违背了目标安全策略的行为。IDS 通过收集操作系统、网络包等信息，来发现这些违规行为。
  • 判断依据：对目标的操作是否超出了目标的安全策略范围。
  • 角色定位：如果说防火墙是“门卫”，那么 IDS 就是网络中的预警机或巡逻员。它的直接目的不是阻断（那是IPS或防火墙干的事），而是发现、记录和报警，为应急响应和取证提供依据。

2. CIDF 通用模型（四大组件）
现代 IDS 都遵循 CIDF 框架，包含四个部分：

  • 事件产生器：负责到处收集数据（抓包、拿日志）。
  • 事件分析器：大脑，负责分析数据是否异常。
  • 响应单元：依据分析结果做出反应（如发警报）。
  • 事件数据库：存储数据和结果。

模块二：两大核心检测技术流派（重点）

这是 IDS 最核心的理论，分为“误用检测”和“异常检测”两大流派，外加一些新型辅助技术。

1. 基于误用的检测（又称：基于特征的检测）

  • 原理（对号入座）：建立一个已知攻击的特征模式库（黑名单）。如果抓到的数据和库里的特征匹配上了，就认定是入侵。
  • 优缺点：优点是准确率高，一抓一个准（比如 Snort 规则）；缺点是高度依赖特征库的更新，对于库里没有的新型攻击（未知攻击）毫无办法。
  • 具体方法：状态迁移、条件概率、规则匹配、键盘监控等。

2. 基于异常的检测

  • 原理（寻找异类）：先给系统或用户的正常行为画一个“轮廓”（建立正常基线/白名单）。如果当前行为严重偏离了这个正常基线，就认为是异常/入侵。
  • 优缺点：优点是能发现未知的、新型的攻击；缺点是误报率极高（因为“异常”不一定等于“入侵”，比如管理员偶尔半夜登录也会被当成攻击）。
  • 具体方法：统计分析、模式预测、文本分类、贝叶斯推理等。

3. 其他新型检测技术

  • 沙箱动态分析：把可疑文件放进一个隔离的“安全屋（沙箱）”里运行，看它有没有搞破坏的动作（专治隐藏极深的木马）。
  • 报警关联分析：把海量零碎的报警连起来看，消除噪音，挖出背后复杂的连环攻击。
  • 攻击诱骗：故意弄个假系统（蜜罐）吸引黑客攻击，从而反向追踪黑客。

根据数据来源和部署位置，IDS 分为三大类：

1. 基于主机的 IDS（HIDS）

  • 数据源：主机的系统日志、CPU/内存状态、注册表、文件完整性等。
  • 部署：直接以软件形式安装在被保护的服务器上。
  • 优缺点：优点是不怕网络加密（因为数据到了主机已经解密了），能防范内部人员操作；缺点是耗费服务器性能，且一旦服务器被黑，HIDS 本身也可能被破坏。无法看到整个网络的宏观扫描。 HIDS包含软件： SWATCH 监视软件、Tripwire 文件和目录完整性检测工具、网页防篡改。

2. 基于网络的 IDS（NIDS）

  • 数据源：网络上流动的通信数据包。
  • 部署：作为一个旁路设备，接在交换机的镜像端口上（静静地旁听）。
  • 优缺点：优点是不影响现有网络性能，对黑客隐蔽，能监控一大片网络；缺点是遇到高加密流量就成了“瞎子”，且在高速网络下容易“漏抓”（漏包）。

3. 分布式 IDS（DIDS）

  • 原理：面对大型复杂网络，采用“多点探测、集中管理”的模式。把 HIDS 和 NIDS 结合起来，统一把情报汇总到一个管理中心进行综合分析。

模块四：演进产品与实际部署

1. 产品的演进
除了传统的 HIDS 和 NIDS，目前衍生出了更多形态：

  • UTM（统一威胁管理）：把防火墙、IDS、杀毒等功能集成在一个铁盒子（硬件）里。
  • APT 检查：专门针对潜伏深、利用文档（PDF/Word）传播的高级持续性威胁。
  • 细分领域 IDS：专盯网页攻击的 Web IDS、专盯数据库违规操作的 数据库 IDS、专盯工业设备的 工控 IDS。
  • IDS相关指标：可靠、可用、时效、准确、安全、可扩展。

2. 部署规范与方法

  • 7 步部署法：确定保护对象 -> 装探测器 -> 定策略 -> 选架构 -> 配规则 -> 测试验证 -> 运行维护。
  • 经典部署位置：
    • 测内网威胁：把 NIDS 挂在内网核心交换机的镜像端口上，查内鬼。
    • 测边界威胁：把 NIDS 挂在防火墙后面的网络边界处，查外部黑客。

💡 核心总结

学习 IDS，只需记住一句话：它是网络里的“监控摄像头”和“警报器”。它通过认黑名单（误用特征）或找行为反常（异常基线）来发现坏人。在部署上，装在电脑里的叫 HIDS，趴在交换机上偷听的叫 NIDS。

什么是网闸？

发表于 2026-03-02 分类于 软考

“网闸（GAP）”这个名字听起来很专业，但其实它的工作原理非常像我们生活中的“银行防弹玻璃下面的那种旋转递物槽”，或者叫“渡船”。

结合您提供的这张图，我用最通俗的语言为您拆解网闸到底是怎么工作的：

1. 核心铁律：内外网“老死不相往来”

普通的防火墙就像一个“安检门”，只要安检合格，外面的人（数据流）是可以直接走到里面去的（网络层连通）。
但网闸的铁律是：绝对不允许内外网有一根线直接连通！ 它们之间没有任何 TCP/IP 网络连接。

2. 网闸是怎么运送数据的？（“渡船”原理）

请看图中间那个方框，里面有“存储介质”和“控制开关”。这就是网闸的核心。
它运送数据的过程，分为严格的三个步骤（假设外网要把一份文件发给内网）：

  • 第一步：外网卸货（此时内网断开）
    外网把数据发过来。此时，“控制开关”将“存储介质”只连接到外网。外网把文件存进这个介质里。这个时候，内网是物理断开的，绝对连不到这个存储介质。
  • 第二步：中间隔离与安检（内外网全断开）
    文件存好后，“控制开关”立刻“咔嚓”一下，把外网也断开。这个时候，这个“存储介质”既不连外网，也不连内网，变成了一座“孤岛”。网闸通常会在这个时候对文件进行杀毒、拆解、检查。
  • 第三步：内网取货（此时外网断开）
    检查没问题后，“控制开关”再次拨动，将“存储介质”连接到内网。内网的主机过来，把这份文件“拿”走。这个时候，外网是物理断开的。

总结一下： 外网和内网就像在河的两岸，数据是靠中间的“存储介质”像渡船一样来回摆渡的。船靠左岸时，右岸上不去；船靠右岸时，左岸上不去。

3. 这样做的好处是什么？（剥离网络协议）

因为内外网从来没有真正连通过，所以所有基于“网络层面”的黑客攻击（比如 Ping 攻击、TCP 洪水攻击、端口扫描等）在网闸面前全部失效。
网闸把外部运送数据的“网络卡车”直接拦在了门外，只把车里装的“纯粹的货物（数据/文件）”搬了进来。

4. 存在什么“安全风险”？

提到了一个致命的风险：恶意数据驱动攻击（带毒文件）。

  • 原理解读： 虽然网闸拦住了所有的“网络攻击”，但如果外网传进来的是一份精心伪装的 Word 文档，而这份文档里藏着木马病毒代码。
  • 结果： 网闸的“渡船”会忠实地把这份 Word 文档摆渡到内网。只要内网的员工双击打开了这份文档，木马就会在内网爆发。
  • 结论： 网闸能隔绝“网络层”的连接攻击，但对“应用层”伪装在正常文件里的恶意代码（比如病毒、恶意宏指令）防御力有限。所以现代的高级网闸通常还要结合强大的内容过滤和杀毒引擎来一起工作。

VPN 虚拟专用网

模块一：VPN 的核心概念与本质

  • 什么是VPN？ VPN 的全称是虚拟专用网。它的本质是：利用加密技术，在公共的、不可信的网络（如互联网）上，硬生生“挖”出一条逻辑上的安全隧道，让数据像在企业内部局域网一样安全传输。 虚拟是指网络连接是逻辑的，不是物理的。
  • 三大安全功能： 保密性（别人看不懂）、完整性（别人改不了）、认证服务（确认对方是本人）。
  • 发展趋势： 客户端越来越轻量化（甚至“零客户端”，如直接用浏览器）、网关功能一体化、管理标准化。

模块二：VPN 的底层基石

VPN 有多种实现技术，按照VPN在 TCP/IP协议层的实现方式，可以分为链路层VPN、网络层VPN、传输层VPN：

  1. 链路层VPN：ATM、Frame Relay、多协议标签交换MPLS；
  2. 网络层VPN：受控路由技术、隧道技术；
  3. 传输层VPN：通过SSL来实现；

VPN 之所以安全，依赖于以下三大底层技术：

  1. 密码算法（核心）： 用于加密数据。包括国际标准（DES, AES, RSA）和国密标准（SM1, SM3, SM4）。
  2. 密钥管理： 密码本怎么发给对方？手工配置太慢，现在主要依靠动态密钥交换协议（如 SKIP、ISAKMP/Oakley），由软件自动协商生成，更安全快捷。
  3. 认证访问控制： 包含“你是谁（用户身份认证）”和“数据对不对（数据完整性认证）”。

模块三：IPSec VPN —— 网络层的安全霸主

IPSec 是网络层最常用的 VPN 技术，通常用于公司总部与分公司之间的网络对接（Site-to-Site）。

  • 三大核心协议：
    • AH（认证头）： 只管数据完整性和来源确认，不管加密。
    • ESP（封装安全负荷）： 既管认证，又管加密（把数据藏起来），是目前最常用的。
    • IKE（密钥交换协议）： 负责自动生成和分发密钥。
  • 【核心考点】IPSec 的两种工作模式：
    1. 传输模式（Transport Mode）： 不改变原来的 IP 包头，只把后面的“数据部分”加密或校验。通常用于主机对主机的通信。（讲解：就像寄信，信封还是原来的信封，只是信纸被加密了。）
    2. 隧道模式（Tunnel Mode）： 会在原数据包外面强行增加一个新的 IP 头，把原来的整个数据包（包括原 IP 头）都当成数据进行加密封装。通常用于局域网对局域网（网关对网关）的通信。（讲解：就像把原来写好地址的信封，整个塞进一个更大的新信封里寄出去，别人根本不知道里面原本要寄给谁。）

模块四：SSL VPN —— 传输层的灵活卫士

SSL VPN 是目前普通员工远程办公（出差在家连公司内网）最常用的技术，因为通常不需要安装复杂的客户端，用浏览器就能连。

  • 工作位置： 介于应用层和 TCP 层之间。
  • 两层协议架构：
    • 上层协议（握手、交换密码规范、报警）： 负责通信前的“对暗号”。也就是身份鉴别、协商加密算法、交换密钥。
    • 下层协议（SSL 记录协议）： 负责真正的“干活”。对数据进行分段、压缩、加算MAC（消息认证码，防篡改）、加密，然后发出去。接收端做逆向解密还原。
  • 加密机制： 握手认证时用非对称加密（点对点之间的身份认证，确保安全），传输数据时用对称加密（保密性通信，速度快）。

SSL记录协议的数据处理过程可以简要概括为发送端四步加工，接收端逆向还原：

1. 发送端处理（封装发送）：

  • 第一步：分割（将长数据切分成易于管理的小区块）。
  • 第二步：压缩（对分割后的数据块进行压缩，此步为可选）。
  • 第三步：加MAC（附加消息认证码，用于确保数据不被篡改）。
  • 第四步：加密（对数据进行加密，生成最终要发送的密文消息）。

2. 接收端处理（逆向还原）：

  • 第五步：接收还原（按发送端的顺序逆向操作依次进行：解密 验证MAC 解压缩 重组数据块），最后将其完整地移交给上层应用。

(记忆口诀：分、压、认证、再加密)

模块五：PPTP 与 L2TP —— 数据链路层的隧道

这两种是较早期的、在链路层（二层）实现的点到点 VPN 技术。

  • PPTP： 微软主导，主要用于电话拨号时代远程用户访问企业网。
  • L2TP： 结合了 PPTP 和 Cisco 技术的优点，运行在 UDP 1701 端口。
  • 两者的相同点： 都使用 PPP 协议对数据进行封装。
  • 两者的核心区别对比（常考点）：
    1. 网络要求： PPTP 必须跑在 IP 网络上；L2TP 适用性更广，只要是点对点连接就行（如帧中继、ATM）。
    2. 隧道数量： PPTP 两个端点间只能建1条隧道；L2TP 支持建多条隧道。
    3. 效率与安全： L2TP 的包头压缩比 PPTP 更小（4字节 vs 6字节），且 L2TP 支持隧道验证（PPTP不支持，相对较弱）。

💡 总结归纳：

如果企业需要分公司和总部的网络直接打通，底层自动完成，选 IPSec VPN（隧道模式）。
如果企业需要让出差的员工用个人电脑随时随地访问公司网页系统，选 SSL VPN（轻量、灵活）。

VPN主要产品与技术指标

模块一：VPN 的主要产品与工作模式

1. 产品形态

  • 商业产品：主要以硬件实体存在，如专用的 IPSec VPN 网关、SSL VPN 网关，或集成在防火墙/路由器中的 VPN 模块。
  • 开源产品：纯软件形态，如 StrongSwan、OpenSwan（针对 IPSec）和 OpenSSL（针对 SSL）。

2. 工作模式

  • IPSec VPN：必须支持 隧道模式（适用于网关对网关、主机对网关），可选支持 传输模式（仅适用于主机对主机）。
  • SSL VPN：主要分为 客户端-服务端模式（C/S，个人连公司）和 网关-网关模式。

模块二：VPN 的核心密码算法要求（重点考点）

国家或行业对 VPN 使用的密码技术有严格的规范，主要分为三大类算法：

  1. 非对称密码算法（用于身份认证、数字签名）
    • 必须使用 1024位及以上的 RSA 算法。
    • 或者使用中国国密标准：256位 SM2（椭圆曲线算法）、SM9（标识密码算法）。
  2. 对称密码算法（用于真正的数据加密）
    • 规定使用国密 SM1 算法（128位分组），且工作在 CBC 模式下。
  3. 密码杂凑算法（用于生成密钥和校验数据完整性/防篡改）
    • 使用国际标准的 SHA-1 或国密 SM3（输出长度为256比特）。
  4. 随机数生成：必须通过专门的《随机性检测规范》。

模块三：VPN 的功能与性能评价指标

如何评判一台 VPN 设备的好坏？主要看功能是否齐全，性能是否强悍。

1. 功能要求差异点

  • IPSec VPN：除了常规的加解密，特别强调 NAT 穿越能力（因为 IPSec 容易被 NAT 路由器挡住）和数字证书/公私钥身份鉴别，需同时支持 IPv4/IPv6。
  • SSL VPN：除了常规功能，特别强调 访问控制 和 客户端主机安全检查（比如检查接入的个人电脑是否装了杀毒软件，以防把病毒带入内网）。

2. 性能指标（两者侧重点不同）

  • IPSec VPN 的性能侧重于“加密处理能力”：
    • 加解密吞吐率：在不丢包的情况下，设备能处理的最大数据流量（需测试64字节小包和1428字节大包）。
    • 加解密时延：数据从明文变密文，再变回明文所需的时间。
    • 加解密丢包率：满负荷运转时丢失数据的比例。
    • 每秒新建连接数：每秒能建立多少个加密隧道。
  • SSL VPN 的性能侧重于“并发用户承载能力”：
    • 最大并发用户数：能同时支持多少个用户在线。
    • 最大并发连接数：能同时处理多少条 SSL 连接。
    • 每秒新建连接数：每秒能接受多少个新用户的登录请求。
    • 吞吐率：服务端网口的最大数据流量。

模块四：VPN 的三大经典应用场景

VPN 技术的出现，极大降低了企业的专线建设成本。图中展示了三种主要用法：

  1. 远程安全访问

    • 原理：利用互联网，通过 VPN 技术把分散在各地的局域网安全地“缝合”成一个巨大的企业内部逻辑网，实现数据安全共享。
  3. 外部网络安全互联（Extranet 合作伙伴接入）
    • 适用场景：企业需要让供应商或外部合作伙伴访问部分内部数据。
    • 原理：通过 VPN 划定严格的访问权限，让外部机构安全接入，既方便业务往来，又防止内部核心机密泄露。

防火墙概述

1. 防火墙的核心概念与安全区域

  • 概念：防火墙是一种安装在不同安全区域边界处的网络安全设备（由软件或硬件组成）。它的核心目的是将自己的网络与不可信的公共网络隔离，从而阻断网络攻击，保护内部网络。
  • 安全区域划分：根据信任程度，网络通常被划分为四个区域：
    • 公共外部网络：如 Internet（不可信）。
    • 内联网 (Intranet)：组织内部的专用网络（高度可信）。
    • 外联网 (Extranet)：内联网的延伸，用于与合作伙伴通信。
    • 军事缓冲区 (DMZ)：介于内外网之间的缓冲段，常放置公共服务设备（如对外提供服务的Web服务器）。

2. 防火墙的工作原理与控制策略

  • 工作原理：作为网络访问控制器，它根据设定的安全规则，对流经的“网络包”进行检查，决定“禁止”或“转发”。它能有效屏蔽内部网络的拓扑结构和运行状况。
  • 安全策略类型：
    • 白名单策略：默认全部禁止，只允许符合规则的包通过。（安全性更高）
    • 黑名单策略：默认全部允许，只禁止与规则冲突的包通过。

3. 防火墙的主要功能

除了基本的隔离，防火墙还具备以下功能：

  • 过滤非安全网络访问。
  • 限制特定的网络访问。
  • 网络访问审计（记录日志）。
  • 网络带宽控制。
  • 协同防御。

4. 防火墙的局限性与安全风险（重要）

防火墙并非万能，采用防火墙的网络仍存在以下风险：

  1. 网络旁路：对未经过防火墙的通信无能为力（例如内部员工直接用物理网卡拨号上网）。
  2. 功能缺陷：不能完全防止病毒感染、数据驱动式攻击以及后门攻击。
  3. 单点故障与特权威胁：一旦防火墙自身失效或被攻破，会导致整个网络的安全防线崩溃。
  4. 内部威胁：无法有效防范来自网络内部的攻击和破坏。
  5. 受限于规则：防火墙的效用高度依赖于安全规则的更新和配置。

5. 防火墙的发展趋势

面对复杂的网络环境，防火墙正朝着以下方向发展：

  • 控制粒度不断细化。
  • 检查安全功能持续增强。
  • 产品分类更细化。
  • 智能化增强。

防火墙类型和实现技术

模块一：传统防火墙的基础实现技术（3大核心机制）

  1. 包过滤技术 (Packet Filtering)
    • 工作层级：网络层（IP层）。
    • 原理：基于数据包的包头信息（源/目的IP、源/目的端口、协议类型、方向）与预设规则进行匹配，决定放行或拒绝。控制依据是“规则集”，过滤规则表示格式：规则号+匹配条件+匹配操作；匹配操作包含拒绝、转发、审计。
    • 优缺点：优点是负载低、速度快、对用户透明；缺点是无法识别用户，易受IP欺骗攻击（无法进行用户级别的过滤）。
  2. 状态检查技术 (Stateful Inspection)
    • 核心机制：通过建立并维护一张“会话表”（Session Table）来工作。
    • 原理：利用TCP/UDP的会话状态信息。只有属于合法且已建立会话的数据包，或者符合安全策略允许新建会话的首个数据包，才被允许通过。相比单纯包过滤，安全性与效率更高。
  3. 应用服务代理技术 (Application Proxy)
    • 角色：扮演内外网通信的“中间人”。
    • 原理：提供应用级的访问控制。内部用户不能直接访问外部，必须经过代理服务器认可并代为请求。
    • 优缺点：优点是能彻底隐藏内部网络结构，支持详细审计和内容分析，安全性极高；缺点是处理速度慢，对用户不透明，且只能支持特定的应用协议。

模块二：网络地址转换 (NAT)

  • 核心作用：解决公网IP短缺问题，同时通过透明转换内部地址，隐藏内部网络结构，提升安全性。
  • 三种实现方式：
    1. 静态NAT：内网与公网IP永久一对一映射。
    2. NAT池：动态分配公网IP集给内网主机。
    3. 端口NAT (PAT)：多个内网IP映射到同一个公网IP的不同端口上（最常用）。

模块三：细分领域的专用防火墙技术

针对不同应用场景，演化出了专门的防火墙：

  1. Web应用防火墙 (WAF)：专门保护Web服务器。通过HTTP协议和内容过滤，防御SQL注入、XSS跨站脚本、Webshell、CSRF等典型Web攻击。
  2. 数据库防火墙：保护数据库安全。核心技术包括数据库通信协议深度分析（精确到SQL语句拦截）和虚拟补丁（无需打原厂补丁、不停机即可屏蔽数据库漏洞）。
  3. 工控防火墙：工业控制系统专用。侧重对工控协议的深度分析，区别于传统防火墙，它必须适应工业现场的恶劣环境及极高的实时性要求。

模块四：下一代防火墙 (NGFW) 与共性关键技术

  1. 下一代防火墙 (NGFW) 的七大新能力：
    在传统功能基础上，增加了：① 不依赖端口的应用级识别与管控；② 入侵防护 (IPS)；③ 数据防泄露 (DLP)；④ 基于信誉的恶意代码防护；⑤ URL分类与过滤；⑥ 带宽管理与QoS优化；⑦ 加密通信分析 (监控SSL/SSH)。
  2. 核心共性关键技术：深度包检测 (DPI)
    • 原理：不仅检查包头，还深入应用层检查数据包的内容（Payload），使用特征匹配或异常检测方法。
    • 面临的挑战：规则维护复杂、隐私保护限制、加密数据难以检测、以及深度解析带来的性能下降（网络延迟）。
    • 解决思路：利用硬件（如GPU）加速模式匹配算法，提升性能。
  3. 其他基础依赖：防火墙的安全性依赖于其底层的操作系统安全，以及精准的网络协议分析能力。

模块二：防火墙的评价标准与技术指标

评价一台防火墙是否合格，业界通常使用四大类指标加上自身安全指标来进行衡量：

1. 安全功能指标（它能干什么？）

这是衡量防火墙“业务能力”的指标，主要包括：

  • 基础网络支持：支持各类网络接口、网络协议（IPv4/IPv6/VPN）、各种路由模式。
  • 控制与管理：包括访问控制（包过滤、NAT、状态检测）、流量/带宽管理、应用层管控。
  • 高级防护机制：支持认证机制、加密算法，具备对抗DDoS攻击、Web攻击、恶意代码等综合防护能力。
  • 运维功能：支持设备虚拟化、完善的审计与报表、多种管理方式（如SNMP）。

2. 性能指标（它能跑多快/多大负荷？）【核心考点】

在不丢包的情况下，衡量设备处理数据的极限能力：

  • 最大吞吐量 (Throughput)：单位时间内能处理的最大数据量（分网络层、HTTP、SQL吞吐量等）。
  • 最大连接速率 (Connections Per Second, CPS)：每秒钟能新建的TCP/HTTP请求数量。
  • 并发连接数 (Concurrent Connections)：同一时刻，防火墙内存中能够同时维持的最大连接总数。
  • 最大规则数：在添加海量安全规则后，测试设备性能是否会大幅下降。

3. 环境适应性指标（它能在哪用？）

  • 物理环境：气候（温度/湿度）、电磁兼容、绝缘、机械适应性（抗震）等。
  • 网络环境：是否适应IPv6、云计算环境、复杂的工控网络等。

4. 安全保证指标（它开发过程靠谱吗？）

侧重于评估防火墙产品的生命周期，包括厂商的开发流程规范、指导性文档、生命周期支持、以及漏洞脆弱性评定。

5. 防火墙自身安全指标（它自己能防黑客吗？）

打铁还需自身硬，防火墙必须保护好自己：

  • 具备严格的管理员身份识别与鉴别。
  • 操作系统的安全等级足够高。
  • 具备强大的抗攻击能力（防止黑客直接打挂防火墙）和异常处理机制。

防火墙防御体系结构类型与实际部署应用

模块一：防火墙的三种典型防御体系结构（按安全性由低到高排列）

网络架构的设计直接决定了防火墙的安全防护能力。主要的体系结构分为三种：

1. 基于双宿主主机结构（最基础）

  • 物理特征：一台计算机上至少安装两块网卡（NIC）。
  • 工作原理：一块网卡连内网，一块网卡连外网。内外网之间物理隔离，不能直接通信。所有进出的数据包都必须经过这台主机内部的安全检查模块处理。
  • 特点：结构简单，内外网数据流完全在双宿主主机的控制之下。

2. 基于代理型结构（又称屏蔽主机结构）

  • 物理特征：由一台过滤路由器和一台代理服务器（堡垒主机）共同构成防御边界。代理主机通常位于内部网络中。
  • 工作原理：
    • 外部网络只能与内网的代理服务器建立连接，无法直接访问其他内网机器。
    • 内网如果要访问外网，也必须经过代理服务器。
  • 优缺点：比双宿主结构操作更简便，安全性更高。致命缺点是：一旦攻击者攻破了这台代理服务器，由于它身处内网，攻击者将如同进入无人之境，可以直接侦听和攻击整个内部网络。

3. 基于屏蔽子网结构（最安全）

  • 物理特征：在代理型结构的基础上，增加了一层周边网络（通常称为DMZ区或隔离区）。使用了两台过滤路由器（内部路由器和外部路由器）。
  • 工作原理：
    • 构建了两层隔离带。对外公开的服务器和应用代理放在这两台路由器之间的“屏蔽子网”里。
    • 外部网络只能访问屏蔽子网，绝不能直接进入内网。
  • 优缺点：安全级别最高。即使黑客攻破了屏蔽子网里的堡垒主机，还有内部路由器作为第二道防线，黑客依然无法直接操作内网。缺点是成本高、配置复杂。

模块二：防火墙的技术应用与部署规范

1. 防火墙的应用场景

防火墙广泛应用于：上网保护、网站保护、数据保护、网络边界保护、终端保护以及网络安全应急响应。

2. 规范化的防火墙部署流程（核心 7 步法）

在企业中部署防火墙不能随性而为，需遵循以下标准流程：

  1. 划分区域：根据安全策略，将网络划分为不同的安全区域（如外网、内网、DMZ区）。
  2. 设置控制点：在这些安全区域的边界交汇处设置访问控制点。
  3. 制定策略：针对每个控制点的业务需求，制定具体的边界安全策略（谁能访问谁，允许什么协议等）。
  4. 选型架构：根据策略，选择合适的防火墙技术（如包过滤还是应用代理）和防御结构（如屏蔽子网结构）。
  5. 配置实施：在防火墙设备上把策略转化为具体的配置代码。
  6. 测试验证：测试边界策略是否被正常执行，有无漏洞或误拦截。
  7. 运行维护：投入生产环境，并持续进行日志审计和策略更新。

3. 应用实例：基于路由器的包过滤防火墙

幻灯片最后一张展示了一个最基础的防火墙应用案例：利用企业边界路由器自带的访问控制列表（ACL）来实现包过滤。

  • 实现方式：通过编写如 access-list 100 deny ip... 等命令行规则。
  • 常见策略：可以实现拦截外部伪造的私有IP（防IP欺骗攻击）、禁止特定的ICMP报文（防Ping扫描）、只允许特定主机远程管理路由器等基础边界安全控制。

认证概念

一、 认证的基本概念与角色

  • 概念： 一个实体向另一个实体证明其所声称身份的过程。
  • 核心角色：
    • 声称者： 需要被证实身份的实体。
    • 验证者： 负责检查确认声称者身份的实体。

二、 认证的组成

认证一般由两部分组成：

  1. 标识（Identification）： 用来代表实体身份的标志（如名称、标识符ID），确保实体的唯一性和可辨识性。
  2. 鉴别（Authentication）： 利用凭证（如口令、电子签名、数字证书、令牌、生物特征等）对实体所声称的属性进行识别和验证的过程。

三、 认证依据（四大类）

认证依据（即鉴别信息）是用于确认实体身份真实性的凭证。目前主要分为四类：

  1. 所知道的秘密信息 （如：密码、PIN码）
  2. 所拥有的实物/数字凭证 （如：数字证书、令牌、门禁卡）
  3. 所具有的生物特征 （如：指纹、人脸、虹膜）
  4. 所表现的行为特征 （如：签名习惯、步态）

四、 认证的机制原理

认证机制由三个核心要素构成：

  • 验证对象： 需要鉴别的实体（声称者）。
  • 鉴别实体： 给出真实性判断的实体（验证者）。
  • 认证协议： 双方进行认证信息交换所遵从的规则。

五、 认证的分类

  • 按凭据的类型数量分：
    • 单因素认证
    • 双因素认证
    • 多因素认证
  • 按利用的时间长度分：
    • 一次性口令（OTP）： 用于防止口令重用攻击（如短信验证码）。
    • 持续认证： （见下方详述）

六、 重点概念：持续认证

  • 定义： 对用户整个会话过程中的特征行为进行连续检测，不间断地验证用户特性。
  • 核心思想： 将对事件的身份验证转变为对过程的身份验证。
  • 三大鉴定因素：
    1. 认知因素： 眼手协调、应用行为模式、使用偏好、设备交互模式等。
    2. 物理因素： 左/右手习惯、按压大小、手震、手臂大小、肌肉使用等。
    3. 上下文因素： 事务模式、导航模式、设备和网络模式。

根据认证主体双方的交互关系，认证主要分为三种类型：单向认证、双向认证和第三方认证。

单向认证

1. 概念：
验证者对声称者进行单方面的鉴别，声称者不需要识别验证者的身份。声称者发送凭据，验证者检查确认即可。

2. 实现技术（两种）：

  • 基于共享秘密：
    • 前提： 双方（声称者A，验证者B）共享一个秘密密钥 。
    • 过程： A 将包含自身标识（IDA）和共享秘密（）的消息发给 B；B 检查无误后即可确认 A 的身份，并回复结果。
  • 基于挑战响应：
    • 过程：
      1. 验证者 B 生成一个随机数 RB（挑战），连同自己的标识 IDB 发给 A。
      2. A 收到后，生成包含 RB 的秘密 （响应），连同自身标识 IDA 发给 B。
      3. B 收到后解密检查 RB 是否正确，正确则确认 A 的身份，并回复结果。

双向认证

1. 概念：
验证者对声称者进行鉴别，同时声称者也对验证者的身份进行确认。双方互为验证者。
2. 核心作用：
在网络服务中（如客户端与服务端通信），通过互相认证，可以有效解决“假冒服务器”的安全问题。

第三方认证

1. 概念：
两个实体（A 和 B）在鉴别过程中，通过一个可信的第三方（TTP，Trusted Third Party）来协助实现认证和密钥交换。A 和 B 分别与 TTP 存在共享密钥 Kpa 和 Kpb

2. 核心技术方案：基于第三方挑战响应（7步过程解析）
该过程通过 TTP 安全地为 A 和 B 分发会话密钥Kab，随后 A 和 B 利用该密钥进行挑战响应。具体过程如下：

  • 阶段一：向 TTP 申请密钥 (步骤 1-2)
    • 实体 A 向 TTP (P) 发送加密请求，包含 B 的标识和 A 的随机数 RA。
    • TTP 解密后，生成供 A 和 B 通信的共享密钥 Kab 。TTP 将带有 Kab 的消息分别用 A 和 B 的专属密钥加密，打包发给 A。
  • 阶段二：A 将票据传递给 B (步骤 3)
    • A 将 TTP 生成的、属于 B 的那部分加密消息（即票据，包含 IDA 和 Kab ）转发给实体 B。
  • 阶段三：A 与 B 利用新密钥进行挑战响应 (步骤 4-7)
    • B 解密票据获得 Kab B 生成随机数 RB，用 Kab 加密发送给 A（B 向 A 发起挑战）。
    • A 用 Kab 解密得到 RB，然后将包含 RB 的消息重新用 Kab 加密发给 B（A 响应挑战）。
    • B 检查 RB 正确无误，则 A 认证通过，B 回复最终验证结果。

常见的认证技术方法及其工作原理

一、 基础认证技术

1. 口令认证技术 (最常见)

  • 原理： 基于用户“所知道的秘密”（账号+密码）。
  • 安全要求： 密码绝不能明文传输和存储，必须经过加密/哈希变换。
  • 优缺点： 简单易实现；但极易受到窃听、重放、中间人攻击和口令猜测攻击。必须配合强口令策略和安全协议使用。

2. 智能卡技术

  • 原理： 利用带有集成电路、具备安全存储和一定计算能力的卡片。
  • 认证方式：基于“挑战/应答”。目标系统发送一个随机数（挑战），用户在智能卡输入，智能卡通过内置算法计算出一个结果（应答）返回给系统验证。

二、 生物与行为特征认证

1. 生物特征认证

  • 原理： 利用人类与生俱来、独特且稳定的生物特征进行验证。
  • 常见类型：
    • 指纹识别： 包括采集、处理、登记、比对等模块。
    • 人脸识别： 一般由客户端、服务器端、安全传输通道组成。
    • 视网膜/虹膜识别： 根据眼底血管分布或虹膜纹理鉴别。核心功能分为“登记”和“识别”两部分。

2. 基于行为的身份鉴别

  • 根据用户操作行为习惯和风险大小进行的动态鉴别。

三、 经典网络认证协议与基础设施

1. Kerberos 认证协议 (强身份认证)

  • 原理： 基于对称密码体系和可信第三方，为客户端和应用服务器建立安全信道。
  • 核心实体 (KDC = AS + TGS)：Key Distribution Center
    • 客户端 (Client)： 访问服务的用户。
    • AS (认证服务器)： 验证用户身份，发放 TGS 会话密钥（发放 TGT 票据）。
    • TGS (票据发放服务器)： 为用户授予访问特定应用服务器的最终票据。
    • 应用服务器 (App Server)： 提供实际服务的设备。
    • 票据Ticket是用于安全传递用户信息的集合。
  • 优点： 减少了用户密钥密文的暴露次数；实现了单点登录 (SSO)，只要用户拿到了TGT并且该TGT没有过期，用户就可以使用TGT通过TGS完成到任一服务器的认证而不必重新输入密码。
  • 致命缺点： 极度依赖时间同步（防重放）；存在单点故障风险，抗拒绝服务(DoS)攻击能力弱。

票据（Ticket） 主要包含以下 6 项核心内容：

  1. 客户方 Principal（客户端的身份标识）
  2. 目的服务方 Principal（目标服务器的身份标识）
  3. 客户方 IP 地址
  4. 时间戳（分发该 Ticket 的具体时间，主要用于防重放攻击）
  5. Ticket 的生存期（票据的有效时间期限）
  6. 会话密钥（用于后续客户端与目标服务器之间安全通信的临时密钥）

2. PKI 公钥基础设施

  • 原理： 利用非对称加密技术，通过公钥证书（类似数字身份证）将实体与公钥绑定，解决公钥的真实性和所有权问题。PKI 涉及多个实体之间的协商和操作，主要包括以下核心实体：
  • 核心实体：
    • CA (认证机构)： 核心，负责证书的颁发、废止和更新。
    • RA (登记机构)： 辅助 CA，负责审核用户身份信息、注册和担保。
    • 目录服务器： 提供证书的管理、存储和分发服务。
    • 终端实体/客户端： 需要被认证的对象及安全服务的使用者。

四、 现代应用安全认证机制

1. 单点登录 (SSO)

  • 用户访问多个互信系统时，只需进行一次身份认证，即可访问所有授权资源，极大简化了口令管理。

2. 人机识别认证 (CAPTCHA/验证码)

  • 目的： 利用计算机难以求解的难题，区分人类和机器程序，防止恶意自动化攻击（如撞库、刷单）。常见有文本、图像（如12306）、语音验证码。

3. 多因素认证 (MFA)

  • 组合使用多种鉴别信息（如：密码+短信+指纹），大幅提升安全性。

4. 快速在线认证协议 (FIDO)

  • 核心理念：保护隐私，生物特征数据绝对不出本地设备。
  • 工作原理：
    • 注册： 设备本地生成公私钥对。私钥留在本地安全芯片，公钥发给服务器绑定账号。
    • 登录： 服务器发送挑战 -> 用户在本地用生物特征（指纹/面容）解锁私钥 -> 设备用私钥对挑战进行签名发送给服务器 -> 服务器用公钥验证签名通过。
  • 优势： 提供了标准化的浏览器 API，兼容各种本地安全认证方式，彻底告别密码泄露风险。

认证的主要产品、技术指标以及在实际场景中的应用

一、 认证主要产品分类

认证技术产品是普遍的网络安全产品，通常以物理硬件实体（集成安全软件）为主。主要分为以下五大类：

  1. 系统安全增强产品：
    • 特点： 利用多因素认证（MFA）技术增强系统、数据库或网站的登录安全。
    • 常见组合： U盘+口令、智能卡+口令、生物信息+口令。
    • 应用： 网银U盾、指纹登录系统等。
  2. 生物认证产品：
    • 特点： 利用指纹、人脸、语音等生物特征进行身份鉴别。
    • 产品： 人脸识别门禁、指纹采集仪、人脸自动识别平台等。
  3. 电子认证服务产品：
    • 特点： 基于 PKI 技术和密码算法，提供数字证书的全生命周期管理（申请、颁发、废止等），提供可信身份、可信时间等服务。
    • 产品： CA数字证书认证系统、SSL证书、时间戳服务平台等。
  4. 网络准入控制产品：
    • 特点： 基于 802.1X、Radius、VPN 等协议，与网络设备（交换机、路由器）联动。
    • 作用： 在设备（主机、手机等）接入内部网络前，进行身份和安全合规性验证，防范非法设备接入。
  5. 身份认证网关：
    • 特点： 提供集中、统一的认证服务（形成认证中心）。
    • 功能： 支持单点登录（SSO）、安全审计等。

二、 认证技术产品的核心评价指标

评价一个认证产品的好坏，主要从安全功能、性能和安全保障三个维度，具体看以下四个指标：

  1. 密码算法支持： 是否支持主流算法，如对称（DES/AES/SM4）、非对称（RSA/SM2）、哈希（SHA-1/SM3）。
  2. 认证准确性（极重要）： 考量生物识别等技术的 认假率 (FAR，把坏人认成好人) 和 拒真率 (FRR，把好人认成坏人)。
  3. 用户支持数量： 系统的最大并发/承载用户量（性能指标）。
  4. 安全保障级别： 系统的抗攻击能力和可靠程度。

三、 认证技术的典型应用场景

认证技术是网络安全的基础，主要用于：用户身份验证、信息来源证实（防假冒）、信息安全保护（防篡改/重放）。具体典型应用如下：

  1. 校园信任体系建设 (PKI应用)：
    • 在校园内建立统一的数字证书发放体系，实现“物理身份”与“数字身份”的一一对应。从而实现统一认证、基于角色的授权管理和责任认定。
  2. 网络路由认证：
    • 目的： 保证路由器设备访问安全和路由信息交换的安全，防止恶意路由更新。
    • 对象： 用户访问认证、路由器邻居认证（如 OSPF、RIP、EIGRP 协议的认证）。
    • 注意： 明文认证极不安全，推荐使用信息摘要认证（哈希加密）。
  3. 基于人脸识别的机房门禁：
    • 彻底杜绝伪造证件、冒名顶替进入核心区域，并实时上传记录便于管理。
  4. eID (网络电子身份标识) 验证：
    • 特点： 由国家主管部门颁发，与公民真实身份一一对应的网络数字身份（基于非对称密码和数字证书）。
    • 验证流程（挑战/响应模式）： 服务商请求 -> eID平台发随机数(挑战) -> 服务商用eID运算 -> 平台验证结果并返回。
  5. HTTP 认证应用 (Web服务)：
    • 支持基本访问认证 (BAA)、数字摘要认证、NTLM 等。
    • 标准交互流程：
      1. 客户端请求资源。
      2. 服务器返回 401 Unauthorized 拒绝访问，并要求认证。
      3. 客户端获取用户凭证并处理。
      4. 客户端再次请求，并在报文中携带凭证（Authorization 头部）。
      5. 服务器验证凭证，成功则返回 200 OK 及资源，失败或无权限则返回 403 Forbidden。

访问控制

发表于 2026-02-04 更新于 2026-02-25 分类于 软考

访问控制包含的主要部分：基本概念与目标、参考模型、主要的访问控制类型、策略设计、管理流程、具体规则实现以及相关产品。

一、 访问控制概述

1. 核心定义

  • 概念：对资源对象的访问者进行授权、控制的方法及运行机制。
  • 三个关键要素：
    • 主体 (Subject)：访问者（如用户、进程、应用程序）。
    • 客体 (Object)：被访问的对象（如文件、应用服务、数据）。
    • 授权 (Authorization)：允许访问的方式（如读、写、执行、发送）。
  • 控制机制：对使用方式的监测、限制以及决策（如允许、拒绝）。

2. 主要目标

  • 防外：防止非法用户进入系统。
  • 防内：阻止合法用户对资源的非法使用（即防止越权访问）。

3. 实现流程

  • 身份认证（首先确认是谁） 授权（根据身份赋予权限） 保护资源。
  • 同时伴随安全审计和监控，以检测攻击企图。

二、 访问控制模型

1. 参考模型组成 (5要素)
一个标准的访问控制机制通常包含以下组件：

  • 主体 (Subject)：操作实施者。
  • 客体 (Object)：被操作对象。
  • 参考监视器 (Reference Monitor)：核心组件，负责决策和执行。
  • 访问控制数据库：策略库，记录权限信息，作为判断依据。
  • 审计库：记录操作日志（成功或失败）。

2. 模型的发展与应用场景

  • 基础类：DAC、MAC、RBAC（常用于操作系统、数据库）。
  • 隐私与版权类：基于使用（UCON）。
  • 移动互联类：基于地理位置。
  • 新兴/分布式类：基于属性（ABAC，用于Web服务）。
  • 风控/动态类：基于行为、基于时态。

三、 访问控制的主要类型 (核心重点)

1. 自主访问控制 (DAC - Discretionary Access Control)

  • 定义：客体的拥有者按照自己的策略，将权限授予其他用户。
  • 实现方式：
    • 基于行（附在主体上）：
      • 能力表：用户持有访问客体的“钥匙”。
      • 前缀表：用户拥有的权限清单。
      • 口令：用户需提供客体对应的密码。
    • 基于列（附在客体上）：
      • 保护位：如UNIX/Linux的 rwx 权限位。
      • 访问控制表 (ACL)：每个客体附带一个列表，记录谁能做什么（矩阵形式）。

2. 强制访问控制 (MAC - Mandatory Access Control)

  • 定义：根据主体和客体的安全属性（安全级别），由系统强制控制。
  • 机制：每个进程和文件都有安全标签。
  • 规则：当且仅当 主体安全级别 客体安全级别（且范畴包含）时，才允许访问。否则直接拒绝。

3. 基于角色的访问控制 (RBAC - Role-Based Access Control)

  • 定义：目前国际流行的先进方法。引入“角色”作为中间层。
  • 核心逻辑：
    • 用户 (U) 角色 (R)：用户被分配角色（岗位/职位）。
    • 角色 (R) 权限 (P)：角色被赋予权限。
  • 优势：实现了用户与权限的逻辑分离，便于授权管理、分级管理、任务分担和实现最小特权原则。
  • 四要素：用户(U)、角色(R)、会话(S)、权限(P)。

4. 基于属性的访问控制 (ABAC - Attribute-Based Access Control)

  • 定义：根据主体属性（如年龄、部门）、客体属性（如机密性）、环境条件（如时间、地点）以及策略来进行授权决策。
  • 特点：细粒度、灵活性高，适用于分布式环境。

四、 访问控制策略的设计与实现

1. 策略设计原则

访问控制策略是规定资源访问权限的核心文件。

  • 设计考量因素：
    • 区分用户类型（内部 vs 外部）。
    • 确认应用信息（端口、IP）。
    • 明确信息的分级与授权策略。
    • 保持不同系统间策略的一致性。
    • 符合法规与合同义务。
    • 考虑权限的维护与更新。
  • 核心原则（重点）：
    • “默认拒绝”原则：建立规则应以“未经明确允许的都是禁止的”为前提（比“未经禁止即允许”更安全）。
    • 规则颁布前需经管理层批准。

2. 常见的访问控制规则类型

访问控制规则实际上就是访问约束条件集，规则是策略的具体表现形式，主要有以下6种：

  1. 基于用户身份：最常用（账号+口令）。
  2. 基于角色：根据任务/岗位分配权限。
  3. 基于地址：利用物理或逻辑地址（IP、域名）限制。例如：禁止远程访问，仅许本地。
  4. 基于时间：设置时间段限制。例如：下班时间禁止访问。
  5. 基于异常事件：触发防御机制。例如：登录失败3次冻结账号。
  6. 基于服务数量：流量/并发控制。例如：防止DoS攻击，达到阈值拒绝新请求。

五、 访问控制过程与安全管理

1. 实施的五个步骤

  1. 明确资产：识别要保护的对象（如路由器、Web服务）。
  2. 分析需求：确定CIA需求（保密性、完整性、可用性）。
  3. 制定策略：确定规则及权限分配。
  4. 实现策略：建立认证系统，授权用户。
  5. 运行维护：监控系统，调整策略。

2. 最小特权管理 (Least Privilege)

  • 定义：系统中每个主体只能拥有完成任务所必须的最小权限集。
  • 原则：“按需使用”。
  • 目的：防止特权滥用，限制特权被攻破后的危害范围。

3. 用户访问管理流程

涵盖用户全生命周期管理，防止非授权使用。

  • 主要工作：用户登记 权限分配 访问记录 权限监测 权限取消/撤销。
  • 关键环节：包括用户责任确认签字、审计用户操作、定期检查违规行为或多余账号。

4. 口令安全管理（最佳实践）

口令是身份鉴别的核心依据，需遵守严格规范：

  • 复杂度：8字符以上，包含大小写、数字、特殊字符。
  • 差异性：禁止使用与账号相同的口令，禁止使用默认口令。
  • 防爆破：限制登录次数（建议3次）。
  • 存储与传输：文件加密存放（仅超级用户可读），禁止明文传输。
  • 生命周期：设置时效（强制定期更改），禁止重用旧口令。
  • 审计：定期运行工具检查弱口令或空口令。

六、 访问控制主要产品与技术指标

1. 主要产品形态

  • 4A系统 (统一安全管理平台)：
    • 核心功能：Account (账号)、Authentication (认证)、Authorization (授权)、Audit (审计)。
    • 特点：集中管理，通常基于角色的访问控制 (RBAC)。
  • 安全网关：
    • 特点：利用数据包信息和威胁特征库进行控制。
    • 例子：防火墙、统一威胁管理 (UTM)。
  • 系统安全增强：
    • 特点：利用强制访问控制 (MAC) 技术加固操作系统。
    • 例子：Linux的SELinux、Windows系统加固。

2. 主要技术指标

评价访问控制产品的四个维度：

  1. 支持的策略规则类型（越丰富越灵活）。
  2. 支持的最大规则数量。
  3. 规则检查速度（性能指标）。
  4. 产品自身的安全和质量保障级别。

七、 访问控制的主要应用场景分类

根据控制对象的不同，分为五大类：

  1. 物理访问控制：针对环境/实体。如门禁、警卫、门锁、区域划分。
  2. 网络访问控制：针对网络资源。如接入控制、路由控制、VLAN划分。
  3. 操作系统访问控制：针对系统资源。如文件读写、进程/内存访问。
  4. 数据库/数据访问控制：针对数据操作。如建表、数据分发。
  5. 应用系统访问控制：针对业务操作。如业务执行、文件读取。

八、 操作系统中的访问控制实现

1. UNIX/Linux 系统

采用 “9比特位模式” 来标识文件权限。

  • 结构：共10个字符（例如 -rw-r--r--）。
    • 第1位：类型标识（-代表文件，d代表目录）。
    • 后9位：分为三组，每组3位，分别对应 所有者 (u)、所属组 (g)、其他用户 (o)。
  • 权限表示：
    • 读 (r) = 4
    • 写 (w) = 2
    • 执行 (x) = 1
  • 数字表示法：例如 rw- (4+2=6)，r-- (4)，即 644。

2. Windows 系统

采用 访问令牌 (Access Token) 与 访问控制列表 (ACL) 机制。

  • 身份标识：用户登录时，WinLogon进程创建“访问令牌”，包含用户及所属组的安全标识符 (SID)。
  • 客体属性：
    • DACL (自主访问控制列表)：决定谁有权访问，以及有什么权限。
    • SACL (系统访问控制列表)：决定哪些访问行为需要被审计（记录日志）。

3. Windows 核心访问流程

  • 请求：用户进程通过WIN32子系统向核心请求服务。
  • 决策者：核心的 安全参考监视器 (SRM)。
  • 判定逻辑：
    1. SRM 将用户的 访问令牌 与客体的 DACL 进行比较 决定是否授权。
    2. 同时检查 SACL 决定是否将该操作发送至审计子系统。

九、 常见服务与网络访问控制应用

1. IIS FTP 访问控制

  • 控制方式：通过FTP站点属性进行配置。
  • 关键设置：
    • 身份验证：是否允许匿名连接。
    • 目录权限：读取（即下载）、写入（即上传）。
    • 注：FTP目录权限对所有FTP用户生效。

2. 网络访问控制

  • 网络通信连接控制：
    • 设备：防火墙、路由器、网关。
    • 原理：部署在不同网络的连接处，强制所有流量经过控制器，仅符合规则的流量才放行。
  • VLAN 网络隔离：
    • 原理：根据功能或业务用途，将网络划分为若干逻辑子网（网段）。
    • 目的：隔离内外部网络，避免各网段间多余的信息交换，缩小攻击面。

3. Web 服务访问控制流程

Web服务的访问控制是一个多层级、顺序执行的过滤过程。只有通过前一层，才能进入下一层判定：

  1. HTTP请求发起。
  2. IP/DNS 检查：客户端IP或域是否被允许？（否则拒绝）
  3. Web 用户认证：Web账号是否允许访问？（否则拒绝）
  4. 文件系统权限：NTFS/Linux文件权限是否允许？（否则拒绝）
  5. 数据库权限：DB系统是否允许操作？（否则拒绝）
  6. 最终授权访问。

其他物理设备安全分析与防护

发表于 2026-02-04 分类于 软考

其他物理设备主要涵盖了网络通信线路、设备实体以及存储介质三个维度的安全分析与防护措施：

一、 网络通信线路安全分析与防护

1. 安全分析

  • 地位：网络通信线路是连接网络系统各节点的纽带，是信息与数据交换的基础。
  • 常见威胁：
    • 线路被物理切断。
    • 线路遭受电磁干扰。
    • 线路信息泄露（如搭线窃听）。

2. 安全防护策略
主要从两个方面入手：

  • 设备防护（核心设备）：针对路由器、交换机等核心设备，为防止单点故障，通常采取设备冗余（设备间互为备份）的方式。
  • 线路防护：采取多路通信的方式，即部署冗余的通信链路，确保一条断裂时备用链路可用。

二、 设备实体安全分析与防护

1. 安全分析

  • 地位：设备是计算、控制和存储的平台，其物理安全至关重要。
  • 常见威胁：
    • 环境关联威胁、盗窃或损害。
    • 电磁干扰、非法外联。
    • 供应链风险：中断、延缓。
    • 硬件层面攻击：固件攻击、硬件攻击、控制组件威胁。

2. 常规防护措施

  • 标志与标记管理。
  • 电磁辐射防护、磁场抗扰。
  • 静电及用电安全防护。
  • 环境安全保护、适应性与可靠性保护。

3. 增强型防护（针对供应链）

  • 提升设备供应链弹性。
  • 设备安全质量保障。
  • 安全合规与安全审查。

4. 硬件攻击专项防护（重点）
针对潜在的硬件攻击（如硬件木马和漏洞），采取以下技术手段：

  • 硬件木马检测技术：

    • 反向分析法：通过逆向工程打开芯片封装，逐层扫描重建电路图，与原始设计进行对比（最直观但成本高）。
    • 功耗分析法：通过K.L扩展分析法获取芯片功耗特征（指纹），与“纯净芯片”进行比对，判断是否被篡改。
    • 侧信道分析法：比对电路的物理特性（功率、时序、电磁、热等）和旁路信息，发现电路变化。

  • 硬件漏洞处理：

    • 特点：硬件漏洞的修补具有不可逆性（无法像软件那样打补丁）。
    • 方法：通常采取破坏漏洞利用条件的方法，防止攻击者利用该漏洞。

三、 存储介质安全分析与防护

1. 主要威胁

  • 存储管理失控。
  • 数据泄露。
  • 设备或介质故障。
  • 数据非安全删除（被恶意恢复）。
  • 恶意代码攻击。

2. 防护措施

  • 强化管理：
    • 设立专区存放，专人保管。
    • 借用需审批登记。
    • 分类存放与备份：重要数据复制两份以上，分开备份。
    • 防拷贝：敏感/关键数据贴密封条。
    • 报废销毁：光盘、硬盘等必须按规定程序完全消除数据信息（防止数据残留）。
  • 技术手段：
    • 加密保存：对存储数据进行加密。
    • 容错灾备：采用磁盘阵列（RAID）、双机在线备份、离线备份等综合措施。

机房安全分析与防护

一、 机房的功能组成与安全等级

1. 机房功能区域组成

根据系统性质和管理体制，机房通常分为以下几类区域（可一室多用）：

  • 主要工作房间：主机房、终端室等。
  • 第一类辅助房间（关键保障）：低压配电间、UPS室、电池室、空调机室、气体钢瓶室、监控室。
  • 第二类辅助房间（办公维修）：资料室、维修室、技术人员办公室。
  • 第三类辅助房间（生活辅助）：储藏室、缓冲间、休息室、盥洗室。

2. 机房安全等级划分 (A、B、C级)

依据系统中断后对国家安全、社会秩序、公共利益造成的损害程度划分：

  • A级（最高）：造成严重损害。要求最严格，措施最完善。
  • B级（中等）：造成较大损害。要求较严格。
  • C级（基本）：不属于A、B级的情况。满足基本要求。
  • 注：可根据实际需求，对不同安全项目（如防干扰、防火）执行不同的等级标准。

二、 机房场地的选址要求

选址需综合考虑环境、地质、电磁干扰及建筑位置等因素：

  1. 环境安全性：

    • 避开危险源：远离易燃易爆场所（化工厂、加油站）。
    • 避开污染源：远离腐蚀性气体、多尘区（矿山、水泥厂）。
    • 其他：避开盐雾区（海边）和落雷区域。

  2. 地质可靠性：

    • 避开断裂带、滑坡、泥石流、矿区崩落区、低洼潮湿区。

  3. 抗电磁干扰：

    • 远离强电磁场（广播台、雷达站）。
    • 远离强电流冲击源（电气化铁路、高压线），距离需在200米以上。
    • 指标参考：GB/T 2887-2011，频率0.15~1000MHz时场强<126dBµV。

  4. 避开震动与噪声：

    • 远离强震动源（冲床、锻床）和强噪声源（机场、火车站）。
    • 避免机房窗户直接临街。

  5. 建筑楼层选择：

    • 不宜设在顶层（防热/漏水）或地下室（防潮/水灾）。
    • 最佳：专用建筑的二层（一层作动力/配电）。

三、 数据中心（Data Center）建设与规范

数据中心指为实现对数据的集中处理、存储、传输、交换、管理以及为相关设备运行提供环境的建筑场所。

1. 建设原则与分类

  • 原则：市场导向、资源有限、区域统筹、安全并重。
  • 分类（按规模）：
    • 超大型 (≥10,000机架)：重点考虑气候和能源，优先在一类地区（气候寒冷、能源充足）建设。
    • 大型 (3,000~10,000机架)：鼓励在一、二类地区建设。
    • 中小型 (<3,000机架)：靠近用户所在地，注重低延时，灵活部署。

2. 设计规范 (GB 50174-2017) 强制性条文

  • 接地：金属外壳、管道、结构必须进行等电位联结并接地。
  • 耐火等级：不应低于二级。
  • 防火隔离：若与其他功能房在同一建筑，需用耐火极限2.0h的隔墙和1.5h的楼板隔开，门为甲级防火门。
  • 火灾探测：主机房需设置两组独立的火灾探测器，联动灭火与监控。
  • 呼吸器：气体灭火系统的主机房必须配置专用空气呼吸器。

3. 数据中心分级

与机房分级类似，分为A、B、C三级，A级对应中断后造成重大经济损失或公共秩序严重混乱。

四、 互联网数据中心（IDC）规范

1. 定义与逻辑结构

  • 定义：提供资源出租（主机托管）、应用平台租用等服务的数据中心。
  • 六大逻辑组成：安全系统、业务系统、资源系统（计算/存储/网络）、网络系统、机房基础设施、管理系统。

2. 工程技术规范 (GB 51195-2016)

  • 分级（R1、R2、R3）：
    • R1：具备一定冗余，可用性 ≥99.5%。
    • R2：具备冗余，可用性 ≥99.9%。
    • R3：具备容错能力，可用性 ≥99.99%。
  • 强制性条文：
    • 抗震：7度以上抗震设防区，主要设备需经抗震检测。
    • 防火封堵：楼板和线缆孔洞必须用非燃烧材料封堵。
    • 标识：不同电压的电源设备需有明显区别标志。

五、 CA机房（认证中心）物理安全控制

CA机房作为核心信任源，有更严格的合规要求（遵循GM/T 0034）：

  1. 屏蔽与检测：实施屏蔽措施，每五年至少进行一次屏蔽室检测。
  2. 访问控制：
    • 严格佩戴身份标识。
    • 进出需经安全管理人员批准。
    • 全程记录（录像、门禁日志），确认无安全用途后方可销毁。
  3. 人员管理：建立陪同制度，定期审计访问权限。
  4. 介质安全：设备处理或再利用前，必须检查敏感数据并进行物理销毁或安全覆盖。

物理环境安全分析与防护

发表于 2026-02-04 分类于 软考

一、 物理安全的基本概念

  1. 定义：
    • 传统上称为“实体安全”。
    • 它是网络信息系统安全、可靠、不间断运行的基本保证。
    • 核心目标：保护支持系统运行的硬件（环境、设备、记录介质），防止因自然或人为因素导致信息丢失、泄露、破坏或服务中断。
  2. 广义定义：
    • 指由硬件、软件、操作人员、环境组成的“人、机、物”融合的网络信息物理系统的安全。

二、 物理安全威胁分析

威胁主要分为两大类：传统威胁与新型硬件威胁。

1. 常见（传统）威胁

  • 自然威胁：地震、洪水、火灾、鼠害、雷电等。
  • 人为威胁：盗窃、爆炸、毁坏、硬件攻击等。

2. 新型硬件威胁

具有隐蔽性、危害性、攻击主动性和非临近性。

  • 硬件木马：
    • 指在集成电路（IC）全生命周期（研发、制造、封装、应用）中植入的恶意电路。
    • 激活后会导致信息泄露或功能失控。
  • 硬件协同的恶意代码：利用硬件特性，使非授权软件访问特权内存区域。
  • 硬件安全漏洞利用：
    • 具有持久性和破坏性。
    • 典型案例：2018年的“熔断”（Meltdown）和“幽灵”（Spectre）CPU漏洞，通过侧信道攻击获取缓存数据。
  • 基于软件漏洞攻击硬件实体：
    • 利用控制系统软件漏洞修改物理配置，破坏硬件。
    • 典型案例：“震网”（Stuxnet）病毒。
  • 基于环境攻击：利用电磁波、温度、湿度等外部环境缺陷破坏系统运行。

三、 物理安全保护体系

1. 保护维度

  • 设备物理安全：标志标记、防电磁泄露/干扰、电源保护、抗震动、供应链安全（防木马）。
  • 环境物理安全：机房选址、屏蔽、防火/水/雷/鼠/盗、供电及空调系统。
  • 系统物理安全：介质安全、灾难备份、访问控制、资源利用。

2. 保护方法

  • 安全合规、访问控制、安全屏蔽、故障容错、安全监测与预警、供应链管理、容灾备份。

3. 分级标准

依据《信息系统物理安全技术要求（GB/T 21052-2007）》，分为四个等级：

  • 第一级：用户自主保护级（基本保护）。
  • 第二级：系统审计保护级（适当保护）。
  • 第三级：安全标记保护级（较高程度保护）。
  • 第四级：结构化保护级（更高程度保护）。

四、 物理环境安全分析与防护（具体措施）

针对具体的环境风险，采取了以下针对性措施：

  1. 防火：消除隐患、安装报警系统、配置灭火设备、加强管理规范。
  2. 防水：
    • 机房内禁铺水管（或做防漏措施）。
    • 墙壁/天花板/地面需防水防潮。
    • 选址避免底层或地下室，防止雨水倒灌。
  3. 防震：建筑物抗震、机柜设备固定、禁止移动在线设备。
  4. 防盗：报警器、锁定装置、视频监控、严格的物理访问控制。
  5. 防鼠虫害：
    • 封堵洞口。
    • 使用超声波驱鼠、捕鼠器、投放毒饵（需谨慎）。
    • 电缆使用防鼠涂层或毒饵。
  6. 防雷：
    • 安装避雷针。
    • 设备安全接地并连通地线网。
    • 重要设备加装专用防雷设施。
  7. 防电磁：
    • 目的：防止干扰和信息泄露。
    • 措施：接地、屏蔽、合理选址。
  8. 防静电：
    • 人员穿着防静电衣鞋、戴静电手套。
    • 控制机房温湿度。
    • 地板和工作台使用防静电材料/阻值达标。
  9. 安全供电：
    • 专用供电线路。
    • 配备不间断电源（UPS）。
    • 配备备用发电机。

网络安全体系建设

发表于 2026-02-02 分类于 软考

一、 国内核心标准：网络安全等级保护 2.0 (MLPS 2.0)

这是中国网络安全工作的“基本法”和最核心的合规要求。

1. 核心流程与分级

  • 工作流程：定级、备案、建设整改、等级测评、监督检查。
  • 定级方法：通过评估“业务信息安全”和“系统服务安全”受破坏后的侵害程度，综合判定。
  • 五个安全等级（级别越高，保护越严）：
    • 一级：用户自主保护级
    • 二级：系统审计保护级
    • 三级：安全标记保护级（注：通常企业核心系统是三级）
    • 四级：结构化保护级
    • 五级：访问验证保护级

2. 等保 2.0 的三大变化（重点）

相比于旧版（1.0），2.0 标准做了重大升级：

  1. 对象范围扩大：不再只管传统电脑网络，把云计算、移动互联、物联网、工业控制系统全都管起来了（通用要求+扩展要求）。
  2. 防护架构升级：提出了“一个中心，三重防护”的架构：
    • 一个中心：安全管理中心。
    • 三重防护：安全通信网络、安全区域边界、安全计算环境。
  3. 强化“可信计算”：这是2.0的一大特色，要求从一级到四级都要逐步增加“可信验证”。
    • 意思是从系统启动（引导程序）开始，到应用程序运行，每一步都要验证“你是你，你没被篡改”，一旦发现被篡改立刻报警。

二、 行业应用案例：智慧城市安全体系

这是一个典型的复杂巨系统安全建设案例，强调“全方位、立体化”。

  • 顶层设计：最上面是战略保障（法律、政策、标准）。
  • 左右护法：
    • 左边是管理体系（决策、组织、协调、评价）。
    • 右边是运营体系（实施、监测、应急、恢复）。
  • 核心技术柱（中间部分）：
    采用了分层防护思想，从下到上依次为：
    1. 物联感知层（摄像头、传感器安全）
    2. 网络通信层（传输安全）
    3. 计算存储层（云平台、服务器安全）
    4. 数据与服务融合层（数据隐私、融合安全）
    5. 智慧应用层（App、Web安全）
  • 基础支撑：最底下是密钥管理、身份认证（PKI/CA）等基础设施。

三、 国际管理标准：ISO 27000 (ISMS)

这是全球公认的信息安全管理体系标准，核心思想是动态循环。

  • 核心逻辑：PDCA 循环
    • P (Plan) 计划：建立 ISMS。识别资产，评估风险，制定策略（比如决定要不要装防火墙）。
    • D (Do) 执行：实施和运行。把计划落到实处，进行日常管理。
    • C (Check) 检查：监视和评审。检查做得怎么样，有没有漏洞，效果好不好。
    • A (Act) 处理：维护和提升。根据检查结果进行纠正，预防再次发生，确保持续改进。
  • 总结：安全不是一次性的工作，而是一个螺旋上升的管理过程。

四、 国际技术框架：NIST 网络安全框架

这是美国国家标准与技术研究院（NIST）提出的框架，主要用于关键基础设施保护，非常强调实战能力。

它定义了网络安全的五个核心功能（IPDRR）：

  1. 识别 (Identify)：“知己知彼”。搞清楚自己有哪些资产、有什么风险、商业环境是怎样的。
  2. 保护 (Protect)：“扎好篱笆”。制定安全措施（访问控制、加密、培训），确保关键服务不挂。
  3. 检测 (Detect)：“即时发现”。通过持续监测，第一时间发现有没有网络安全事件发生。
  4. 响应 (Respond)：“快速行动”。发现出事了，立刻分析、缓解、沟通，把影响压到最小。
  5. 恢复 (Recover)：“亡羊补牢”。制定恢复计划，修好被破坏的功能，并从中吸取教训。

综合总结

建设网络安全体系的四种维度：

  1. 要合规：必须遵守等保 2.0（中国法律底线）。
  2. 懂场景：像智慧城市那样，根据业务层次（感知、网络、应用）进行分层设计。
  3. 重管理：利用 ISO 27000 (PDCA) 确保流程不断优化。
  4. 强实战：利用 NIST (IPDRR) 提升从识别到恢复的闭环作战能力。
